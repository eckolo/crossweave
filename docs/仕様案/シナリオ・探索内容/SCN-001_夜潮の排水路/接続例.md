# SCN-001 接続例

版：0.2／2026-09-13。CO-S01の表示・意味状態を辿る4例。**設計用の未実行例であり、実APIの返却値や新しい試遊結果ではない。** 表のST等は[内容切替と帰還](内容切替と帰還.md)の提案ID。具体量は[札と成果の接続](札と成果の接続.md)のPT-NT試行値を基準とする。P-01（返し潮解放）を使う箇所を明記した。

## EX01 初回踏破：潜水服を倒さず、仕事を終える

開始条件：未解決、出発履歴なし、進行中探索なし、初期無料札だけの合法な準備、着想0、素材M0、3新札の所持個体0。初回の途中でCRD01を借りて観測した場合を例にする。借りられる確率・順序を保証するものではない。

| 段階 | 公開表示と内容対応 | 意味状態と実結果 |
|---|---|---|
| S01→S02 | TXT01・02→TXT03・04。OBJ-ENTRY。T1とEαを表示 | 出発成功時にMODE-FIRST、SET-UNRESOLVED、探索ID=例run-01を固定、ST03=true |
| 水路でCRD01を引く | COND01、札の実性能・由来・期限 | 観測済みとなる。借り札は探索中の一枚で、inventoryは0のまま |
| T1踏破→S03 | TXT05・06、Eα生存ならCOND04。OBJ-PORT | RW01を取得・保護。T1退場、Eα生存退場、T2参加。Eα報酬なし・全構成開示なし。札・余力を継承 |
| S04 | TXT07、OBJ-REPAIR。奥の水門・調える／復旧残量 | CL03を公開。水門を見ただけでは解決・新報酬・全回復なし |
| T2踏破→S05 | TXT08、OBJ-DONE | 有効なclear、RW03を取得。精算はRW01＋RW03保持、着想+3、M+1、nt_stop解放。P-01採用時だけnt_flow解放も追加。ST02=true、ACH-RESOLVEDを一度 |
| S06→S07 | TXT09、帰還結果。CL05詳細未閲覧ならTXT10B | 所持個体0、Eα構成は観測分のみ。解放済みでも所持品として3札を選ばない。終了時余力と帰還後余力を分ける |
| 次の準備 | 実際に選べる札・心得・候補を表示 | 仮にPS02基礎へ既存試行の2着想を払えば残り1。400 unitsの候補購入には届かない。習得しただけで装備済みとしない。購入見送りでも合法な準備で再訪へ出発可能 |

最後の心得・購入は接続後の説明例。PT-NTの帰還画面に実装されているとは扱わない。新探索の開始は次の明示出発であり、TXT09やS07閲覧では生成しない。

## EX02 途中撤退から再挑戦：知識は残り、入口からやり直す

開始はEX01と同じ未成長状態。1回目はEαを先に撃破し、T1まで進んだが水門の原因はまだ公開していない。以下の累計では途中で成長への支出・購入をしない。

| 段階 | 表示 | 状態・成果 |
|---|---|---|
| 1回目Eα撃破、T1未踏破 | COND03、確認した構成と未保護成果 | RW02=着想1＋nt_pressure解放対象を未保護で取得。対象の初攻略構成は既知。まだ恒久解放・所持ではない |
| T1踏破、港の公開 | TXT05・06。Eαは既に撃破のためCOND04なし | RW01とRW02を保護。前半の消耗を継承 |
| 原因公開前に任意撤退 | END-W1、COND05。実領収の持帰り一覧 | 着想2、M1、nt_pressureを恒久解放。P-01ならnt_flowも解放。所持0。CL02=true、CL03=false、ST02=false |
| 帰還から新たな出発 | TXT12→TXT14・TXT25、OBJ-PORT | MODE-RETRY、SET-UNRESOLVED、別探索ID=例run-02。前回の保護成果は恒久状態に残り、今回の報酬台帳は空。T1・T2は入口の初期状態 |
| 今回はT1を先に踏破 | 既知の港TXT15、今回の生存退場COND04 | 今回RW01のみ保護。Eαの過去の初攻略知識は保持するが、今回の撃破・RW02はなし。現在の非公開札順は見せない |
| 初めて原因公開→T2踏破 | TXT07→TXT08・09 | 今回RW01＋RW03で着想+3、M+1、nt_stop解放。累計は着想5、M2。nt_pressureは既存解放として維持。案件をここで初めて解決 |

比較境界：1回目のEα撃破直後、T1前に撤退した場合はEND-W0。着想1とnt_pressure解放対象を失い、恒久解放は増えない。一方、Eαの開示済み初期構成は残る。再挑戦で「札を知っているので持参できる」とはしない。T1後に緊急脱出した場合も今回の成果は全喪失し、知識を保持する。

既知の港・原因に応じて本文を短くし、未観測部分は初見文を使う。準備を変えた効果・面白さは[比較仮説](判断と比較仮説.md)で未測定のまま扱う。

## EX03 解決後の再訪：直った水門を背景に、道を確かめる

開始条件：EX01の踏破後、着想3・M1、ST02=true、未精算探索なし。P-01を採りnt_flow/nt_stop解放済み、所持0。支出なし。CL05詳細は未閲覧でもよい。次の明示出発に成功する合法な準備がある。

| 段階 | 表示 | 状態・成果 |
|---|---|---|
| S01R→S02R | TXT17→TXT18、OBJ-REVISIT。潮の残る地下水路・進む／道のり | MODE-REVISIT、SET-REVISIT、例run-03。ACT04と同型ACT02。以前のACT01の初攻略からACT04の全構成を補わない |
| 再訪T1踏破、Eαを残す | TXT11、COND04。正常な水門と荷揚げの景色 | RW04取得・保護。Eα生存退場、RW02なし。ACT05参加、回復なし。ST02はtrueのまま |
| S04R | TXT19。管理用連絡路・辿る／道のり | 水門や噛み込んだ鎖を攻略対象にしない。札は現地の流れと留め具の働きとして供給する案 |
| S05R→S06 | TXT20→TXT21、OBJ-CHECKED、END-R | P-02でRW04＋RW05を保持、今回着想+3・M+1。累計着想6・M2。既存解放なので新しい解放数0、所持0。連絡路の初調査完了実績を一度記録 |
| 帰還後→次の準備 | 取得候補が実際に生成された場合だけ候補と価格を表示 | 例えば400 unitsで購入可能でも、自動購入なし。購入確定後にだけ所持個体が増え、選んだ個体を次の札組へ。未実装の接続例 |

TXT08・09を再利用して「また水門を直した」と表示しない。途中撤退ならTXT23で案件解決を維持。緊急脱出ならTXT22、今回のRW04等を全喪失しても以前の3着想・M1・解放・解決実績を取り消さない。

再訪の次回も同じ調査目的で反復できる提案。ACH-RESOLVEDやACH-ROUTE-CHECKEDを重ねて報酬化せず、今回の達成と各RWを一度だけ精算する。

## EX04 探索中の保存再開：同じ借り札・同じ未保護成果を続ける

保存時点：未解決の探索run-04、MODE-RETRY、S02a付近。Eαは撃破済み、T1は未踏破。現在操作可能な一手の前。RW02は未保護、Eαの初期構成は公開済み、nt_pressureの恒久解放はまだない。実際の進行から保存した値をH・D等と表記し、架空の合法手順を実行済みとして提示しない。

| 保存する意味 | 保存時 | 再開直後 |
|---|---|---|
| 探索とモード | run-04／内容0.2／MODE-RETRY／SET-UNRESOLVED | 同一。新規出発判定を通さない |
| 主体 | P余力H、T1道のりD、Eα退場 | H・Dそのまま。Eαを再生成せず、T2を先に出さない |
| 札・共有循環 | 各札ID・由来・領域・期限、消滅予定、場、捨て場、山札順 | 全て同じ。Eα由来の捨て場札は退場時に消滅済み、残る由来札の「捨てる時に消滅」も維持 |
| 実行状態 | 時刻・乱数・次の行動予約・選択待ち・現在場面／停止位置 | 同じ一手を続ける。読込や描画で追加ドロー・NPC行動を実行しない |
| 今回の成果 | RW02取得済み・未保護、精算なし | 同じ。ST07未作成、着想・解放・所持を増やさない |
| 表示 | COND03は表示済み。現在の短文／操作位置 | 同じ位置へ「探索を再開」。COND03を新しい撃破として発火させない。帰還本文なし |
| 既知情報 | Eα初期構成開示済み、未観測の港・原因なし | 既知範囲を保持。未見の港・水門を補完しない |

再開後に撤退を明示したら初めてEND-W0としてRW02を失い、Eαの知識を持ち帰る。T1まで進めばその時にRW02を保護する。再開そのものに保護効果はない。

S03の港本文の表示中に保存した場合も、`pause=port`相当を復元し、まだ公開していないS04の原因を既知にしない。S05の踏破本文の表示中に既に精算済みなら、ST07を読んで同じ踏破結果を表示し、再精算しない。既読による省略と、未処理イベントの実行を別に管理する。

旧PT-NT-001-file-v1の保存をこの意味表だけで新形式へ変換しない。旧形式の検証・対応範囲・移行方針はCO-D01／CO-01で設計が定める。

## UI・設計が受け取る最小単位

| 受け取り先 | 入力と公開出力 |
|---|---|
| UI-S05・S06 依頼と準備 | 選択可能なモード、目的、実既知範囲、準備の合法性。全報酬表や未知のT2構成は渡さない |
| UI-S15・S18 探索と対象詳細 | 場面・本文ID、現在の対象表示、公開済み札、由来・消滅予定。現時点の目的を一つ表示 |
| UI-S16・S24 帰還と成果 | END種別、精算済み領収、今回の保持／喪失、増えた種類解放、調査記録。購入候補と所持を別に表示 |
| UI-S07〜S12 次の準備 | 確定後の所持・習得・装備・合法な無料札・実候補。読取と比較を更新操作にしない |
| 設計CO-01→後続実装 | ST→実フィールド、MODE／SET→出発アダプター、ACT→知識プロフィール版、RW→精算キーと候補生成、TXT→表示投影を対応付ける |

ここに記した入力・出力は内容側の要求。CO-D01の実API名や保存形式と照合済みとは扱わない。受入時にはDEP05・07・09・12・13の対応欄を埋め、固定試遊の変更は新試験版で行う。
