# crossweave — M1実行基盤と配布案

版：0.1／2026-09-26（日本時間）／CO-M1R R1〜R4。担当：実行基盤・配布設計 `20260926-runtime-delivery`。

**比較済み・方式判断待ち。推奨は、既存HTML/CSS/JavaScriptをElectronで包んだWindows 11 x64向けアプリを、ZIPで限定配布する方式。保存はアプリ専用領域のファイルとする。** 正式採用・実装・実機合格を示す文書ではない。今回依頼である調査・比較・推奨・後続計画の提出と、M1完成は別である。

根拠：[構成調査・一次資料](../作業資料/実行基盤・配布/CO-M1R_構成調査と比較根拠.md)、[後続実施計画](../作業資料/実行基盤・配布/CO-M1R_後続実施計画.md)、[調査版・環境・blob](../作業資料/実行基盤・配布/CO-M1R_調査版と環境.json)。

## 1. 選定の結論と成立条件

選定軸は、①利用者が開発準備なしで起動できること、②既存本体・了承済みUIを保つこと、③終了・更新後の保存を扱えること、④実物を確認できること、⑤最終アプリへ継続できること。現在の仮データはそのまま使う。

Electronを推す理由は、既存の演算と画面を同じJavaScript系統で保ちつつ、実行環境を同梱し、配布物・起動操作・保存場所をM1からアプリとして揃えられるため。ブラウザー案の追加作業はより少ないが、URL・ブラウザープロファイルに保存を結び付ける運用と、後のアプリへのデータ移行が加わる。Godot等への移植をM1前に必須とする性能・機能上の不足は、今回の公開成果からは見つからない。

次の成立条件を満たすまで「配れる・遊べる」と報告しない。

- **対象の採否**：Windows 11 x64・マウス中心・ZIP配布がM1の相手に合うこと。ユーザーのOSを特定した結果ではなく、対応範囲を絞る提案。Windows 10・ARM・macOS・Linux・スマートフォン対応は未採用・未確認。
- **作成環境**：固定バージョンのElectron／Forgeと依存を取得できるWindowsビルド環境を確保する。後続担当のWindows PCまたはWindows CIが候補。現在のWorkにWindows実行環境はない。
- **確認環境**：対象Windowsの通常ユーザー権限で、ZIPのダウンロードから一巡・終了再開・更新まで確認する。CIの成功だけでマウス操作や表示を確認済みにしない。
- **配布経路**：まず本人向けの限定配布。既存Dropboxの大型成果物運用へ新規版付きパスを登録する案。共有範囲変更・一般公開・ストア公開は別の後続判断とする。

対象Windowsで実行確認する経路を用意できない場合は、アプリ完成を待ち続けず、対象PCの通常ブラウザーで確認できるURL配信案を再比較する。無条件に別方式へ切り替えず、未成立条件と追加負担をとりまとめへ返す。今回の調査のためにWindows準備をユーザーへ要求する必要はない。

終了の案内・保存待ちの制御・版表示は後続で追加する最小機能であり、実装済みボタンと混同しない。未確定の編成を終了時に自動購入・自動確定する方式は採らない。

配布時の署名と起動警告は未確認。本人向けM1は未署名ZIPも比較対象に残すが、警告が一切出ないとは約束しない。OSや組織の実行制限を解除することを標準手順にせず、実物で起動できない場合は署名済み配布等へ見直す。広く配布する際の署名・費用・更新の整備は別途扱う。[一次資料S7](../作業資料/実行基盤・配布/CO-M1R_構成調査と比較根拠.md#一次資料)

方式Bを選ぶなら、提供時に確認したWindows PC＋Edge/Chrome通常プロファイルを初期対象とし、HTTPSの固定originでIndexedDBを使用する。プライベートモードは対象外。通常セーブは端末内で、クラウド共有保存にはならない。別ブラウザー・プロファイル・originへの移行は書出し／読込みで扱う。PWA化・オフライン配信・サーバーセーブは自動的に付いてくる機能ではない。[S8]

アプリ内IndexedDBもA1の実装候補になる。既存Storeを流用できる一方、アプリのChromiumプロファイル・origin管理とファイルへの取り出しを運用に含める必要がある。A1では更新・バックアップ・将来の保存移行をアプリ側で明示しやすい**ファイルStoreを推奨**する。この差分の原子性・終了制御を実装・確認する負担を見積りから除外しない。

## 4. R3 — 保存の方針

### 保存先・契約

- 保存先案は`%APPDATA%\crossweave\saves\m1-local.json`。Electronの`userData`をアプリ名の将来変更に引きずられない固定領域へ設定し、その配下に保存する。実際の絶対パスをアプリから確認できるようにする。[S2]
- ゲーム文書は現行`CW-M1-save-2`を継承。所持・残高・編成・候補・知識・案件状態・探索run／乱数／全領域・帰還領収・要求台帳を**同じ確定単位**として保存する。UI表示用viewだけを保存して復元しない。
- 新設するFileStoreは既存の`load(slot)`／`commit(slot, expectedRevision, document)`契約を満たす。`createCampaign({storage})`で注入し、IndexedDBStoreは保全する。保存媒体の変更だけを理由にゲーム形式をsave3へ上げない。
- 保存外枠にファイル形式・チェックサムを加える場合も、ゲーム文書のschemaとは別に版管理し、Storeが包みを外して現行Campaignへ渡す。チェックサムは破損検出用で、不正改変対策とは扱わない。
- 通常保存は1枠。確認用入力・試作のDB・旧PT-NTの保存・検査結果は別領域。通常版はMemoryStoreへ黙って切り替えない。

### 保存時点

| 操作 | 永続化する時点と再開内容 |
|---|---|
| 新規開始 | 初期文書のcommit成功後に開始。既存slotは拒否 |
| 取得・編成の確定、変換、ロック等 | 現行Campaignのコマンド単位で保存成功後に表示を更新。所持・残高・編成・候補を別々に書かない |
| 出発、探索の一手、本文進行・閲覧記録、帰還処理 | 現行executeの保存境界を継承。受理済みの一手と自動処理が揃った境界を再開点とし、描画やアニメーションの途中は再開点にしない |
| 予測・詳細表示・未確定編集・支払前取消 | 通常の画面内編集でゲーム保存を変えない。確定していない取得を保存済み所持へ昇格させない |
| 探索の中断・通常終了 | 未決の保存を待ち、最後の確定状態から再開できることを確認して閉じる。終了時だけの一括保存に依存しない |
| 強制終了・クラッシュ | 次起動で最後の完全な保存を読む。未完了操作は成功保証しない。保存成功後に応答だけが失われた場合は同request_idの再送で重複処理を防ぐ |

既存の旧draftの退避・再確認は保持するが、通常の未確定編集を新たに自動保存する要件は加えない。手札の同一性・枚数・乱数状態・進行は確認し、保存時に正規化される配列順を画面上の完全一致と誤認しない。

### 書込み・失敗・競合

実装候補は、main process側の単一書込みキュー、同一保存領域を使うアプリの単一起動、revision照合、同じディレクトリーの一時ファイルへの全量書込み・flush・検査・置換、直前の完全保存1世代の保全。これは**提案する実装手順**であり、renameだけであらゆる停電に耐えることを証明したものではない。[S2・S11]

比較・置換はキュー内で行い、古いrevisionを拒否する。失敗を空保存へ変換しない。置換前の失敗なら旧保存を維持し、置換後の応答喪失なら再読込みで要求台帳を確認する。保存成立後のバックアップ整理失敗で「決済されていない」と返さない。UIは保存待ち中に二重操作を受けず、再送時に同じrequest_idを使用する。

破損・未対応形式・読込み権限エラーがあれば、元ファイルを保全し、勝手に初期化しない。完全な直前保存から戻せる場合は、戻る版・失われ得る最後の操作を案内して選択させる。通常の新規開始と復旧を混ぜない。手動書出し／読込みは既存機能を活用し、読込みによる既存枠の無断上書きを禁止する。

2タブをM1の通常利用形態にしないため、ブラウザーの実2タブ検査はこの方式の必須から外す。代わりに同版・旧新版の二重起動抑止と、同一要求再送・stale拒否・書込み失敗を確認する。多重起動を抑止してもrevision／request_logの契約は除去しない。

### 更新と移行

配布フォルダー・ZIP名・ゲームの表示名にセーブの所在を依存させない。新版起動時は対応するschema／engine／rule／contentを検査し、対応外なら読込みを停止して元保存を保全する。移行前バックアップは通常の直前1世代と区別し、成功確認まで保持する。

M1最初のファイル保存間の更新は必須確認。既存save2の書出しデータは明示importの経路で再利用する。save1と旧編集中案は既存移行例を使う代表確認へ縮小し、ブラウザーDBを自動探索・回収する新機能は作らない。旧UI・試遊の異なる保存形式を互換とみなさない。新版で変換した保存を旧版へ自動で逆変換しない。旧版へ戻す場合は対応する更新前バックアップを使う。

| N6 | 同版・旧新版の二重起動、古いrevision・同要求再送 | 2つの書込み所有者を作らず、staleを拒否。再送は一度だけの効果 |
| N7 | 旧ZIP→新版ZIP、save2 import、代表save1／旧draft、壊れた入力 | 保存領域が同じで更新後も再開。移行は一度、旧案は要確認。未対応・不正時は元保存不変。新規作成や候補再抽選でごまかさない |
| N8 | ネットワークなしで新規・続き、通常マウス操作、FHD・倍率変更 | 起動・素材・文字・ドラッグ・詳細窓・一巡を操作できる。ブラウザー／Nodeの別インストールや開発サーバーが不要 |

停電耐性を物理試験していない場合は未確認と明記する。最終アプリではバックアップ世代・保存容量／速度・同期等を実際の必要性に応じて拡張する。M1へクラウド保存・複数端末・複数枠を追加しない。
