# AJ1：準備から再挑戦までの通し試作

[crossweave-journey.html](crossweave-journey.html)を保存し、JavaScriptが動くブラウザーで開く。通信やインストールは不要。開始時は成長ポイント0、初期札の構築から始まる。

## 試せる流れ

1. A/Bから探索先を選び、持込12枚と習得を編集する。「試したい狙い」は任意。札名を開くと性能を確認できる。
2. 変更差分・返還・習得費・残ポイントを確認して出発する。枚数違反や予算不足の変更案は確定されない。
3. 相手と環境／共有の場／自分と手札の配置で操作する。札の選択→対象の選択→実行が基本。通常設置の札別ボタンとドラッグは操作設定で切り替えられる。
4. 踏破・撃破・撤退・死亡の結果を確認する。持帰り・喪失・新しい札の解放・確認済みの知識を別々に示す。
5. 前回の構築を起点に札と習得を変え、再出発する。習得を外すと実際に使ったポイントを全額返還する。未使用ポイントを残してよい。

進行・変更途中の案・操作設定を自動保存する。保存が利用できない環境では画面で知らせる。「保存ファイル」でJSONを書き出し、「読み込む」で戻せる。同じ探索の再読込みではHP・場・手札・乱数・知識を復元し、報酬を重ねて受け取らない。保存ファイルはAJ1専用で、旧UI-R-002や旧Zの保存とは互換ではない。

## 固定した条件と参照元

| 項目 | AJ1の範囲 |

| ゲーム処理 | AHの三探索先・習得・帰還に、AIの準備検証と借り札観測を接続。旧ファイルの変更なし |
| 初期条件 | ポイント0、初期札guard3（攻撃8・防御3・回復1）、HP60、手札3、持込12・同名2枚まで |

UI由来の`support.js`・`view.js`・`play.fragment.html`はAJ向けの派生版。元blobとSHA-256を[provenance.json](provenance.json)に記録する。旧Z固有の大岩・区間・再開始を、A/B/Cの目標・帰還・次の準備へ差し替えた。パッシブ込みの行動コスト・次の時刻、借り札の由来、待機中／今回有効な習得を表示する。相手の知識欄は観測台帳から作り、未公開の初期山札や現在の手札を補完しない。

具体的な数値・札名・スキル名・画面構成は試行値である。UI Workの専用ファイル、PT-Z-001、UI-R-001/002の固定条件、既存AH/AIの比較結果を更新したものではない。

## 再生成と確認

リポジトリルートから実行する。組立はNode.jsとPython 3の標準機能のみ。参照エンジン・入力のSHA-256が異なれば組立を中止する。

```sh
node docs/検証/統合試作/deck_feedback_trial/journey_aj/build.cjs
CW_JSDOM_PATH=/path/to/jsdom node docs/検証/統合試作/deck_feedback_trial/journey_aj/verify.cjs
```

今回のDOM確認にはjsdom 30.0.1を使用した。[verification.json](verification.json)へ結果を保存。

- 150手について、画面から実行した状態・乱数を既存AH/AIと照合し、選択時の予測と実際の一手を確認。PS01の割引が予測コストと次の時刻へ反映される局面を含む。
- 初期ポイント0からAを34手でクリアし、得た踏ん張りを重撃1枚と交換、PS02を習得してCを25手でクリアする自動操作を確認。その帰還後にPS04へ無料で取り直して次の一手を比較した。
- 別の自然開始Bは21手でクリア。Cの死亡fixtureは42手で死亡し、今回報酬喪失・既習得と知識保持を確認。勝敗は固定方策による接続試験で、人の試遊結果ではない。
- 途中再読込み7件と、帰還再読込み・次の同じ一手・部分成果の撤退・不正構築・探索中の習得拒否・保存JSON読込み・不正な自動保存の非上書きを確認。
- 通常設置の札別／ドラッグ／確認操作、場外取消・Esc・pointercancel・タッチ本文の非ドラッグ・古い入力の拒否・一致攻撃の明示的な対象選択を確認。テスト用参照口は検証時だけ挿入し、配布HTMLには含めない。

実ブラウザーの描画・画面寸法・実端末のタッチ操作・ファイル選択／ダウンロード、人の自由構築と反復負担は未確認。ローカル環境に実行用ブラウザーがなく、取得も完了しなかったため、DOM確認を実描画確認とは扱わない。

## 次に評価すること

「遊べる接続」と「狙った体験が成立した」は分ける。初回の勝敗だけで構築の良否を採点せず、次の三点を追う。

| 観点 | 見たい経験 | 問題が出た場合の対応 |
|---|---|---|
| 狙いを作り直せるか | 帰還後、外す札・入れる札・習得変更の理由を持てる | 変更差分や解放札の役割が読めないなら表示を修正。読めても違いが出ないなら札・習得・探索内容の組合せを見直す |
| 現地の選択が後半に効くか | 支援環境、有限札、借り札への対処が次の状況へ続く | 判断が済んだ後の同じ反復を減らす。C32/C24の比較候補を使い、全回復・手札リセットで区間を切らない |
| 成長が選択を広げるか | 少ない予算から二つ以上の狙いを組み合わせ、取り直して試せる | 四候補・合計8ptだけでは長期の取捨選択を評価できない。習得候補の段階追加と成長予算の設計を先に比べる |

設計上の対応策・全体優先順位は[探索全体の設計22章](../../../../仕様案/カード探索ゲーム_探索全体の設計.md#playable-journey-aj)を参照。素材用途・世界観・装備枠をこの接続から確定しない。
