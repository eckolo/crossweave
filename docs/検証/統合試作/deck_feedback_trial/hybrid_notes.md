# 成長ポイントと用途限定報酬：AF1

2026-09-09 UTC。採用済みD43・基本設計0.43に対応する、複数種類の報酬と帰還後使用の接続試験。報酬内容・量・素材名・レシピ・強化値は仮設定。

続くユーザー指示により、素材の具体用途を固める前に世界観を幅広く検討する。以下の硬質片や札名は処理確認用の仮例であり、世界観や成長対象の既定案ではない。[世界観Workへの引継ぎ](../../../作業資料/引継ぎ/カード探索ゲーム_世界観Work_引継ぎ.md)を参照。

## 目的

一つの攻略報酬に複数の明細を持たせ、成長ポイント・用途限定素材・札解放を独立して保持する。使い道の選択と用途の制限を両立させ、同じ獲得・保護・精算から次の構築・強化へ渡せることを確認する。

元のAE1は比較時の入力・コード・結果を保全する。AFは既存の構築検証・出発・ポイント購入を再利用し、AEの重複札→ポイント変換や自動HP適用は呼び出さない。共通の戦闘・札循環・報酬保護規則は変更しない。

## 試行プロフィール

初期10種類・山札12枚・同名2枚まで・属性比固定なしはAEと同じ。採用済みの製品値ではない。

| 取得元 | 仮の報酬明細 |
|---|---|
| 大岩R | 成長ポイント1＋硬質片1 |
| 最初の環境T0 | 成長ポイント1＋踏ん張りの解放 |
| 敵E | 成長ポイント1＋鋭撃の解放 |
| 後続環境T1 | 成長ポイント2＋硬質片1 |

同じ取得元の明細は同じ保護・精算に従う。たとえば未保護のRを任意撤退で失う場合、ポイントと素材の両方を失う。後の踏破でRが保護されれば両方を持ち帰れる。今回取得した分は死亡で失い、以前に持ち帰った各種の成果は保持する。

固定用途の例は硬質片1で溜め打ちを解放、別の例は硬質片1と成長ポイント2で常時軽減+1。ポイント単独ではAEの3点でHP+2／軽減+1も比較に使える。**同じ強化に素材とポイントを併用するレシピは試行例であり、D43による採用や全強化への義務付けではない。** 素材の限定先を迂回できる汎用換金はこの試験にない。能力値と価格の優劣を判断する試験ではない。

既解放の札が再び報酬に含まれた場合は、処理未決定の重複として記録する。重複の補償・現物在庫・一律ポイント化のいずれも正式採用しない。T0を2回持ち帰ると、明示されたポイント明細から合計2点を得る。重複札からさらに加点されたという扱いにはならない。

## 入出力と再現

```sh
node docs/検証/統合試作/deck_feedback_trial/hybrid_study.cjs
```

Node.js／Python 3の標準機能のみ。`hybrid_inputs.json`が条件、`hybrid_rewards.js`が処理、`hybrid_results.json`が結果と参照16ファイルのSHA-256。旧比較結果は更新しない。

| 関数 | 入出力 |
|---|---|
| `initialProfile()` | 初期解放を持ち、ポイント0・素材0のAF専用プロフィール |
| `depart(...)` | AFプロフィールを既存AEの出発処理へ渡し、AFの素材・記録を保持した探索状態を返す |
| `finish(profile, runId, game)` | 既存エンジンの精算と取得済み報酬の保護状態を照合し、持帰り明細だけを各保管先へ反映 |
| `buy(profile, id, kind)` | 帰還後に選んだポイント用途へ支払い。素材の残数は変えない |
| `useMaterial(profile, id, recipeId)` | 指定用途のポイント・素材を全て確認してから消費。要件不足ではどちらも消費しない |
| `rewardsView(publicState)` | 現在までに獲得した報酬だけを、明細・未保護／保護／持帰り／喪失として表示するデータ |
| `holdings(profile)` | ポイント残高、保有素材と対応用途、解放札、未処理の重複記録 |

全関数は入力プロフィールを複製して次状態を返す。呼出側が次状態を保持して次の操作へ渡す。精算・素材使用の同一IDの再処理は加算・消費を重ねず、内容の矛盾は拒否する。旧AEプロフィールの恒久保存移行、複数端末・同時操作・改ざん対策などの製品基盤は対象外。

知識は既存のAD／D42観測処理からプロフィールへ反映する前提であり、AFは受け取った知識を維持する。AFの自然2経過には知識観測アダプターを追加していない。既存のD42検証を再計数せず、AFだけで通し試遊の全機能が完成したとは扱わない。固定PT-Z-001／UI-R-001の画面と条件は不変。

## 確認したこと

- 人工的な精算4条件：未保護撤退、保護済み撤退、クリア、死亡。複数明細を一緒に精算し、元のゲームが不変で、JSON読み戻し後の同精算も二重反映しない。
- 人工的な支払4枝：ポイント4・硬質片2から、保持、HP購入、素材のみの札解放、ポイント＋素材の強化をそれぞれ次出発へ接続。
- 支払不足3条件：ポイント不足、素材なし、別素材だけを保有。すべて元の残高・在庫を変更せず拒否。探索中の素材使用・未精算状態の反映も拒否。
- 重複札1例：T0を異なる探索で2回持ち帰り、ポイント2と重複記録1を保持。札解放は1種のまま。
- 公開範囲2条件：報酬未取得時は空、R取得後はRの2明細だけを返す。未取得T0等の内容をこの表示から公開しない。
- 既存AEと同じ2自然経過：seed0で環境踏破後P5手帰還→踏ん張り1枚採用→seed1でP34手死亡。ゲーム終端ハッシュはAEと一致。新たにポイント1も持ち帰り、次探索の死亡後もそのポイントと札解放を保持した。

自然2経過では素材取得・使用と強化購入まで到達していないため、それらは人工条件の結果として区別する。新しい人の所感、獲得意欲、成長速度、最適反復、素材が全体の遊びへ寄与するかは未評価。

## 世界観検討と接続した後の具体化

先に世界観候補を広く比較し、成長する対象と成果の意味を考える。以下はその方向性と往復して具体化する評価課題であり、AFの素材・用途を先に固める指示ではない。

- 成長ポイントだけで進める用途と、特定報酬を狙うことで進める用途を、次に選びたい探索・構築へ結び付ける。
- 素材を挟む意味を確認する。唯一の用途へ即時に変換するだけなら、札や固定強化の直接報酬と体験差が小さく、素材という段階が必要かは個別に判断する。
- 素材とポイントの二重要求には、素材待ちでどの成長も止まる条件と、素材の有無に応じて選び分けられる条件の差がある。既に採用済みの併用方針だけで前者を標準にしない。
- 重複札・余剰素材の扱いは具体的な取得頻度と用途が揃ってから比較する。今回の保留記録を製品の最終的な無補償処理として扱わない。
