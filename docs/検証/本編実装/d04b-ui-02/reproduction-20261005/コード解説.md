# 合意UIの再現修正を読む

パスの先頭は `apps/crossweave-godot/`。画面コードは `Godot/Application/`。`partial` はC#のファイル分割で、別の本編・session・保存を作る機能ではない。

## 一つの操作が通る道

公開View → 実Controlの表示 → `GuiInput`／Buttonの`Pressed` → 未払いPlanの編集または既存`Send` → `FileGameSession` → Coreの確定結果 → `Adopt` → `Render`となる。画面は価格、行動結果、消滅先、順序の同時刻を推定しない。`PreviewAction`／`PreviewPreparation`の応答を表や差分へ配置する。

取得を押す・列へ移す操作はPlanだけを変える。確認窓で一度確定するまで支払わない。無効案も編集内容を勝手に補充・破棄しない。R07の`CanStage`とR06の`DropPlan`は、ボタン・詳細・ドラッグで共用する。quick設置で未使用札が消滅する場合は既存公開予測を表示して確定を待つ。補充札の合法実画面が未取得なら、同じ分岐があることだけで合格にしない。

## Godot固有の部分

`Control`、`Panel`、`Label`、`ScrollContainer`、`Button`、`CheckBox`、`Theme`、`StyleBoxFlat`はGodotの部品。サイズと入力領域は実ノードから採取する。取得・手札・場の余白送りは同じ実`ListViewport`へ入る。自然なFHDでoverflowが0の状態と、同じノードの幅を限定した送り検査を区別する。

GodotのLabelの自然高はCSSのline-heightと同じではない。末行にも一行分の領域を設け、本文は20px／34px、一般段落は18px／1.6で組む。句点と禁則・grapheme分割は原本`prose-layout.js`に従う。文字、公開値、読了IDを編集する処理ではない。数値のGeorgiaと日本語のYu Gothic UIをbaselineで並べる集計も、文字画像を手で移動せずfont metricsと原本の行高から配置する。

書体集合TTCには複数faceがある。このGodot版では`VariationFaceIndex`の変更後も実幅が旧faceのままだったため、`AcceptedSystemFont`は既存OS faceのテーブルを同じ内容のままメモリへ読む。変更するのは格納位置とchecksumであり、字形・name・metricsを作り直さない。書体を素材ファイルへ保存・再配布しない。現在の原本ブラウザーで採った文字別解決fontと、過去に未記録だったOS／AAは別項目として残す。

SVGは原本の既存Lucide定義。動的Textureはそのpathの描画である。shaderはCanvasItemの既にTextureを乗算した`COLOR`のalphaだけを角丸maskへ通す。もう一度Textureを掛けるとRGB・alphaを二重乗算して、既存絵の見え方を変えてしまう。

hoverは押下中も続く原本CSSの状態を、同じButtonの現在themeから反映する。focus-visibleはkeyboardから選んだ時だけ別の透明輪郭面を重ねる。mouseで別操作を選んだ時に輪郭を消すことと、keyboardで選択済みの同じ操作をクリックした時に維持することを分ける。checkboxは文字ラベル全体ではなく20pxのinputへ輪郭を出す。これらは選択・確定の条件を変更しない。

取得移動の200ms ease-out、120msのホールド表示、220msの掴み成立、eventの260ms送り・1300ms維持・2800ms終了は表示時計である。減動設定はこの起動中の画面設定で、DTOや乱数へ混ぜない。連続証拠は実FramePostDrawごとの画像と壁時計を先に保持し、入力列の後にPNGへ圧縮する。圧縮でmain threadが停止する時間をホールド時間の実測に加えない。

## C#／.NETの部分

ラムダはButton等のsignalへ操作意図を登録する。`async`／`await`は描画や既存保存workerの完了を待つもので、保存が済んだと推定する機能ではない。`JsonObject`／`JsonArray`のコピーを使い、公開応答を描画用に加工してもCoreの状態を変更しない。

`J.Obj`は子JSONを深くコピーする。取得行の修飾説明をコピー後の旧home変数へ足しても応答には入らない。今回の`Inspect`では、公開取得・所持行へ修飾説明を足してから応答を組む順に直した。単なるソース上の代入と、利用側が実際に受け取ったpayloadを区別するための変更である。

## 本作が所有する境界

札の効果量、有限回数・明示null・キー欠落、回収時消滅、共有回収、保存形式は既存Core／契約の所有物。UIはゼロや既定2で未公開を補わない。主体の防御内訳の表示区分は、既に公開されたeffectsのusesを要約するだけで、消費・持続を新しく計算しない。

記録の「この主体」「同探索の別主体」「過去」は、UIが名前や見た目から分類しない。最小の`UiPublicProjection`が旧記録のrun・actor・profileを使って原本の分類へ投影する。公開側には原生のrun/event ID、私有山札、未観測札を渡さない。初期構成は明示的なcatalogue grantのある場合だけ表示する。未知の構成は未知のまま残す。

## 失敗した時の状態

保存が拒否された時は未確定案を保ち、成否不明なら操作を止めて既存の照合・再読込みへ進む。同じrequestの再送は既存のreplayed結果を表示し、二重に適用しない。復旧は隔離検査でだけ故障を注入し、壊れた元ファイルも保全する。通常セーブの削除・初期化で問題を隠さない。

この版には不足と失敗試行を残す。失敗したmanifestや未取得fixtureを、後の別ケース成功へ読み替えない。読む人はID別のsource hash、入力mode、原寸画像、DTO・実ファイルの証拠を一緒に確認する。独立UI適合・配布・実機受入はこの教材の完了宣言ではない。
