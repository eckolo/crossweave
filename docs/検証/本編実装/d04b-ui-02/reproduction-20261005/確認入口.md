## 同じ本編の入口

アプリは既存 `apps/crossweave-godot/Godot/Main.tscn`／`GameScreen`。仮画面、第二本編、新規配布物は作らない。検査引数のある起動だけが `user://proofs/d04b-ui-save-01/<新しい隔離slot>/m1.json` を使う。通常起動の保存は読まない・書かない・初期化しない。

担当・CIが既定環境を準備し、必要modeを新しい証拠出力先で確認する。以下は開発担当用で、遊ぶ利用者への手順ではない。

```sh
python apps/crossweave-godot/UiProbe/verify.py --no-acquire --skip-regression --rendered --full-hd --theme light --modes repro-home,repro-explore,repro-prediction --review-fixtures docs/検証/本編実装/d04b-ui-02/reproduction-20261005/fixtures --evidence <新しい証拠出力先>
```

## 原本の入口と制約

`legal-common-fixed`／`legal-return` は固定原本72d0eb58のCampaignと合法commandから得た状態。C#接続ではFormatVersionと二つの識別タグだけを既存形式へ合わせる。登録値・数値・素材・私的状態の作り替えはない。元保存、合法command列、公開応答、hashを残す。`fixtures/receipt.json`で検査入力への同一コピーを確認する。

原本の採取は既存bundleとCampaignを隔離MemoryStoreで接続し、1920×1080、DPR1、zoom1の現Edgeから実画像・DOM・文字別解決fontを得た。localhost・拒否済み経路・代用UIは使わない。`verification/`は実行した補助コードの保存版で、当時の担当環境のパスを含む。通常利用者へ実行を要求しない。

R01-filler／R04-unlimitedの合法fixtureは未取得。一般分岐や単体境界を確認したことを該当実画面の証拠へ置き換えない。再開には既存担当が確認できる合法command・seed・旧保存、または既存全入口の到達不能根拠が必要である。[必要証拠と残件](必要証拠と残件.md)で担当と条件を固定する。
