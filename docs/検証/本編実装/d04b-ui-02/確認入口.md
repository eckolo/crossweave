担当側で固定環境を準備した後、必要な指摘modeだけを新しい出力先へ再実行する。通常の利用者へこのSDK手順を要求しない。

```sh
python apps/crossweave-godot/UiProbe/verify.py --no-acquire --skip-regression --rendered --full-hd --modes review-preparation,review-destination,review-destination-field --review-fixtures docs/検証/本編実装/d04b-ui-02/review-20261002/fixtures-fixed/fixtures --evidence <新しい証拠ディレクトリ>
```

`review-safety-consume,review-safety-doomed,review-safety-quick,review-resume,review-safety-off,review-safety-matched`がR01。quickとresumeは同じ実行の並びで使い、別プロセスから同じ隔離slotを開く。`review-prediction-place,review-prediction-attack,review-prediction-guard,review-prediction-heal,review-prediction-defense_support`がR03／R04。`review-order-tie,review-order-different`がR05、`review-preparation`がR02／R07、`review-destination,review-destination-field`がR06、`review-scroll-prep,review-scroll-hand,review-scroll-field`がU01。

現在のfixtureディレクトリにfillerとunlimitedはない。未確認の境界を再開する場合は規則・数値を変えずに合法な状態を得て、対応する固定fixtureを指示別に保存する。fixture再生成だけを行う入口は`--modes review-fixtures`（描画省略可）。この生成だけで操作確認の合格にはならない。

関連.NET回帰のfilterは[manifest](review-20261002/selected-regression/manifest.json)のcommand／selectedを使う。15件は新しい回収先公開契約、予測非破壊、公開コピー、取得群原子性、取消、DTO往復と次結果、再精算防止、防御境界だけ。全旧スイートを再実行しない。

人の確認順はR01の消滅で止まること→R03の5能力と予測→R02の混合確認と取消→R04の場／防御／消滅詳細と記録→R05の同時刻→R06の移動先と可否→R07の上限全入口→U01の余白送り。自然FHDで列が収まる状態と、実node限定寸法でoverflowを作る試験を区別する。担当所有の隔離保存以外を削除・初期化しない。

## 開発担当が再実行する

固定ツールを担当側で準備する。システムSDKを変更せず、既存UiProbeがリポジトリ内`.tools`へhash照合した依存を置く。

```sh
python apps/crossweave-godot/UiProbe/launch.py --prepare-only
python apps/crossweave-godot/UiProbe/verify.py --no-acquire --rendered --full-hd --evidence <新しい結果ディレクトリ>
```

検査は通常Main.tscnを、引数で明示した一意の隔離slotへ向ける。普段の`user://saves/local/m1.json`を読まない・書かない。既存セーブを削除する準備は不要。履歴の検証slotも削除して再利用せず、毎回新しいslotを作る。

- `--modes interaction,resume`：同じ検査slotを別プロセスで開き、全DTOと次結果を比較する。resume単独を新しい出力先で実行しない。
- `--modes inheritance`：編成・未払い・ドラッグ・詳細・予測・行動順・記録・本文・帰還→編成を操作し画像を取得する。
- `--modes natural`：既存自然一巡fixtureの入力順を実画面のボタンへ渡し、Core結果・保存・精算を照合する。
- `--modes legal-acquisition`：既存の合法取得fixtureで通常初回に出ない有料心得・変換を確認する。通常保存へ検査残高を入れない。
- `--skip-regression`：同じCore／保存コードで.NET回帰を既に実施し、UIだけ再確認する場合。
- `--skip-build`：同じソースをビルド済みの場合のみ。今回の正式な修正後記録はビルド込み。

`verify.py`はビルド開始前のsource_sha256を固定し、実行中のソース変更を検出すると不合格にする。各modeのJSONはscene・プロセスID・隔離保存先・実窓寸法・入力方式・確認項目を持つ。

## 人が後続レビューで見る順

1. 起動→探索先左上「編成」。札／心得、三領域、未払いの取得予定、取消・確認・確定を確認する。
2. 探索本文は左下。右下「進む」→探索。札の効果値と場の値、主体と本人の位置、行動順アイコンを確認する。
3. 左右の札・主体・行動順を交互に選ぶ。反対端の詳細、同じ対象で閉じる、隣の選択、予測札の非実行を確認する。
4. 札の角寄りを220ms保持して動かす。元の掴み位置、同じ札面、横送り、Esc・右クリック・ホイール取消を確認する。
5. 予測と行動ボタン、記録の基本構成と札詳細、メニューと表示設定を確認する。
6. 帰還は右下「進む」→探索先→左上「編成」。同じsessionと所持・残高を確認する。

この順序は後続UI適合確認への案内であり、Windows11物理入力・DPI・音・GPU性能の受入を今回済ませた意味ではない。利用者が遊ぶ入口は後続の修正版配布であり、この開発手順の実行を利用者へ要求しない。
