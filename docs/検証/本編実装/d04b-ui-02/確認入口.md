## 開発担当が再実行する

固定ツールを担当側で準備する。システムSDKを変更せず、既存UiProbeがリポジトリ内`.tools`へhash照合した依存を置く。

```sh
python apps/crossweave-godot/UiProbe/launch.py --prepare-only
python apps/crossweave-godot/UiProbe/verify.py --no-acquire --rendered --full-hd --evidence <新しい結果ディレクトリ>
```

検査は通常Main.tscnを、引数で明示した一意の隔離slotへ向ける。普段の`user://saves/local/m1.json`を読まない・書かない。既存セーブを削除する準備は不要。履歴の検証slotも削除して再利用せず、毎回新しいslotを作る。

- `--modes interaction,resume`：同じ検査slotを別プロセスで開き、全DTOと次結果を比較する。resume単独を新しい出力先で実行しない。
- `--modes inheritance`：編成・未払い・ドラッグ・詳細・予測・行動順・記録・本文・帰還→編成を操作し画像を取得する。
- `--modes natural`：既存自然一巡fixtureの入力順を実画面のボタンへ渡し、Core結果・保存・精算を照合する。
- `--modes legal-acquisition`：既存の合法取得fixtureで通常初回に出ない有料心得・変換を確認する。通常保存へ検査残高を入れない。
- `--skip-regression`：同じCore／保存コードで.NET回帰を既に実施し、UIだけ再確認する場合。
- `--skip-build`：同じソースをビルド済みの場合のみ。今回の正式な修正後記録はビルド込み。

`verify.py`はビルド開始前のsource_sha256を固定し、実行中のソース変更を検出すると不合格にする。各modeのJSONはscene・プロセスID・隔離保存先・実窓寸法・入力方式・確認項目を持つ。

## 人が後続レビューで見る順

1. 起動→探索先左上「編成」。札／心得、三領域、未払いの取得予定、取消・確認・確定を確認する。
2. 探索本文は左下。右下「進む」→探索。札の効果値と場の値、主体と本人の位置、行動順アイコンを確認する。
3. 左右の札・主体・行動順を交互に選ぶ。反対端の詳細、同じ対象で閉じる、隣の選択、予測札の非実行を確認する。
4. 札の角寄りを220ms保持して動かす。元の掴み位置、同じ札面、横送り、Esc・右クリック・ホイール取消を確認する。
5. 予測と行動ボタン、記録の基本構成と札詳細、メニューと表示設定を確認する。
6. 帰還は右下「進む」→探索先→左上「編成」。同じsessionと所持・残高を確認する。

この順序は後続UI適合確認への案内であり、Windows11物理入力・DPI・音・GPU性能の受入を今回済ませた意味ではない。利用者が遊ぶ入口は後続の修正版配布であり、この開発手順の実行を利用者へ要求しない。
