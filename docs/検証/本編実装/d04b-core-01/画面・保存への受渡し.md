# D04B-CORE-01 画面・保存への受渡し

2026-09-28。純C#・メモリー本編。Godot画面を接続した記録ではない。

## 画面側の入口

`Crossweave.Core.Application.GameApplication.Create()`で新規開始。以後同じインスタンスを保持し、出発ごとにCreateしない。初期状態は所持20、編成12、着想0、帰還候補なし。準備からSCN-001だけへ出発する。

| API | 戻り値と役割 |
|---|---|
| Inspect() | 独立コピーのJsonObject。revision/view_token/phase/capabilities/home/draft/story/case/profile/knowledge/exploration/action_history/return |
| PreviewPreparation(revision, token, plan) | コピー上の準備。ok/current/owned/groups/acquisition/equipment/deck/payment。新取得はpending:trueとpending handle。失敗はok:false/error、元本体は不変 |
| PreviewAction(revision, token, choice) | 現在の一行動だけ。ダメージ、体勢、防御、actor_changes、field_after、unused_hand_after、current_reservations_after、next_self_reservation。NPCの将来選択・次の手札は計算しない |
| QuoteConversion(revision, token, itemIds) | 変換額と件数、前後残高。読取りのみ |
| Execute(GameCommand) | CommandResult(Status,Error,View)。committed/replayed/rejected。成功・再送時はView全体を交換する |

`GameCommand(RequestId,ExpectedRevision,ViewToken,Type,Payload)`。RequestIdは操作ごとに一意。同じ意味の再送は同じID、変更した案は新ID。古いrevision/tokenでは拒否。同IDの違う内容はrequest_conflict。同要求のreplayedは追加消費・追加領収なし。

| Type | Payload |
|---|---|
| save_draft / commit_preparation | { plan } |
| discard_draft / withdraw / ack_return | {} |
| set_item_lock | { item_id, locked } |
| convert_items | { item_ids:[] } |
| depart | { case_id:"SCN-001" } |
| play | { choice:{card_id,target} }。exploration.legal_actionsから渡す |
| continue_scene | { scene_id, advance?:true, displayed_text_ids?:[] }。advance:falseは表示記録だけ |

planは `schema:"CW-M1-preparation-2", acquire:[], composition:{deck:[],equipment:[]}, migration_review:null`。Inspect().draft.planをコピーして編集。`acquire`は取得可能行のid、編成はowned行のidか取得可能行のpending_selection_idを使う。取得取消は未払いのacquireとそのpending参照を除く。取り外しだけでは取得予定を取り消さない。確定所持品を取得可能へ戻さず、別の変換操作へ渡す。

`home.owned`の個体・数量・選択・ロック・変換理由、`home.groups`の集約、`home.acquisition`の残在庫と群制限、`home.offers.status`と持越しを使う。初期／後日取得を別操作へ分けない。detailsには札の合成済み値、心得の発動条件・合成済み効果・条件・装備容量を渡す。UIで価格や効果を再計算しない。

本文はstory.texts、既公開履歴はstory.text_history。Inspect・予測は状態不変。continue_sceneで実閲覧記録だけ増えても、精算を再適用しない。帰還phaseの確定済み領収を表示→必要な本文を進む→ack_return→同じ準備へ戻る。

画面はExportDtoの内部stateを参照しない。NPC私有札順・乱数・台帳UID・request履歴はviewに渡さない。画面内未確定編集はUI側で保持し、通常のドラッグごとにsave_draftを呼ばない。拒否時は案を保ち、Viewを成功扱いにしない。

## 保存側の入口と保持対象

`ApplicationDto(FormatVersion:1, RuleSetId, ContentSetId, State)`。State.schema=`CW-CSharp-application-1`、engine_version=`CW-CSharp-core-1`。現行規則0.5／内容SCN001-0.2を固定。ExportDto()は独立コピー、Restore(dto)は別の所有者へ深いコピーで復元。JSONシリアライズ→デシリアライズのメモリー往復を試験済み。旧JavaScriptセーブの製品移行APIは実装していない。検査fixtureの変換はTestsだけ。

| DTO内部 | 必ず保持する意味 |
|---|---|
| revision/view_nonce/request_log | 古い操作拒否、同ID同内容の再送、二重適用防止 |
| session.campaign_id/nextRun/active | 探索ID・index・seed・mode・内容版・set・公開履歴。次の探索を同seedで再作成しない |
| economy/profile/inventory/unified/at/sales | 残高と端数、全所持個体、初期付与／取得／変換履歴、ロック、候補・購入・帰還の台帳、知識・資材・解放・成長 |
| au.deck/aq.equipped | 確定編成。実個体IDと修飾、次出発の持参内容 |
| game.state/memory/next_card_number | 手札・山札・場・共有回収・消滅、主体HP/体勢/機転/防御の量と回数、予約時刻、イベント・報酬保護、観測・パッシブ待機条件 |
| game.rng/future_rng | MT全語＋index、未登場主体を含む全系列。復元時再seedしない |
| receipts/casebook/public_history/scene | 一度だけの帰還、初解決、再訪、手掛かり、本文公開と実閲覧 |
| draft | 明示保存された未確定案とrevision/dirty/valid。未払い参照を確定個体へ昇格させない |

安定時点はExecuteの一コマンド全体。内部の攻撃途中・帰還資源だけ加算した時点・支払だけ済んだ時点は外へ公開しない。

確定順：現在版・要求履歴確認 → 深いコピーで演算と検査 → candidate DTOをIApplicationCommitBoundary.TryCommit(expectedRevision,candidate)へ渡す → trueのときだけメモリー所有状態と公開viewを交換。false/例外では元状態を保持し、同じ要求を再試行できる。デフォルトの境界未指定はメモリーのみ。任意に注入した境界の失敗はC#試験の偽物で、実ファイル書込み失敗の確認ではない。

後続の保存担当は、一つの確定キューとストア所有権の下で候補を永続化してからtrueを返す。falseは「永続化していない」を意味する。書込み成否が不明な中断、原子的ファイル置換、バックアップ、二重起動、更新互換、破損診断、容量・OS権限はRD-SAVE-02で実装・検証する。request履歴・領収・観測を今回無制限に保持しており、長期量の制御も後続で互換を定義して扱う。

DTOは本編の取出し／復元契約であり、外部入力全体の耐改竄検査・正式ファイルフォーマット完成を意味しない。現行構造・版・札保存則・編成・領収整合の検査を持つが、更新版からの移行・不正な任意編集の完全な検査は後続。
