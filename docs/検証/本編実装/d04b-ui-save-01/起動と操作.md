# 本編の起動と操作

以下のパスはリポジトリルート相対。これは開発環境からの起動案内で、正式配布物の案内ではない。

## 初めて開く

1. このアプリ枝を取得し、Python 3.12以上で `python apps/crossweave-godot/UiProbe/launch.py` を実行する。
2. 初回は固定SDK10.0.401・Godot.NET4.7.2・Noto Sans JPを取得しhash照合する。restore、build、Godotの素材importが終わると本編の開始画面が開く。
3. 保存がない場合は「新しく始める」。既存の完全保存がある場合は「続きから」。保存失敗を空の所持や新規開始へ置き換えない。

`--editor` を付けるとGodotエディターが開く。対象は `apps/crossweave-godot/Godot/project.godot`、実行はF5（プロジェクトの通常入口）。同じC#コードを読むIDEは `apps/crossweave-godot/Crossweave.sln` 一つでよい。F11はウィンドウ／全画面の切替。基準は1920×1080、初期ウィンドウ1280×720、比率16:9を保つ。

取得済み環境だけを使うには `--no-acquire`、GUIを開かずビルド・importまで確認するには `--prepare-only`。OSの画面が使えない環境では、後述のheadless確認へ進み、実表示合格とは記録しない。

## 本編の操作順

| 場面 | 操作・期待する結果 |
|---|---|
| 拠点 | 「編成」から取得可能／所持／編成を開く。「札」「心得」で分類を切り替える |
| 取得 | 候補の「取得」で未払いの予定にする。詳細の「取消」または取得可能へドラッグで取り消す。残高はこの時点で減らない |
| 編成 | 「編成」「外す」、または220ms保持後のドラッグで移動。枚数不足や枠超過は確認に表示され、勝手に補充されない |
| 一括確定 | 「確認する」で候補・札組・心得・価格を確認し、「確定する」。成功後に所持と残高が更新される |
| ロック／変換 | 所持の札を選ぶと詳細。ロックした個体、初期配布品、編成中の個体などはCoreの理由により変換不可。変換は別の確認窓から明示確定する |
| 出発 | 「戻る」→「出発」。未確定の変更がある間は出発できない。「戻す」は画面案を確定編成へ戻す |
| 本文 | 実際に表示した段落を記録する。「続きを読む」で進む。「詳細」は任意本文。目的表示は読了対象へ送らない |
| 探索 | 手札を短く選ぶと詳細・予測。主体を選ぶと対象になる。「行動予測」で公開予測を読む。「行動する」で確定 |
| ドラッグ | 220ms保持して場へ放す。一意の合法行動または選んだ対象があると確定。対象候補が複数で未選択なら予測を表示し、対象と確定ボタンで確認する |
| 一覧の移動 | 保持前の横スワイプは一覧のスクロール。内部のScrollContainerを使い、全画面の縦スクロールはしない |
| 詳細・取消 | 左側の札からは右端、右側からは左端に詳細を出す。同じ札、外側、×で閉じる。Esc・右クリック・フォーカス喪失はドラッグを取り消す |
| 3帰還 | 踏破／撤退／緊急脱出の成果・喪失・着想を表示。本文を終えたら拠点へ。踏破後は再訪、未解決なら再挑戦を選べる |
| 再出発 | 拠点で取得・編成を確定して出発。同じFileGameSession・campaignを継続し、探索indexと乱数の続きはCoreが決める |

自分の「札組の残り」は公開された整理順であり、引く順ではない。敵の非公開札順・乱数・保存DTOは製品画面へ渡さない。

## 保存・終了・異常

通常保存は `user://saves/local/m1.json`。Godotのカスタムユーザー領域crossweaveを使う。標準設定ならWindowsは `%APPDATA%/crossweave/saves/local/m1.json`、Linuxは `$XDG_DATA_HOME/crossweave/saves/local/m1.json`（未設定時 `~/.local/share/` が基準）。`user://` を絶対OSパスへ変えるのはGodot側だけ。

- 操作の確定時に保存する。「中断して終了」やウィンドウの閉じる操作では、探索を撤退扱いにしない。再開時は同じrun・同じ乱数状態。
- 画面内の未確定編集がある場合は「編集を続ける／終了」を選ぶ。終了時の暗黙取得・支払いはない。以前明示保存されたdraftは残る。
- 保存中は二重の確定を受け付けず、描画を続ける。終了要求は保存が終わってからDisposeし、ロック解放後に終了する。
- **保存失敗**：操作と変更案を保持。「同じ操作を再試行」は同じRequestIdと内容。新しく購入し直す命令は発行しない。
- **成否不明**：古い表示に留まり通常操作を停止。「読み直す」で変更案の破棄を確認し、実保存を採用して「前の操作を照合」。確定済みなら再適用しない。
- **破損**：新規で上書きしない。正常なbackupがあれば、最後の一操作分が戻る可能性と原本保全を説明して「復旧する」。壊れた原本は `.damaged-<識別子>` に保全。
- **非対応版**：対応するアプリで開くよう説明し、復旧・新規作成で上書きしない。
- **二重起動**：先に開いた画面を閉じてから読込みを再試行。別保存先へ自動移動しない。
- 技術詳細は同じ場所の `m1.json.diagnostic.log`。ログ保存の失敗を本編保存の成功へ読み替えない。

## 自動確認と実機への引渡し

`python apps/crossweave-godot/UiProbe/verify.py` が、本編Main.tscn・実ノード・合成InputEvent・実FileGameSession・実ファイルを使う。検査先は `user://proofs/d04b-ui-save-01/<一意slot>/m1.json`。通常保存は使わない。入力fixtureは `apps/crossweave-godot/Tests/Fixtures/application-oracle.json.br`。有料取得や変換に必要な合法保存は、そのfixture専用ケースだけで作る。

Windows 11実機では後続担当が、開始→編成→探索→3帰還→再開、×／Alt+F4、連打、保持・スワイプ・右クリック・フォーカス切替を実マウスで確認する。100／125／150%倍率の日本語、詳細窓と内部スクロール、F11、GPU描画・音・60fps目標・応答100ms・メモリー目標は実測して記録する。今回のCIやheadless寸法をその合格値にしない。人の試遊は開始していない。

代表試作だけを開くには `python apps/crossweave-godot/UiProbe/launch.py --proof`。従来 `apps/crossweave-godot/packaging/Windows確認票.md` は基盤確認として別に維持する。
