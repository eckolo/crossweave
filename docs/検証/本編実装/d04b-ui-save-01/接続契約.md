# Godot・保存・後続への接続契約

パスはリポジトリルート相対。コード基点 `dad99fbc820cc4a49164faac3260c0a1d5d95d0b`。

## 所有者と確定境界

`apps/crossweave-godot/Godot/Main.tscn` → `apps/crossweave-godot/Godot/Application/AppEntry.cs` → `apps/crossweave-godot/Godot/Application/GameScreen.cs` が通常入口。GameScreenがアプリ起動中のFileGameSessionを一つだけ所有する。拠点・編成・探索・帰還は表示の再生成であり、sceneごとに本編を作り直さない。

`apps/crossweave-godot/Infrastructure/Application/FileGameSession.cs` のCreateNew／Open／Execute／Reload／RecoverBackup／Disposeを継承。保存形式v1・DTOv1・規則版・内容版、ファイル確定手順は02Aのまま。`docs/検証/本編実装/rd-save-02a/接続契約.md` が保存内部の契約。

| 境界 | 今回の接続 |
|---|---|
| 初期化／再開 | 絶対パスを渡す。初期保存または読込み成功後だけSessionとViewを採用 |
| 予測 | Inspectのrevision／view_tokenと未払いPlanをPreviewPreparation、合法choiceをPreviewActionへ。QuoteConversionも読み取りだけ |
| 確定 | 明示操作でGameCommandを一つ作る。FileGameSession.Executeが候補計算→実ファイル確定→Coreのメモリー交換を行う |
| 成功 | committed／replayedの返却View全体を採用。古い個体handle・選択・予測・画面案を新しい状態へ持ち越さない |
| 拒否 | rejectedは旧ViewとPlanを保持。CoreやファイルをUIから補正しない |
| 成否不明 | indeterminate／blockedはstale表示と操作停止。確定DTOを画面へ推測で戻さない |
| 再読込み | 利用者へ画面案を失う旨を確認してReload。実物のViewを採用してから、保存していた同じ要求を照合 |
| 再送 | LastCommandのRequestId・revision・token・type・payloadをそのまま使用。Coreは保存済み要求履歴を先に照合し、replayedなら二重適用しない |
| 終了 | 保存workerの結果を受けてからDispose。探索終了をwithdrawへ読み替えない |

ノードを触るのはGodotメインスレッド。同期ファイルAPIは一度に一つのTaskで実行し、`_Process` が結果を受け取る。Busy中は次の確定を作らない。画面のButton、Texture、Nodeをworkerへ渡さない。保存後の読戻しも02Aが担当する。

## 本編状態と画面状態

ViewはCore公開情報の独立コピー。Planは未払いの編集案。Screen、選択札・対象、詳細、スクロール位置、PointerGestureはUIだけの状態。通常の取得予定・ドラッグではsave_draftを呼ばない。既存の明示保存draftは読込み時に復元し、「戻す」の明示discard_draft以外で勝手に消さない。

所持集約は公開blueprint.keyに基づく表示上のまとめ。一度の操作で代表一個体の公開IDだけを使う。価格・消費枠・戦闘効果・支払い・変換可否をUIで再計算しない。Coreの心得詳細に追加したname／trigger_text／effect_textは表示情報であり、保存DTOの増設ではない。

返却された新しいViewをAdoptすると、古い予測・選択・Planは捨てる。再試行前のPlanは保持するが、読込み直した新tokenを古いhandleへ単独で付け直さない。結果表示・ウィンドウの再描画はExecuteを呼ばず、帰還を再精算しない。

## 保存領域と異常

| 用途 | Godotパス |
|---|---|
| 通常本編 | `user://saves/local/m1.json` |
| 今回の隔離検査 | `user://proofs/d04b-ui-save-01/<slot>/m1.json` |
| 過去の代表試作 | `user://proofs/rd-proof-02/<slot>/probe.json` |

検査モードは `--ui-check`、英数字・ハイフンの専用 `--ui-slot`、絶対 `--ui-output` の組合せが必須。通常起動ではUiAutomationを生成しない。故障点や合法DTOへのinternal接続は隔離検査だけ。UIの製品表示はExportDtoを使わない。

起動ではmissing、invalid_save／checksum_mismatch、unsupported_*、save_in_use、io_errorを分ける。新規作成は現保存・backup・作成途中ファイルがない場合のみ。backup復旧は明示確認し、巻戻しと原本保全を伝える。初回作成中断はArchiveIncompleteCreationで未確定ファイルを保全後、利用者が新規作成を選ぶ。
