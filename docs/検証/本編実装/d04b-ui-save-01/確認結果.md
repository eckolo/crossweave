## 入力・期待・実際

検査入口は `apps/crossweave-godot/UiProbe/verify.py`。実ノードへのviewport-local InputEventで操作し、各確定では実ファイルのDTOを読む。fixtureと故障注入は `apps/crossweave-godot/Godot/Application/UiAutomation.cs` に隔離する。

旧fixtureの160操作に加え、次プロセスの1行動と追加変換の1命令、計162命令で確定DTOを比較した。その他のUI編集・ロック・再訪等にも個別チェックがある。708／709というチェック数は、命令ごとの複数照合を含む数であり、独立したシナリオ数ではない。

命令比較では、UIが実際に作ったGameCommandを操作前DTOの独立メモリーCoreへ実行し、予想確定DTOと画面Session・実ファイルDTOを照合する。view_nonceだけを比較から除く。要求履歴・所持・編成・探索・乱数・領収は比較に残す。画面phaseも既存fixtureの期待遷移と比較する。旧Coreの演算・MT・旧期待結果への回帰は既存72試験を利用した。

## 実描画で見つけた点と修正

最初のWindows run `36657086190`（1ae0d563）で5描画ケースと10画像を取得できた。画像レビューで、(1)Noto Sans JPの縮小画像での細い文字の見え方（元フォントの可変軸既定は100）、(2)TextureRectのSize設定順による潜水服画像のはみ出しを発見した。

dad99fbcでFontVariationのwght=400を明示し、ExpandMode.IgnoreSize→Texture→Sizeの順へ修正した。フォント・画像の元バイト、固定rendererは変更していない。主体画像が親の幅・高さ・右端を越えないノード検査を追加。最終画像と確認票は `docs/検証/本編実装/d04b-ui-save-01/results/windows/rendered/` と `docs/検証/本編実装/d04b-ui-save-01/results/visual-review.json` に保存する。

Windows CIの実描画はCompatibility rendererがOpenGL3.3不足を検出してANGLE／Microsoft Basic Render Driverへ自動移行した。音声デバイスはWASAPI初期化に失敗しdummyへフォールバックしており、音の確認成功にはしていない。論理viewport1920×1080、runnerの実window報告1028×720、比率維持したviewportの取得画像は1028×578。実FHDモニターやDPIの確認ではない。

Linuxではユーザー領域のXvfb起動も試みたが、表示用socketを開けず、実描画はできなかった。許可の拡張や別ブラウザーへの置換はしていない。Windowsの実描画画像を配置確認の根拠とし、Linux headlessの寸法だけで実表示合格にしない。
