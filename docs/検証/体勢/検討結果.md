## 条件と再現

[入力.json](入力.json)に基点・参照エンジンSHA-256・対象最大値1/20/100/150/250・14種類の削り量と維持条件を実行前に固定した。[比較.cjs](比較.cjs)は、基準`engine.js`を読み取り、独立したメモリ上で閾値・超過倍率・予測・状態検査だけを変更する。変更する元文字列の出現数が違えば停止する。元のエンジン・配布HTMLを編集しない。

```sh
node docs/検証/体勢/比較.cjs
```

[結果.json](結果.json)に、元と候補のハッシュ、差分、入力と比較コードのハッシュ、全結果を保存。人工状態には3主体と実在する札・場・回収山を用意し、実エンジンの`play`・`predict`・保存復元と状態検査を実行した。HPを十分高く固定して、環境踏破等の後続イベントをこの局所比較へ混ぜない。

## 得られた結果

- 閾値・超過の70局面で、到達するまでHP減少0、到達で1倍・超過100ごとに＋1倍、到達後の累積リセットを確認。
- 現行との14比較で、最大体勢100なら到達条件と蓄積リセットは一致。攻撃−防御10の命中では、旧処理よりHPダメージが10少ない。累積100の場合は旧20に対して新10。
- 連続攻撃5例で、削り50・攻撃−防御10を4回使うと、道M1は10/10/10/10、霧M100は0/10/0/10、旧試作は0/20/0/20。どの手にHPが進むかを分けられる。
- 会心保持、0ダメージ防御と回数消費、回避で削り0、不一致設置、複数攻撃者の共有蓄積、最大値150の保存再開、最大値0の除外、高最大値の未到達時判定の8境界を確認。
- すべての実行した攻撃で、予測の到達・正味加算・HP減少が実行結果と一致した。

## 適用範囲

現行実装との整合性を点検した人工局面の結果。候補を共通エンジンへ採用済みとはしない。AH/AI/AJの通し結果、実描画、対戦・探索バランス、反復テンポ、楽しさを再評価した結果ではない。道の体力をどれだけ増やすか・各札の調整・旧セーブの製品移行方式は別に残る。
