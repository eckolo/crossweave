# crossweave UI 正式参照版

登録版：1.0／2026-09-12（日本時間）。状態：**現行UIの正式版として登録済み**。担当：UI Work `20260910-ui-readability`／`ui/readability-20260910`。

ユーザーの「他にも細かい改善はあった方がよさそうだがいったん現状で概ねの方向性は良さそう。現行を正式版としていったん登録し、他WorkでUIに関係する検討が発生した際には参照するようにして」という判断に基づく。現在の探索画面を今後の検討の基準として採用する。細部の改善は継続でき、過去資料の「未採用の操作試作」という一括表記は、この判断で更新する。

## 今後の基準にする内容

| 項目 | 基準 |
|---|---|
| 画面構成 | 場を挟み、相手を奥・手札を手前に置く。横長を基本にUI全体を中央へ収め、下帯は細く保つ。16:9を実装上の基準とし、狭い表示では可読性のため高さを確保する |
| 件数と表示範囲 | 場は可変枠で、2×2・4枠固定ではない。全件を一度に詰め込まず、必要な領域で送り・スクロール・詳細窓を使い、範囲外の存在を案内する |
| 情報量 | 常時表示は現在の判断に必要な情報へ絞る。山札・状況・突破条件・履歴・設定は下帯から必要時に開く。見出しとボタンは短く、同じ数値や説明を重ねない |
| 出札 | タップ／クリックで札を選び詳細を開く。短いホールドでつかみ、それより前の移動は横送り。同じ出札はドラッグと選択札直下の実行ボタンの両方で行える |
| 窓 | 同じ対象の再クリックと窓外クリックで閉じる。情報量と対象に応じた大きさ・位置とし、場札の窓で場の操作を塞がない。マウスでは一時表示とクリックでのピン止めを使い、状態は記号で示す |
| 予測 | 手札→一致する場札→作用先の関係を盤面側へ薄く描く。実行ボタンのホバーでは手札詳細を閉じ、ボタン直上へ予測札を表示する。設置予測では場からの一致補正を示す |
| 行動順 | 公開中の全行動主体の次回をアイコン列にし、押した主体を基準とする前後・時差を表示する。攻撃対象の選択とは分ける |
| 履歴 | 一行の短文を新しい順に残す。発生時は右下帯の直上へ上積みし、古い行から薄く消して下へ詰める。持ち込み・補給や重複要約は表示しない |
| 場札 | 通常は突破・探査。身構札の一致予測中は該当する場札だけ身構・攪乱。縮小欄内にスクロールを作らず、全文は詳細で読める |
| 絵と背景 | 背景を画面全域へ連続させ、ベースと環境由来の表現を分ける。相手・場・手札は絵を持つ前提。素材や演出は情報の識別と反復操作を支える |
| 用語 | 世界観Workの正式用語を継続して照合する。主体別の残量名と行動名は独立。名称変更時は意味・公開範囲・表示幅を確認する |

220msのホールド、窓の幅・透過率、履歴の件数・間隔・フェード時間、余白などは現在版の再現値として保存する。変更禁止の最終値にはしない。仮のアイコン・背景表現・配色を最終の画風や素材として採用したものではない。

## 他WorkがUIに関係する検討を行うとき

関連作業の開始時と成果反映前に、集約側のWork分担から本書の最新版を確認する。正式参照版と確認コミットを自Workの記録へ残し、UIに関わる変更案には**現行との差分・表示する情報・公開時点・操作や画面への影響**を添える。基準と整合する細部の具体化は進めてよい。方向を変更する場合は変更提案として扱い、採用済みの同じ判断を再質問しない。

| 担当 | UIとの接続で確認すること |
|---|---|
| 設計 | 新しい規則・主体・公開情報・数量・準備や取得操作が、いつ何を見せる必要を生むか。ゲーム条件を指定してUIへ渡す |
| シナリオ・探索内容 | 常時必要な情報、発生時の短文、任意の詳細を分ける。対象ごとの残量名・行動名、除去や残置で変わる結果を示す |
| ビジュアル・演出 | 背景・相手・場・手札・予測線・窓の重なり、輪郭と選択状態、反復時の演出時間を現行画面と照合する |
| 世界観 | 正式用語・主体表示名・道具表現の変更と対象IDを示す。UI側は対応表と表示幅への影響を記録する |
| 試遊 | 登録画面と同じ条件か、新しい比較条件かを明示する。使用版と操作・所感を残し、旧試遊と混同しない |

UIの配置・操作・専用実装はUI Work、共通仕様・エンジンと成果統合は設計Work、各Workの原記録は各担当を維持する。必須マージを増やさず、UIは参考先として取得する。停止中のWorkへの自動通知・自動起動を前提にせず、共通索引と記録から次の作業時に取得する。

## 確認済み範囲と継続改善

ユーザーから現行の概ねの方向性を了承・正式登録する判断を受領した。前回の検査はDOM・仮時計・与えた矩形による90項目、固定3構成74行動の状態・乱数・既知情報の一致。今回の登録では画面コード・固定入力・組立画面を変更していない。

実ブラウザーの各表示幅での重なり、実端末での操作経路、長い正式名称や履歴の読み取り、最終素材での視認性は継続確認する。既存F01〜F03の原記録や未取得の操作を補完しない。

後継版を正式登録するときは本書の版・対象コード・採用差分を更新する。検討中のUIを作っただけでこの参照先を差し替えず、過去の正式版は固定コミットから取得できるようにする。中心の確定仕様への採用要約とコード統合は、対象コミット付きで設計Workへ依頼する。
