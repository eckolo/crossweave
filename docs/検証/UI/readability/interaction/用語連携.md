## 仮設定・保留

- 残量名は用語集1.1の主体別設定に追随。耐久・道のりの上記割当は既存試遊のUI仮設定であり、正式な相手コンテンツ採用ではない。相手の絵、ゲージのアクセシブル名、詳細、予測、突破条件に同じ残量名を使う。
- 大岩の実行動詞「壊す」、環境「進む」、敵「攻撃」はUIの記録付き仮設定。相手の追加・採用や動作変更を意味しない。
- 属性A〜Dは維持。用語集4章の「試作用の割当は未確定」と、A01〜A04の対応行の整合は世界観／設計側へ確認を依頼する。UIで割当を確定しない。
- 「予測」「獲得物」「あとN行動」「再突入」は受領済みの短いUI表記を優先する。長い旧称や削除済みメニューを復活させない。
- 現在の縮小欄は属性＋札名、2数量、必要時の消滅条件の最大3行。長い名称は札名だけ省略し、詳細で全文を読める。実ブラウザーでの文字幅・重なりは未確認。

## 作業時の追随手順

作業開始時と成果反映前に、自Work・必須同期元の確認と実取込を行う。その際に世界観の参考refも取得する。

```sh
git fetch origin +refs/heads/design/worldbuilding-20260910:refs/remotes/origin/design/worldbuilding-20260910
node docs/検証/UI/readability/interaction/check-terms.cjs
```

確認ツールは取得済みrefを読み、本文の変更有無と用語ID別の追加・変更・削除を返す。本文が変わったときは終了コード2として要確認を示す。変更があれば、正式採用区分・意味・世界観設定と明示された後継を読んでから対応表を更新する。単純な一括文字置換は行わない。用語以外の世界観設定変更も、開始時・反映前のHEAD差分から確認する。

名称変更時は手札・場・山札・予測・履歴・状態・アクセシブル名を確認する。数量の意味が変わる場合は固定比較の表示変換として成立するか確認し、ゲーム変更が必要なものは保留して設計側へ渡す。対応表の出典・版・SHA・ID行、使用版とWork記録を更新し、対象コミット付きで統合依頼へ記載する。

これは本Workが作業する時の照合手順であり、待機中の自動監視や他Workへの自動送信は設定していない。
