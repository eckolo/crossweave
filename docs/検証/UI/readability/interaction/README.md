# UI-R-002：繰り返し札を出す操作とBC1の探索画面

2026-09-10、使用版0.2。UI Work `20260910-ui-readability`。未採用の操作試作。固定PT-Z-001と同じゲームコード・入力に、配置と操作だけを接続した。

最新版では、ユーザーの「札上の二つのボタンで挙動が異なると分かりづらい」という指摘を受け、追加ボタンを撤去した。札全体から、横移動＝閲覧、上移動＝ドラッグ、タップ＝選択を使う。旧v0.1の画面・条件はコミット`d5d5672027e508bae2fa39ac0e06517ff04b867c`の同じディレクトリに保持する。UI-R-001とPT-Z-001は更新しない。

ユーザーはUI-L-004の方向を「わかりやすくて良い」と評価し、具体化を依頼。頻繁に繰り返す「札を場に置く」操作を重視し、ドラッグ・札ごとのボタン・選択後の共通ボタン等を比較すること、複数方式の併用と設定による調整も許容することを明示した。以下はその具体案であり、各既定値の正式採用・操作速度の実証ではない。

## 最初に操作する

組立済みの[preview.html](preview.html)を取得してブラウザーで開く。GitHubのコード表示では操作できない。Node.jsがあればリポジトリルートで再生成できる。

```sh
node docs/検証/UI/readability/interaction/build.cjs crossweave-card-gestures.html --standalone
```

入口は固定PT-Z-001と同じW seed32、攻撃6・防御5・回復1、HP60、初期12枚、手札3枚。画面上の「参照」から山札、状態、成果、履歴、撤退、入口からの再開始を開く。新しいゲーム条件や山札順の開示を加えない。

標準の仮設定：

- 札の本文をクリック／タップ：選択と予測。下部の共通ボタンで実行できる。
- 札全体から左右へ動かす：手札を横スクロール。横移動に決まった入力は、途中で上へ動いても札を出さない。
- 札全体から上へ動かす：札を持ち上げて場へドラッグ。マウス・タッチ・ペンで同じ方向の区別を用いる。長押しの待機は不要。
- 場へドロップ：通常の設置は実行。一致または他の手札の消滅が伴う設置は予測へ進み、下部で実行する。
- 場の外で離す／Esc／入力中断：未実行のドラッグを取り消す。ドラッグ前の選択へ戻す。
- 操作設定で「通常の設置はすぐ出す」をオフにすると全件確認式。「ドラッグを使う」をオフにしても横スクロールと共通の選択→実行は残す。設定は画面を開いている間保持する。

「確認」は追加の毎回ダイアログではなく、同じ画面の予測と固定ボタンを使う。攻撃対象は初回に本人が選択し、生存している間は保持する。対象が退場しても別の相手を自動選択しない。行動後は次の札を自動選択せず、共通ボタンを未選択状態へ戻す。

## 操作方式の比較

下表の回数は入力手順の数であり、速さの実測ではない。札や場の確認、対象選択、画面内の移動は別に数える。

| 候補 | 通常設置まで | 反復時の利点 | 負担・対応 | 今回の扱い |
|---|---|---|---|---|
| 札全体から上方向へドラッグ | 1ジェスチャー | 手札→場の関係を直接表せる。専用ボタンや長押しが不要 | 最初に上へ動かす必要がある。斜め入力と端末差の確認が残る | v0.2で実装 |
| 各札の「置く」ボタン | 1クリック／タップ | 短い移動で繰り返せる | 札上の選択・つかむ・実行の区別が増えるとの指摘 | v0.2で撤去。旧v0.1で比較可能 |
| 札を選び共通ボタンで出す | 通常2クリック／タップ | 予測・コスト・損失を確認しやすい。キーボードの通常操作でも使える | 各手で選択と実行の間を移動する。既に選択済みなら実行だけでよい | 全設定で残す |
| 札の本文を一押しで即実行 | 1クリック／タップ | ボタンを追加せず最短にできる | 調べる／選ぶ／スクロールと誤認しやすい | 今回の既定にはしない |
| ダブルクリック／ダブルタップ | 2クリック／タップ | 札の上で完結する | 二度の入力、速度判定、単クリックとの区別、札補充後への入力の持越し | 未実装。追加の比較候補 |
| 長押しからドラッグ | 待機＋1ジェスチャー | 持ち上げた後の初動方向を問わない | 毎手の待ち時間、長押しの発見、スクロールとの判定 | 反復操作では方向判別案を先に試す。未実装 |
| 番号キー＋実行キー等 | 選択＋実行 | マウス移動を減らせる | 配置変化、他操作との競合、端末差 | 未実装。まず標準のTab／Enter／Spaceを利用 |

現在の第一案は「札全体の方向判別＋タップ選択・共通実行」。設定操作をプレイ開始の条件にしない。速度の優劣は未実測であり、移動距離・押し間違い・確認のしやすさ・数十手繰り返した疲れで比較する。

### 方向判別の仮設定と中断

- 横10 CSS px以上かつ横成分が縦の1.5倍以上なら、指を離すまで横スクロールに固定する。閲覧中は選択・予測・ゲーム状態を変更しない。マウス／ペンは手札のスクロール量を直接更新する。
- 上14 CSS px以上かつ上成分が横の1.5倍以上なら持ち上げる。開始後は自由に動かせる。札の表示を薄くし、札名が指について移動し、場の受入領域を強調する。場で離した時だけ既存の設置／一致確認処理へ進む。
- 方向が曖昧なまま32 CSS px以上動いた場合、または下へ動き始めた場合は、その入力での出札を取り消す。小さな揺れは選択タップとして扱う。これらの閾値は比較用仮値で、製品仕様ではない。
- ブラウザーが横スクロールやピンチ操作を引き受けた場合の`pointercancel`、捕捉喪失、複数指、Esc、画面の非アクティブ化は出札しない。ドラッグ開始済みなら元の選択へ戻す。
- 操作直後の合成クリックを抑え、スクロール終了で札を選んだり、ドロップ後に別札や共通実行を押した扱いにしない。次の新しい押下では抑制を解除する。キーボードの選択・実行を残す。

タッチの横移動はブラウザー標準へ任せ、札に事前に`touch-action: pan-x pinch-zoom`を指定する。ドラッグ中に指定を書き換える方式は使わない。根拠：[MDN touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action)。札上での上下移動はドラッグ判別に使うため、画面全体の縦スクロールは札の外から行う。ドラッグをオフにすると札からも上下スクロールできる。スクロール開始角度のブラウザー差・ピンチ・縦スクロールの操作感は実機未確認。

## 設置と一致を混同させない

基本設計4.1・4.2と固定コードでは、同じ属性の場札があれば一致が必須。空いている別枠へ置いて一致を回避する操作はない。この固定試験での行先は札の属性から決まり、プレイヤーに枠を狙い分ける入力を要求しない。場領域へのドロップを同じ正規入力へ変換する。

将来、複数の合法な設置先／一致先を選ぶルールが採用された場合は、合法先を提示する選択を追加する。今回、属性数と枠上限を同一視する製品ルールや、自由な枠選択を追加しない。可変数の一般配置はUI-L-004を継続参照する。

反復設置の短縮と結果の把握を両立するため、以下を仮設定とする。

- 札には「設置／一致」とコストを示す。ドラッグ中は離した後が実行か予測かを表示し、共通実行ボタンも設置／攻撃等に合わせた文言を使う。
- 一致は、攻撃・防御・回復等の結果と損失を確認して実行。攻撃対象未選択なら実行不可。
- 他の手札が期限切れで消滅する設置は確認へ進む。通常の期限切れによる回収は、期限表示と要約を残し、追加の確認操作を必須にしない。
- 実行後の巻戻しは新設しない。相手の行動・補充・公開情報の変化まで巻き戻す新しいゲーム条件になるため、固定比較に混ぜない。取消は実行前に行う。

確認を挟む条件が多すぎて反復を妨げる場合は、試遊で頻度と理由を確認する。今回の条件はユーザーの正式な仕様判断ではない。

## 画面と参照範囲

相手・環境を上、共有の場を中央、自分・手札を下に置く。札数や予測文で画面全体を押し下げず、対象・場・手札の領域内で横移動できる。送りボタンと表示範囲はあふれた領域だけに出す。選択に連動した同属性枠への移動は、その場の領域だけを動かす。

各行動後に札の選択を解除する一方、対象と各領域の閲覧位置は可能な範囲で保つ。場の変化には印を残し、結果の要点と詳細への入口を常時置く。山札・行動履歴・状態内訳・全文の効果と計算は参照窓へ分ける。初版の固定表示高は比較用仮設定であり、製品の画面比・最小解像度の決定ではない。

選択対象の固定表示、画面外の複数変化への直接移動、全体一覧、ドラッグ中の端での自動送りは未実装。固定試験では場全体へ落とせるため、目的枠が画面外でも精密なドロップや自動送りを要求しない。情報量増加時の全UIの候補比較は[UI-L-004](../layouts/bc1-scroll/README.md)を継承する。

UI側の確認：既存3構成・74手で、同じ選択列による状態・乱数・知識がUI-R-001と一致。3入力種別のドラッグ／確認後の設置、横から上へ曲げる入力、曖昧な斜め移動、下移動、複数指、中断、微小移動のタップ、合成クリックと次のタップ、旧入力の拒否をDOMで確認した。札は選択面一つで追加ボタンがないことも確認。詳細は`verification.json`。検証用フックはメモリ内にのみ注入し、配布画面に含めない。

未確認：実ブラウザーでの描画・ポインター捕捉、実端末のタッチと横スクロールの競合、実際の反復時間・誤操作・疲れ。既知のプレビューURL制限があるため、この記録を実機確認済みとはしない。

試遊担当向けの観測点：通常設置の入力数と手の移動、意図しない実行、取消の成否、スクロールをドラッグと誤認する頻度、一致の確認を忘れないか、補充後の札を見失わないか、予測・詳細を開く回数、設定を変えた理由。既に受領した見やすさやBC1への所感は再質問しない。
