## 最初に操作する

組立済みの[preview.html](preview.html)を取得してブラウザーで開く。GitHubのコード表示では操作できない。Node.jsがあればリポジトリルートで再生成できる。

```sh
node docs/検証/UI/readability/interaction/build.cjs crossweave-actor-order.html --standalone
```

入口は固定PT-Z-001と同じW seed32、攻撃6・防御5・回復1、HP60、初期12枚、手札3枚。下帯の「山札」から絵と残数の一覧、「状況」から状態をそれぞれ直接開く。撤退は下帯から直接押す。持ち込み・開始時の補給は履歴へ表示しない。獲得物の持ち帰り／喪失は終了後の「帰還」で確認する。プレイ中に初期状態へ戻す操作は設けず、撤退→再突入とする。履歴は独立した「履歴」から全文を確認できる。新しいゲーム条件や山札順の開示を加えない。

標準の仮設定：

- 札をクリック／タップ：選択と同時に全文・予測の窓を開く。同じ札をもう一度押すと閉じ、再び押すと開く。閉じても選択は保持し、札直下の実行ボタンを使える。実行ボタンのマウスオーバーでも詳細は閉じ、札をボタン直上に表示する。マウスを離しても詳細は自動で開き直さない。「別の札を選んだときも詳細を開く」をオフにすると、別札は選択だけになり、同じ札を再クリックすると詳細を開く。
- 札を少し押し続ける：仮に0.22秒で札が浮き、場へ運べる。つかんだ後の移動方向は自由。マウス・タッチ・ペンで共通。
- つかむ前に動かす：手札を横スクロール。斜めでも縦でもドラッグにはしない。途中で止まっても、その指を離すまでは閲覧を継続する。
- 場へドロップ：通常の設置は実行。一致または他の手札の消滅が伴う設置は詳細窓の予測へ進み、札の直下で実行する。
- 場の外で離す／Esc／入力中断：未実行のドラッグだけを取り消す。つかんだ札の選択を残し、以前の札へ戻さない。つかむ前のスクロールでは選択を変更しない。
- 操作設定でホールド時間を0.15／0.22／0.32秒から調整できる。「通常の設置はすぐ出す」をオフにすると全件確認式。「ドラッグを使う」をオフにしても横スクロールと共通の選択→実行は残す。設定は画面を開いている間保持する。

設置・一致の確認は同じ画面の予測と共通ボタンを使う。タップで開いた詳細は、そのまま実行するか、窓外クリックで閉じられる。攻撃対象は元の固定試遊と同じく最初の環境V0を初期選択し、生存している間は指定を保持する。退場時は元版の表示順で最初の有効対象へ切り替える。常設対象がなくなる初期・退場時の追加操作を撤去した。行動後は次の札を自動選択せず、窓を閉じ、共通ボタンを隠す。

## 窓と予測の比較ポイント

- 場札・相手・突破条件・行動順は最大幅420px、その他の情報窓は560pxを上限に、必要な高さだけを使う。場札の窓は場の列の上に収まれば上へ、下に収まる場合は下へ置く。両側とも不足するときだけ広い側を使い、窓内をスクロールする。相手の窓は相手の列の下を優先。列を覆って同じ札・相手へ再クリックできなくなる配置を避ける。
- メニューの窓は下帯の上、行動順は小さな予定列の下へ置く。窓背景のみ約88%（明）／90%（暗）の不透明度にし、2pxのぼかしを加える仮案。文字・ボタンの不透明度は落とさない。半透明の影と背景の暗転も弱める。読みやすさと背後の文字の干渉は実画面で未確認。
- 手札の詳細窓は幅最大840px、上端16pxから手札直前までを使う。狭い画面では内容を1列へ。相手の絵を覆う分、攻撃時の対象切替を窓内にも置く。手札は残すため、同じ札の再クリックや別札への切替ができる。短い窓へ全文を押し込んだ旧版はv0.8に保全。
- 選択した手札の実際の位置から場の該当枠へ線を引く。一致攻撃は場札から現在の対象へ、防御・回復・主効果なしの一致は自分の状態表示へ続ける。設置は空き枠で止め、対象へ効果が出る線を描かない。窓内は今回の結果と性能表に分け、攻撃時だけ折り畳みの計算根拠を置く。設置時の補正値を予測・要約・性能へ重ねて書かない。
- 線は絵と状態表示より上、詳細窓とドラッグ札より下。窓と重なる部分は薄い透過面とぼかしに覆われ、線の読み取りは制限される。窓を閉じても選択は残るため、盤面全体でつながりを確認できる。線はポインター操作を妨げない。太さ2px・線の不透明度46%・囲み30%は仮値。設定から表示を切り替えられる。
- 手札・場・相手・自分の帯のスクロールと画面幅の変更に合わせ、表示中のオブジェクトの矩形から引き直す。完全に画面外の端点へ向かう区間は省き、別札へ誤接続しない。画面外を指す専用矢印は未実装。既存の送り操作・表示範囲案内を使う。
- 場札は主効果・場の補正・コスト・期限・消滅条件を性能表で確認できる。期限の共通ルールは設定へまとめる。場の札を手札扱いで選択・出札しない。相手はHP・蓄積・防御・回避・軽減・次回予定、従来の詳細情報にある行動傾向と確認済み札種だけを示す。非公開の手札・山札や未登場の相手は追加しない。
- 手札／場札／相手の詳細は、見えている別オブジェクトを押すと直接切替、同じものなら閉じる。手札窓内の対象ボタンは対象の切替だけを行う。場札・相手の窓の外にある実行ボタンは閉じる操作として扱い、そのクリックでは出札しない。
- マウスではメニュー上で180ms待つと一時表示。メニューから窓へ移動しても維持し、両方から離れて160msで閉じる。クリックで固定し、同じメニューの再クリック・外側・Escで閉じる。別メニューは1回のクリックで切替。固定中はホバーで内容を上書きしない。タッチ／キーボードはクリック・タップで開閉する。仮の遅延値は実機の経路と併せて評価する。
- ホバーだけではゲーム状態・選択・フォーカスを変更しない。窓内を明示的にクリックした場合も固定へ移り、その操作を処理する。固定窓を外側から閉じる操作は背後へ出札しない。一時表示中の背景操作は閲覧窓を閉じ、その通常操作へ進む。
- 札を手動で未選択へ戻すゲーム操作はない。開始時・使用直後・手札から選択札が消えた時には未選択を残し、補充された札への連続実行を防ぐ。窓を閉じることと札の選択を解除することを分ける。専用の選択解除・詳細ボタンは不要になった。
- 「手」は自分の行動回数と読み取りにくいとの指摘を受領。「あと○行動／今回まで」に暫定変更し、札の詳細には自分の行動終了ごとに1減ること、相手行動では減らないことを明記。世界観の正式用語決定には広げない。

## 常設情報と行動順の読み方

上部の小さな列は、現在参加している行動主体の次の1回ずつを予定時刻順に並べる。あなたも含む。仮絵は自分＝足跡、環境＝木々、敵＝虫の既存アイコンで、相手と共通の絵を使う。`+N`は現在時刻からの待ち時間。アイコンを押すと、その主体の次回を0とした「前／基準／後」と時差の表を開く。別のアイコンは基準の切替、同じアイコンの再クリックは閉じる操作。窓は押したアイコンの下に置き、窓外でも閉じる。攻撃対象は変更しない。あふれる場合だけ送りボタンを出す。

固定エンジンの順序は `next_at` 昇順、同時刻は環境V → 自分P → 敵E、さらに同役割はID順。行動しない大岩や未登場の相手は列へ入れない。退場・登場と行動後の予定を更新し、探索終了時には列を外す。札の選択だけでは予定を変えず、未選択の将来の札・非公開の行動を仮定した複数周分の予測は加えない。札を使うコストと個別結果は従来の予測窓から読める。

「突破条件」は現在の対象のみ表示する。固定入口では大岩の破壊と最初の環境の踏破を別々に示す。前者はRを得て未保護のまま移行、後者はT0を得て取得済み獲得物を全て保護して移行する。後続区間に入って初めて、その区間の環境を示し、敵の撃破は必須ではないことを説明する。これはPT-Z-001固定の`replace_environment`条件であり、設計最新版の突破・成長ルールの採用ではない。

操作の説明、場と対象の役割は「設定」からいつでも確認できる。未選択時の操作文、空き枠ごとの誘導、絵の仮置き説明は常設しない。選択中の期限切れ・消滅・対象未指定など判断に必要な注意は残す。正式な初回チュートリアルは未実装で、案内窓の内容を今後の教材へ移す候補とする。

### ホールドの仮設定と中断

- 押下時に既定220msのタイマーを開始する。8 CSS px未満の揺れは許容し、短く離せばタップ選択。8px以上動いた時点でホールドを取り消し、離すまで横スクロールに固定する。角度・方向比では分岐しない。スクロールは移動の横成分を用いる。
- 時間が経過したら、元の札を薄くし、属性・札名・効果を持つ札を指の上に浮かせる。場を強調し「つかみました」と結果の案内を出す。ここではゲームは進まない。持ち上げ後は任意方向へ運べる。
- つかんでから場へ運び離した時だけ既存の設置／一致確認へ進む。手札上で離すだけでは実行しない。手札の閲覧中に止まる、斜めから縦へ曲げるといった入力でも、途中からホールドへ移らない。
- `pointercancel`、捕捉喪失、複数指、Esc、非アクティブ化・非表示化で取消。ホイール、待機中のスクロール位置変化、設定変更、参照を開く、再開始、ゲーム版の変更でも保留タイマーを無効化する。ホールド開始後ならつかんだ札の選択を維持し、以前の札へ戻さない。再開始・札の消失などゲーム状態が変わる場合はその状態を優先する。
- 操作直後の合成クリックを抑え、スクロール終了で札を選んだり、ドロップ後に別札や共通実行を押した扱いにしない。次の新しい押下では抑制を解除する。キーボードの選択・実行を残す。

掴んだ表示は幅180px、実際の表示高を測って、通常はポインターが下端から6px内側に入る位置へ置く。固定の100px上方オフセットを廃止し、画面端では枠内に収めたうえで接触を保つ。マウス・タッチ・ペンで同じ仮配置。

ホールド後に横向きへ運ぶことも保証するため、ドラッグ有効時の札には事前に`touch-action: pinch-zoom`を指定し、単指の横スクロール量をUI側で更新する。ジェスチャー途中で`touch-action`を変えても効かない制約を考慮した実装。根拠：[MDN touch-action](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/touch-action)。ピンチを禁止せず、画面全体の縦スクロールは札の外から行う。ドラッグ無効時のタッチは標準の上下・左右スクロールへ戻す。ホイール・トラックパッドは標準のスクロールを利用する。今回の単指スクロールは追従のみで独自の慣性送りは未実装。実機でのホールド境界、スクロール感、ピンチは未確認。

## 設置と一致を混同させない

基本設計4.1・4.2と固定コードでは、同じ属性の場札があれば一致が必須。空いている別枠へ置いて一致を回避する操作はない。この固定試験での行先は札の属性から決まり、プレイヤーに枠を狙い分ける入力を要求しない。場領域へのドロップを同じ正規入力へ変換する。

将来、複数の合法な設置先／一致先を選ぶルールが採用された場合は、合法先を提示する選択を追加する。今回、属性数と枠上限を同一視する製品ルールや、自由な枠選択を追加しない。可変数の一般配置はUI-L-004を継続参照する。

反復設置の短縮と結果の把握を両立するため、以下を仮設定とする。

- 札には「設置／一致」とコストを示す。ドラッグ中は離した後が実行か予測かを表示し、共通実行ボタンも設置／攻撃等に合わせた文言を使う。
- 一致は、攻撃・防御・回復等の結果と損失を確認して実行。対象は常設指定を使い、任意に切り替えられる。有効対象が存在しない異常状態では実行を抑止する。
- 他の手札が期限切れで消滅する設置は確認へ進む。通常の期限切れによる回収は、期限表示と要約を残し、追加の確認操作を必須にしない。
- 実行後の巻戻しは新設しない。相手の行動・補充・公開情報の変化まで巻き戻す新しいゲーム条件になるため、固定比較に混ぜない。取消は実行前に行う。

確認を挟む条件が多すぎて反復を妨げる場合は、試遊で頻度と理由を確認する。今回の条件はユーザーの正式な仕様判断ではない。

## 画面と参照範囲

相手・環境を上、共有の場を中央、自分・手札を下に置く。札数や予測文で画面全体を押し下げず、対象・場・手札の領域内で横移動できる。送りボタンと表示範囲はあふれた領域だけに出す。選択に連動した同属性枠への移動は、その場の領域だけを動かす。

各行動後に札の選択を解除する一方、対象と各領域の閲覧位置は可能な範囲で保つ。場の変化には印を残す。新しい出来事は一時的に画面へ出し、全文の履歴と山札・状態内訳・効果の計算はそれぞれの窓へ分ける。この版は横長16:9を基準とし、幅1,024pxなら高さ576pxが目安。相手・場・手札の可変部分を1.2：0.9：1.2で配分する。文字と操作の寸法を保つため、通常の最小高は504px（幅600px以下512px）、タッチ向け546px（同554px）。この下限に達した幅では16:9より縦が長くなる。画面全体の縦スクロールと各領域の送りを利用し、情報を無理に縮小しない。下帯は通常32px、幅600px以下40px、タッチ向け48px／600px以下56pxの1段。狭い帯は折り返さず内部で横に送る。手札の直下に40px／タッチ44pxの局所操作だけを確保する。16:9は製品を見据えた今回の基準で、対応解像度や狭い端末での最終構成は未確定。

選択対象の固定表示、画面外の複数変化への直接移動、全体一覧、ドラッグ中の端での自動送りは未実装。固定試験では場全体へ落とせるため、目的枠が画面外でも精密なドロップや自動送りを要求しない。情報量増加時の全UIの候補比較は[UI-L-004](../layouts/bc1-scroll/README.md)を継承する。
