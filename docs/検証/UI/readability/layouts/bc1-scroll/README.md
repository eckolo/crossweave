# UI-L-004：画面枠を保ち、情報量に応じて参照範囲を変える

2026-09-10。使用版0.1。BC1を引き継ぐ配置の検討用。ゲーム未接続。

## 受領内容と前提の修正

ユーザーは、枠数の増加で画面全体の縦横比が変わる案の実装負担を指摘し、すべてを一度に収める必要はないこと、スクロール等を許容し、その場合は誘導が必要なことを補足した。続けて「場を横にスクロールできる、というのはあくまで一例」「他のUIに関しても表示がせせこましくなったりするなら一案として同様に検討」と明示した。

したがって、従来の「すべての場の枠を同時表示するために縦へ拡張」「横スクロールを既定にしない」というUI側の仮方針を修正する。すべてのUIについて、読み取れる大きさ、重要情報の把握、操作の安定性を優先し、スクロール・一覧への切替・要約と詳細の分離を比較する。全領域の横スクロールを採用したという意味ではない。

端末・ウィンドウの寸法への対応と、ゲーム内の情報増加への対応を分ける。前者で画面枠と配置を決め、後者は原則その領域の内部で扱う。ウィンドウをリサイズした場合には再配置してよいが、札が増えただけで手札・実行位置・画面全体を押し下げない。特定の16:9等の比率や製品の最小解像度は未決定。

## 各UIの再検討

[既存の全UI表示時機表](../bc/検討.md#表示時機の基準)を、情報量が多い場合の扱いまで拡張する。「常時表示」は領域と重要な要約を指し、全項目を同時に表示する義務とはしない。

| UI・対象情報 | 多い／長い場合の候補 | 画面に残す情報・見失わせない処理 |
|---|---|---|
| 場所・区間・情景 | 名称は短縮表示＋詳細、情景は領域に合わせる | 現在地と区間移行。長い地名で他の領域を押し出さない |
| 相手・環境などの主体／対象 | 横送り、一覧への切替、対象選択時の一覧拡大を比較 | 主体数・選択対象・直近に動く主体。画面外の参入／離脱／重要変化の印。図の横送りは候補の一つ |
| 各主体のHP・命中／会心蓄積・防御・有効回数 | 対象欄内の短い状態表示＋主体詳細 | 自分と選択対象の重要状態を保持。他の主体を画面外に置く場合も緊急変化を通知する |
| 回避／軽減の内訳・存在効果・支援・相手の性格／観測札 | 有効状態の要約＋主体詳細内の縦スクロール | 作用中の効果と終了。影響先を選択時に示す。未知情報を追加しない |
| 公開行動順・絶対時刻・手数 | 直近の順序を残し、全予定は展開一覧・縦送り | 次に動く主体。開くだけでゲーム時間を進めない |
| 共有の場の枠・属性・空き・札・主要効果 | 横送り、一覧拡大、ページ切替を比較。折り返しも画面内で成立する場合の候補 | 総枠数・表示位置・選択枠。一致する枠が画面外にある場合の誘導。消滅予定や変化の通知 |
| 手札の名前・属性・主効果・期限 | 横送り、一覧拡大を比較 | 枚数・選択札・期限切れが迫る札の要約。札を探して往復し続けるなら一覧を優先 |
| 手札の場効果・会心増加・行動コスト・由来・初期持込との差 | 選択札の詳細／必要時の参照内で縦送り | 今の行動コストと損失予測。未選択の札も参照可能とする |
| 一手の予測・詳細計算・ルール全文 | 予測の要点を固定位置、計算内訳は展開・縦送り | 対象、効果、コスト、重要損失。実行ボタンをスクロールの末尾へ追いやらない |
| 期限切れ・防御終了・札消滅の警告 | 同種をまとめた要約から該当一覧へ | 実行に関係する重大な損失は、一覧を開かなくても分かる表示。警告だけを横送りの外へ隠さない |
| 直前の結果・状態変化 | 最新要点＋複数変化の展開、詳細は履歴内の縦送り | 重要な変化を短時間で消さず、画面外の対象へ辿れる。演出のために閲覧位置を勝手に奪わない |
| 山札の残数・巡目・属性／用途要約・全種類／効果／枚数 | 必要時の参照で要約→縦一覧、絞り込みは数が多い場合に比較 | 公開範囲。残数をボタン脇へ常設するかは独立した比較項目 |
| 共通回収山・再構築・混入 | 必要時の参照で要約→縦一覧 | 共通であること、再構築／混入の変化印。由来と配分を追えるようにする |
| 行動履歴全文 | 必要時の縦スクロール、まとまり単位の展開 | 過去を読んでいる間は自動で末尾へ飛ばさず、新着の印と最新への入口 |
| 成果内訳・保護／未保護・帰還／撤退 | 成果一覧は縦送り、帰還時に精算要約を表示 | 帰還入口と確定操作は固定。重要な持帰り／喪失の見込みを要約 |
| 出発構成・再開始・終了理由／精算 | 独立画面の縦送り、項目が多ければ段階的な切替 | 選択内容の要約と開始／再開始操作。選択だけで再開始しない |
| 試験ID・コミット・デバッグ情報 | 試験用説明・版情報へ分離 | 再現可能性を保持し、通常の判断領域を使わない |

共通の候補基準：収まる間は送り操作を出さず、あふれた場合だけ参照範囲を切り替える。総数・現在範囲・端の続き・移動操作などで範囲外の存在を伝える。タッチだけに依存せずボタンでも移動できるようにする。領域内の移動で画面全体を動かさず、選択はIDで保持する。複数の領域を行き来する負担が高い場合は、選択対象の固定や一覧拡大を比較する。

## 図の操作と実装範囲

`preview.html`を取得してブラウザーで開く。GitHubのコード表示画面上では動作しない。

```sh
node docs/検証/UI/readability/layouts/bc1-scroll/build.cjs crossweave-bc1-scroll-preview.html --standalone
```

- 通常量＝2対象・5枠・手札3枚、場が多い＝2対象・8枠・手札3枚、手札・対象も多い＝5対象・8枠・手札7枚。すべて密度確認用であり、ゲーム条件・上限ではない。
- 同じ表示幅では画面枠と各領域の高さを保つ。図の画面高680pxは比較用仮設定であり、製品の画面仕様ではない。画面幅が変われば可視件数を再計算する。
- 対象・場・手札をそれぞれ実寸で測定し、あふれた領域だけ送り操作と表示範囲を示す。狭い表示では通常量でも送り操作が出る。「8枠ならスクロール」という件数分岐は使わない。
- 指での横スクロール、前へ／次へのボタン、端のフェード、表示範囲と総数を実装。参照窓は開閉でき、本文に縦スクロールを設定している。図の参照内容は項目ラベルのみで長い履歴は含まない。
- 状態変化・警告・画面外の一致枠／期限切れ通知、一覧拡大、選択固定、一手の実行は今後のゲーム接続で確認する。図でこれらを実装済みとはしない。

操作版への接続では、画面外の重大変化に気づけるか、候補を探すための往復や開閉が増えすぎないか、選択中の増減で位置を見失わないかを確認する。特に対象欄は敵の存在や行動順を隠しやすく、横送りと一覧表示の比較を優先する。
