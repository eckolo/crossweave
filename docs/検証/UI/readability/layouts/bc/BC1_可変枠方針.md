「1案目」は直前に提示したUI-L-002のBC1を指す。評価されたのは場を挟んで相対する感覚であり、図の面積比・枠数・すべての表示方針の確定ではない。次の具体化の基準をBC1とする。前のBC2を有力としたUI側の推薦は、今回の反応を受けて更新する。

2×2・4枠は前図の模式例にすぎない。枠数が状況により変わり得ることを、今後のUI設計の前提として明記する。増減する条件、属性数との対応、同属性の複数枠、枠上限、札が載った枠の消失時の処理を、この発言から追加決定しない。共通ルールの整合は設計Workが担当する。

## 保つ構造

奥に環境・敵などの主体と情景、中央に共有の場、手前に自分と手札を置く。共有の場を境として相対する構図を保ち、枠の数や並びはその中央領域の中で調整する。上下の位置を新しい陣営・距離・射程のルールにしない。場は全主体で共有し、回復・防御など自分へ向く行動も扱う。

山札・回収山・履歴等を必要時に開く方向と、各UIの表示時機の検討は[前の検討表](検討.md#表示時機の基準)を継承する。中央に空きがある場面を埋めるため、外した大型パネルを自動で常設に戻さない。

## 可変枠の配置方針

| 状況・論点 | 次の試作での扱い |
|---|---|
| 枠数が少ない | 横一列を中央に寄せる。札を際限なく引き伸ばさず、空きは情景や余白として使う |
| 一列に読みやすく収まる | 枠数に応じた横並び。固定の4列や2×2に合わせない |
| 一列では読み取りが厳しい | まず場の横幅を使い、その次に場の領域を縦へ広げて折り返す。列数は枠数と使える幅に応じて決める |
| 枠の増減 | 追加・消失箇所を示し、既存枠の位置移動を抑える。操作中に枠が別の意味へ入れ替わったように見せない |
| 枠の識別 | 画面上の行列番号やA〜Dの固定配列で識別しない。ゲームから渡る枠の集合・安定した識別子と属性等を元に描画する。属性数と枠数を無条件に同一視しない |
| 選択中の変化 | 札・対象・枠の選択をIDで追う。対象が消えた場合は状態を明示し、別の枠へ黙って選択を移さない |
| 密度がさらに高い | すべてを小さくする、枠を重ねる、ページや横スクロールの外へ隠す処理を既定にしない。実際に必要な最大密度と画面寸法を確認し、情景面積や複数段配置でどこまで保てるかを比較する |

折り返し後も「奥の主体—中央の共有の場—手前の自分・手札」の関係を維持する。増減のたびに中央揃えで全枠が動く方式と、既存位置を保つ方式には違いがあるため、動的な増減場面では後者を優先して検討する。

3枠・5枠・8枠などを図の密度確認用の例として用意できるが、これは製品の上限・実際の出現条件ではない。今回その比較図や動的配置を実装・検証したとは扱わない。

## 固定試遊との区別・次の確認

PT-Z-001の固定コード・入力`e9b5b0a27b6fc51694c347c7e941a28ff97856f5`と既存UI-R-001は維持する。固定試遊のA〜D表示を、ゲーム全体の最大4枠という制約にしない。可変枠の表示確認用データは別のUI試験として識別し、既存の試遊へ増減ルールを追加しない。

次はBC1の配置を基準に、少数・多数・増減中の各状態で、場の全体と主要効果を読み取れるか、枠の位置を見失わないかを確認する。今回は方針の記録までで、実描画・操作版・人評価の追加確認はない。
