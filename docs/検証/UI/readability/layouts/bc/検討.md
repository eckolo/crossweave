2026-09-10（日本時間）、v0.1。未採用の配置・表示方針案。UI-L-001の5案、UI-R-001の操作試作を保存したまま検討を進める。

**提示後の更新：** ユーザーはBC1の「場を挟んで相対する」構図を評価し、場の枠数は状況次第で可変と明示した。今後は[BC1・可変枠の方針](BC1_可変枠方針.md)を優先する。下記の4枠・2×2は提示時の図の例であり、固定仕様ではない。BC2を有力とした当時の推薦も今回の反応で更新する。

## 受領内容と判断範囲

UI Workのユーザー原文：

> 方向性としてはBとCが想定に合う
> ただし、Cの懸念点については完全に同意
> BCの折衷案的な方向性でまた案出してみて

続く補足：

> 山札や行動履歴あたりは常時表示しなくても良いかもしれない
> その方向性も視野にいれて

> 各UIについても「常時表示すべきか否か」は一通り検討するように

Bの共有の場を中心に見る方向と、Cの情景を大きく見せる方向が合うという反応。Cで場が狭まり読み取りづらくなる懸念も受領した。B/C全体の正式採用や、山札・履歴を必ず非表示にする確定指示とは扱わない。前回のA/Bを先に比較する推薦は今回の検討優先から外し、B/Cの折衷を進める。追加の操作列・人評価結果は取得していない。

本資料は画面構成の候補。図の場と手札は模式例で、実入力から得た局面ではない。ゲーム進行は未接続。世界観は別Workの担当とし、特定ジャンルの絵や物語を採用しない。

## 折衷3案

3案とも、山札・回収山・履歴の常設パネルを外す。参照ボタンは画面上部の固定位置に残す。右側の大きな予測欄も常設せず、札選択中の予測と実行を手札の近くの帯へまとめる。これにより、情景のために場を細い帯へ圧縮せずに済む。

| 案 | 配置 | B/Cから引き継ぐ点 | 懸念と対応 |
|---|---|---|---|
| BC1 上下に分ける | 上に情景と対象、中に4属性の場を横一列、下に手札。自分の状態は手札の左、予測・実行は下の帯 | Cの上部情景とBの中央の場を、十分な高さのある別領域として確保する | 情景が上部の横長領域に限られる。情景とカードを別々の箱に見せすぎない余白・背景のつなぎ方を検討する。対象→場→手札の上下移動は残る |
| BC2 情景に重ねる | 情景を盤面全体の背景へ広げ、中央手前に2×2の共有の場。環境・敵の選択領域は左右、手札は下 | Bの中央の場を維持しつつ、Cの情景を画面全体に感じられる構成 | 場が絵や主体を遮る。中央をUI用の領域、左右を主体・状態変化用の領域として最初から分ける。場は不透明にし、演出や背景が文字と競合しないようにする |
| BC3 左右に分ける | 左約55%を情景と対象、右約45%を2×2の共有の場。下に手札と選択中の予測 | 情景のまとまった面積と、場のまとまった面積を隣接させる | 左右の視線移動が増え、中央の場というBの性質は弱まる。選択札・該当属性・効果対象を同時に強調し、予測文を左端や別窓へ離さない |

**UI側の次の比較候補はBC1とBC2。** BC1は必要な領域を安定して確保する基準、BC2は情景と盤面を同じ画面として見せる有力候補。BC3は、重なりを避けたまま情景面積を確保する候補として残す。まだ効果を実証しておらず、ユーザーの選択前に一つへ確定しない。

図の広い表示の大枠は上部9・情景＋場60・手札等23・実行8の比率。BC1では情景＋場を43:57、BC2は中央の場を横幅52%、BC3は55:45に仮配置した。隙間・内側余白を除く概念的な比率であり、正式な最小サイズではない。小さい表示では、文字を縮小せず配置だけの16:9縮図へ切り替える。実製品のモバイルUIの採用案ではない。

## 表示時機の基準

「情報を参照できること」と「本文を常に占有表示すること」を分ける。下表は既存UI-R-001の情報対応表を一通り見直した仮設定。常時とは通常の判断画面で見えること、選択中とは操作に連動して出ること、変化時とは起きた結果をその場所に表示すること。必要時の参照口は固定位置・明示ラベルとし、ホバーや記憶だけに頼らない。

| UI・情報 | 通常の表示方針 | 表示を広げる時機・参照口 | 理由・留意点 |
|---|---|---|---|
| 現在の区間・場所 | 短い名称を常時 | 区間移行時に変化を示す | 何に対処しているかの基準。説明文・過去区間を並べ続けない |
| 情景・環境の外観 | 常時、主要UIより後ろ | 参加・退場・踏破で変化 | Cの方向。絵だけで環境の選択対象や状態を代用しない |
| 行動可能な主体と対象選択 | 常時 | 選択中の対象を強調 | 相手が誰か、環境も対象かを隠さない。多主体でも対象を辿れるようにする |
| 各主体のHP | 小さなバーと数値を常時 | 予測時に前後値、実行後に実変化 | 生存・突破・回復判断の基礎。HP以外の詳細まで大型パネルにしない |
| 命中蓄積・会心蓄積 | 短い状態表示を常時 | 関連する選択時に次の値と説明 | 現在の蓄積が次の一手の効果を変えるため、毎回詳細を開かせない。0状態の冗長な説明は不要 |
| 防御・有効回数 | 有効中は常時 | 選択時に継続・終了・更新を表示 | 「防御なし」の大型領域は不要。終了を見逃すと判断が変わる |
| 回避・軽減の内訳 | 有効状態を短く表示、内訳は必要時 | 主体の詳細／攻撃選択時の計算 | 詳細数値の全主体分を常設しない。命中・ダメージに影響する状態の存在は示す |
| 存在効果・支援の範囲 | 有効中は元の主体付近に短く表示 | 対象選択時に影響先、詳細は主体参照 | 背景の装飾へ埋め込まない。支援終了は変化として残す |
| 公開の行動順 | 直近の順序を小さく常時 | 全予約の時刻・順は行動順の参照から | 次に誰が動くかは手の重さに関わる。非公開の札・対象・行動内容は予告しない |
| 現在の絶対時刻・手数 | 詳細参照 | 選択時は行動コストと自分の次回予定 | 開発用カウンターを主役にしない。公開値は失わず参照可能に保つ |
| 共有の場の属性・空き・札 | 常時、中央または中央に近い領域 | 手札選択に連動して該当枠を強調 | 一致・設置の基本判断。全案で場を単なる小アイコン列へ縮めない |
| 場の主要効果 | 短い数値・記号・ラベルで常時 | 選択中は実際の寄与、全文は札参照 | 各枠を開かないと比較できない状態を避ける。長いルール文は常設しない |
| 場の札の消滅予定等 | 該当札に印を常時 | 使用・回収される選択時に明示 | 不可逆な損失を詳細内だけに隠さない |
| 手札の名前・属性・主効果 | 各札に短く常時 | 札選択中に詳しく表示 | 手札3枚の判断材料。全文を3枚分並べる必要はない |
| 手札の使用期限 | 各札に短く常時 | この手までの札を強調、選択中に失効結果 | 開いたときだけ見えると取り逃しやすい。色だけに依存しない |
| 手札の場効果・会心増加・行動コスト | 選択中、任意の札詳細でも参照 | 置く場合は場効果、一致なら主効果とコストを中心に | 非選択札の全文を常設しない。未選択の札も調べられるようにする |
| 手札の由来・初期持込との差 | 札の詳細・山札で必要時 | 混入や消滅条件に関わる変化時は知らせる | 由来の説明で手札を埋めない。消滅予定は別行のとおり常設 |
| 一手の予測 | 札選択中のみ、手札に近い帯 | 関連する主体・場の上にも短く示す | 未選択時の空の大型予測欄をなくす。攻撃・防御・回復・設置で強調先を変える |
| 詳細な計算・ルール説明 | 必要時 | 選択札の詳細から | 確定結果を先に示し、式や内訳は確認したい時に読む |
| 期限切れ・防御終了・消滅の警告 | 関係する選択中に明示 | 該当札・自分・実行付近 | 毎回の確認ダイアログは増やさず、損失を知って選べるようにする |
| 実行操作 | 判断中は固定位置 | 合法な選択が揃うと有効化 | 出現で手札が移動することを避ける。演出中の多重入力を防ぐ |
| 直前の変化 | 発生時に該当箇所＋短い結果表示 | 詳細は履歴。次の実行まで確認可能 | 全経過の常設は不要だが、短時間で消える通知だけにはしない。自分と他者の結果を区別 |
| 自分の山札の残数・巡目・用途／属性要約 | 通常は閉じる候補 | 固定の山札ボタン。残数が判断に関係する選択や再構築時にも表示 | 常設の専用枠を廃止。開閉が多すぎるならボタン横の残数だけを残す比較を行う |
| 山札の全種類・効果・枚数 | 必要時の一覧 | 山札ボタンから要約と同じ画面 | 未ドロー・手札・初期持込・消滅予定を区別。札順や非公開情報は追加しない |
| 共通回収山の残数・参照 | 通常は閉じる候補 | 固定の回収山ボタン、回収・再構築時の変化表示 | 自分だけの捨札と誤認させない。原版の公開範囲に限定する |
| 再構築・混入の把握 | 変化時に表示 | 山札ボタンに変化の印、開けば配分と由来を確認 | 画面を自動で全面的に塞がない。見逃した場合も結果・履歴から辿れる |
| 行動履歴全文と並べ順 | 通常は閉じる | 固定の履歴ボタン | 常設スクロール欄を廃止。後から読むための経過は保持する |
| 相手の性格・観測した札 | 必要時 | 主体の詳細から | 札選択と無関係な長文を常設しない。過去の知識と相手の現在の非公開札を混同しない |
| 成果の内訳・保護／未保護 | 通常は閉じる | 成果ボタン。獲得・保護時は通知、帰還検討時は内訳を表示 | 画面に報酬表を並べ続けない。帰還判断に必要な情報はその場で確認可能にする |
| 帰還・撤退の入口 | 小さい固定操作を残す | 実行前に現在の精算見込みを参照 | 行動ボタンと離し、誤操作を抑える。元版にない精算条件を加えない |
| 出発構成・再開始 | 探索中は設定から必要時 | 出発前・探索終了後は専用画面 | 通常の戦闘画面の下に構成フォームを常設しない。選択だけで探索を再開始しない |
| 終了理由・精算 | 探索終了時の画面 | 持帰り・喪失・再開始の操作を表示 | 操作不能な盤面の端に小さく置かない。今回の図には未接続 |
| 試験ID・コミット・デバッグ情報 | 通常ゲーム画面外 | 試験用の説明・設定・版情報 | 比較・再現には保存するが、プレイヤーの判断領域を圧迫しない |

表示を減らすために全文や公開値を削除しない。前の情報設計の「山札要約・時刻・結果等を常時」の扱いを、この候補では上表の時機へ変更する。UI-R-001そのものは改変しておらず、実装時には項目ごとの参照先を再確認する。

開く操作でゲーム時刻を進めず、札・対象の選択と盤面を保持する。閉じたときは操作元へ戻す。長い参照は山札・回収山・履歴を共通の参照領域で切り替え、複数の大型窓を重ねない。選択に連動する表示も、そのたび手札・主体の位置が動かない固定領域へ収める。

## 今回の図で示す範囲

`preview.html`は配置3案の切替と、山札・回収山・履歴の参照位置を開閉できる模式図。図内の「HP・状態」「主効果・期限」等は上表の表示項目をまとめた領域ラベルであり、全項目の表示タイミングを実装した実機画面ではない。

山札・履歴だけを隠す案ではなく、相手の長い状態説明、計算全文、予測の大型パネル、山札要約、成果内訳、出発設定まで通常画面の常設対象から見直した。状態変化をその場で示す演出、選択への連動、残数表示の頻度、人が読む負担は今後の操作版で比較する。

## 試遊への接続と残る確認

1. 上表の表示方針を共通にしてBC1/BC2などの配置だけを比較する。山札の残数まで閉じる案と、残数だけ常設する案は別の表示条件として記録し、配置差と混ぜて評価しない。
2. 操作版の次候補IDはUI-R-002（作成時に競合確認）。既存の固定`e9b5b0a27b6fc51694c347c7e941a28ff97856f5`／W seed32を使う初回比較では、演算・入力・公開範囲を維持する。コード・専用差分・開始局面を固定してから試遊へ渡す。
3. 入口だけでなく、既存の混入後・多主体・期限切れ／防御終了／消滅の再現局面で、隠した情報を毎手開き直す必要がないか、変化が後から辿れるかを見る。過去のユーザー状態とは扱わない。
4. BC2では、対象数が増えても中央の場や左右のHP表示を遮らないことを確認する。場や手札の字を小さくすることを面積不足の第一の解決策にしない。必要なら情景側の占有面積・対象の配置を調整する。
5. 表示連動・描画・入力の確認はUI側、人評価と原記録は試遊側、ゲームの機械比較・共通成果統合は設計側。UI-L-002の模式図で実装・評価済みとしない。

今回の同期で設計0.45/D43〜D45と世界観Workの追加を確認した。これらの新しい条件はPT-Z-001／UI-R-001へ混ぜない。世界観は確定前提に置かず、情景の具体的な絵は世界観Workの成果と後で接続する。
