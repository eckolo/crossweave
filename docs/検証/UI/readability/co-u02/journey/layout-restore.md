# 探索画面の配置と札の寸法を戻す

操作試作0.9／2026-09-16。Work `20260910-ui-readability`、枝 `ui/readability-20260910`。

ユーザーから「手札や場の枠が変に大きくなり、当初のデザインから乖離した」と指摘を受領。能力欄の追加を理由に、探索の構成まで変えた回帰を修正する。正式参照UI-R-002 v0.15は固定原本のまま維持する。

## 原因と修正

0.8で低い画面の切替境界を高さ360pxから480pxへ広げた。その結果、通常の会話幅736pxでも相手と場が横に並ぶ配置になった。さらに札が各領域の高さへ伸び、手札・場の枠と領域配分が元の構成から離れた。0.8の44件は状態・窓の座標計算などの検査であり、この見た目を保証していなかった。

`exploration-layout.css`を接続部品の最後に適用し、全幅で奥から相手→場→手札→薄い下部操作帯の順に揃える。低い画面でも相手と場を左右へ分けない。通常幅の札幅は固定原本どおり、手札184px・場172pxを維持。高さは領域に合わせて小さくなり、手札132px・場92pxを上限として、空いた面積を埋めるために引き伸ばさない。

現在の情報量に必要な最小高さを積算し、通常配置の境界を410pxとする。通常配置は407px、単体入口の外枠を含めて409pxを必要とする。736px・16:9の会話枠では内側412pxとなり、通常配置を維持できる。単純に以前の360pxへ戻すと、追加された能力欄と44pxの操作帯が収まらないため、領域内の寸法も同時に整理した。

高さ410px未満でも3段の関係を保ち、選択時の操作は手札の横に置く。予約の詳細はメニューに保持し、重複する一致見出しと送りボタン列を省く。280px未満は絵の余白と装飾を外し、320px幅の内側178pxに相手46px・場44px・手札44px・下部44pxを割り当てる。札名・値・予測・残り行動数は残す。全体縮小や主画面全体の縦スクロールは追加しない。

札の横送りは従来の横方向の列を維持。通常のマウス表示では送りボタン、タッチでは直接スワイプを使い、細いスクロールバーが札の高さを奪わないようにする。低い画面では横スクロール・札のドラッグ入力を使う。実タッチの使いやすさは未確認。

今回の変更は配置・表示寸法と提示開始位置のみ。対象保持、余力と隠蔽、4能力、再設定前の隠蔽予測、ピン、小窓の関係、本文の折り返しは維持する。共通runtime・保存・経済・シナリオには変更を加えない。

## 操作提示と検証

今回の提示は設計提供の自然保存例 `entry.save.json.gz` から開始する。入口本文を画面で読み、進めると探索画面に入る。描画前に本文を既読にする・場面を自動で飛ばす処理は追加しない。通常の帰還開始もビルダーの既定値として維持する。

実Campaign＋設計所有MemoryStoreの操作試作であり、閉じた後の永続保存は保証しない。実IndexedDB接続版とは区別する。

- [今回27件](layout-restore-checks.json)：1024／736／600／320pxの入力で、上下関係のCSS契約、札の上限寸法、選択・対象・固定した予測窓・下書き保持。実previewAction、出札、撤退を確認。
- [対象とハッシュ](layout-restore-freeze.json)：ソース、検査、設計保存例、提示ファイルを固定する。旧検査を再実行・再計上しない。
- JSDOMは描画しない。CSS契約は正式参照の配置CSSと追加CSSの宣言を解析したもの。全CSSのコンテナ／メディア条件、フォント、クリッピング、実タッチ、会話内ホストの表示は未確認。
- 正規Browserから既存ローカル入口を開く要求は `net::ERR_BLOCKED_BY_CLIENT`。別ポート・別URL方式・別ブラウザーで回避していない。実表示の問題が解決したと断定しない。
