# 相手の選択と詳細を一つにするサンプル

窓位置の最新規則は[UI0.14.5](steady-details.md)を参照。以下は選択・詳細統合を提出した0.14.4時点の記録。

2026-09-26（日本時間）／UI0.14.4。1920×1080に広げた現在の画面では、敵の対象指定と詳細をホールドで分ける必要が薄れた、というユーザー指示に基づく修正版。

## 操作

| 対象 | クリック | ホールド |
|---|---|---|
| 敵・踏破対象の地形 | 行動対象を切り替え、その相手の詳細を開く | 追加の動作なし。進行表示も出さない |
| 手札 | 札を選択して詳細・予測を表示 | 既存の短ホールドでつかみ、場へ運ぶ |

クリックは実行命令を出さない。相手を選んだときは選択中の札を保ち、その札の対象・操作名・予測・関係線を切り替える。実行は札下の操作ボタン／既存の場へのドロップから行う。相手の詳細を閉じてからでなくても次の相手・札・操作ボタンを押せるよう配置する。

別の相手へ移ると同じ詳細窓の内容を切り替える。同じ対象を再クリックすると、札と同様に詳細だけを開閉し、対象指定は保持する。「選択時に詳細を開く」の設定を札・相手で共用する。常時表示していた「対象の詳細」ボタンは除去した。操作説明・読み上げ名も更新済み。

相手の押下は移動や取消を判別するだけで、時間到達による機能はない。長く押して離した場合も通常のクリック一回として扱う。スクロール、移動、キャンセル、別ポインター、画面離脱後の誤クリックを抑止する。札の表示待ち120ms・標準220msでつかむ操作は維持。

## 配置と試用範囲

相手の詳細は固定416×384px。既存の窓と同じ13:12の縦横比を保ち、内容量・相手によってサイズを変えない。本文の文字は縮小しない。描画された相手・場・手札・行動順・操作ボタンを避ける候補から空き位置を選ぶ。札の詳細・予測は従来の520×480pxのまま。外枠1920×1080、敵の絵の大きさ、共通札面、ゲーム側の規則と固定入力は変更しない。

本文内入口：`/workspace/crossweave-select-details.html`。[生成照合](../review/select-details-manifest.json)。同じ実Campaign・設計MemoryStore・既存の4場面から生成した。別実装の見本や静止画への置換ではない。会話内では全体／原寸を切り替えられる。

## 確認と残件

[差分15項目](../review/select-details-checks.json)を確認。クリック直後の対象・詳細、地形への切替、再クリック、敵のホールド無反応、取消5経路、ボタン起動、札を保った予測・関係線、倍率、窓を閉じず敵へ実API行動、札の既存ドラッグと取消、説明を確認した。注入したサンプルのFHD矩形では、相手の詳細が敵・場・手札・行動順を覆わないことを確認。実際の描画を確認したという意味ではない。

Node／JSDOMと注入した矩形・capture・可視通知・クリック通知による限定確認。実ブラウザー描画、実フォント、実マウス／タッチ／キーボード、IndexedDB・複数タブは未確認。[実環境での確認事項](../u02b/browser-review.md)へ分ける。旧全検査は再実行していない。

9月25日の「クリックは詳細だけ・敵ホールドで対象指定」という[旧提案](interaction-proposal.md)は、このサンプルの方針で置き換えた。旧提案の採用待ちを現在の残件としない。今回ユーザーに見ていただく点は、相手を替えた際の詳細窓の位置、札と相手を行き来するときの操作感。取得編成の本編接続と実環境確認の残件は別に保持する。
