# 句読点・窓の関係・能力表示の見直し

操作試作0.8／2026-09-16。同じWork `20260910-ui-readability`・枝 `ui/readability-20260910`。ユーザー指摘を受領したUI専用差分。正式採用・受入・CO-U02全体完了ではない。

## 本文の折り返し

段落の原文と読取IDは維持し、表示幅と実フォントで収まる範囲を測る。残りの本文が一行に収まる場合は改行を増やさない。途中で折り返す必要がある場合、収まる範囲の最後の句点を優先し、句点がなければ最後の読点で折る。疑問符・感嘆符も文末として扱う。閉じ括弧は句点と同じ側に置く。

収まる範囲に句読点がない長い一文だけは通常の折り返しを許す。文字を削る・枠外へ出す・縮小する方法は使わない。結合文字・絵文字を分割しない。幅とフォントの読み込みが変わったら再計算する。意味上の段落を分割して別の既読IDにはしない。

適用対象は帰還・場面の本文、探索先の目的文、窓内の説明段落。能力表・札名・操作ボタンにはこの段落規則を強制しない。表示レイアウトの処理だけで本文を既読にはせず、実際に可視になった対象だけを既存の `continue_scene`、`advance:false` へ送る。

## 対象と操作の所属

局所的な操作は対象と同じまとまりに置く。「詳細」は探索場所名のすぐ横に置き、目的文の右端へ離さない。帰還の詳細は獲得・回復のまとまりに置く。札の増減と装備は対象の直下、比較・確定・出発は現在の構成に対応する下部操作帯、全体メニューは共通操作位置とする。

単独ボタンを空いた場所へ置かない。距離・位置・ラベルの3つで「何を操作するか」を読めるか確認する。原稿を説明の箱へ合わせるためだけの不自然な改行は加えない。

## 小窓から開く小窓

- 元の窓を残し、新しい窓を隣へ置く。まず元の位置を保てる左右の空間を探し、足りなければ2枚を枠内に並べ直す。320pxでも親を隠す切替にしない。
- 帰還内訳→札詳細、メニュー→遊び方等、調査記録→対象→札、探索メニュー→行動順等に適用する。記録の3段目では直前の対象一覧を残し、一覧の下へ追加しない。
- 同時表示は直前の窓と現在の窓を基本にする。深い参照は「←」で戻る。元の一覧位置と編成下書きを保つ。固定した詳細が多数ある場合は直近2枚と戻る経路を使う。
- 見える「戻る」の文字は省き、読み上げ名は戻り先を示す。ピン留めは全窓で同じ `pin` マーク、固定中の押下状態、操作名「固定する／固定を外す」で揃える。
- 窓の本文は小窓内で縦スクロール可能。狭い窓の見出しと操作は段を分ける。外枠は16:9で変えず、出発・帰還等の文脈切替で小窓を閉じる。

探索メニューから共通の設定・保存／調査記録を開く入口では共通の窓へ切り替える。これは別の窓系統への移動で、探索メニューを残す親子表示には含めていない。

## 主体の能力・予測・札の性質

主体の余力・隠蔽は現在の値と変動値を表示し、最大値の重複文字を除いた。上限は2本のバー、読み上げ、補助表示、主体詳細に保持する。身構・機転・軽減・攪乱は常時表示。予約帯を含めて能力欄の高さを確保できるよう低い画面の配置切替を早め、数値欄を縮めない。隠蔽のマークは斜線入りの目から仮面へ変更した。

隠蔽予測は公開 `posture_before - hit_gain` を表示する。hit_gain は本体が解決した値で、UIで探査・攪乱の計算を再現しない。0を下回ってもその値を表示し、初期化後の `posture_after` を混ぜない。現時点の機転・軽減・攪乱等の解決後値は公開されておらず、推測を補完しない。

通常札の「共有回収へ」は省略。公開された札固有の発動・効果・回収時の消滅を「性質」にまとめる。自身以外への全体効果などが公開された場合も同じ欄に置くが、未提供の効果を実札へ追加しない。消耗札も本体が回収時に消滅させるため、その出来事を表記する。

予測末尾の一般的な注釈を除いた。続く主体の行動を含む範囲と未公開の変化、ピン操作は「遊び方」にまとめる。期限切れの札等、その選択で実際に生じる情報は残す。

## 検証と残件

[検査結果](fit-review-checks.json)は今回変更44件。実Campaign＋元のMemoryStore、自然帰還・探索開始の保存例、公開previewAction、編成確定と撤退を使用した。句読点・長文・閉じ括弧・結合絵文字、実測関数の再配置、親子窓と戻り、スクロール・下書き保持、ピンの状態、負の隠蔽予測、通常／特殊札の説明を扱う。

1024／736／600／320pxの矩形を明示したJSDOM検査では、2枚の窓が枠内で交差しないことと状態保持を確認した。文字幅の検査は合成値。負の隠蔽境界と特殊性質は公開データ形の例も併用しており、本体でその全経路をプレイした扱いにはしない。旧検査群は再実行・再計上しない。

**JSDOMは描画しない。実フォントの改行・敵欄の物理的はみ出し・詳細末尾や確定操作への物理到達・実タッチ・会話内ホストの表示は未確認。** 正規Browserのローカル入口拒否の既存記録を別経路で回避しない。会話内へ操作版を提示するが、表示合格やユーザー受入と記録しない。実IndexedDB結合・正式UI-R-002 v0.15完全移植も未了。固定原本・runtime・保存・経済・シナリオは無変更。

[対象コード・入力・生成物のハッシュ](fit-review-freeze.json)と保存後の `fit-review-save.json` に同一成果の範囲を残す。設計Work `20260909-design-assembly`／`dev_design_tmp_assembly`へ、このUI差分・共通探索部品・生成distの確認と統合を依頼する。自Workから逆方向統合せず、受領・採用・統合を先取りしない。今回の保存・再提示で区切り、稼働枠を解放する。
