# 相手の詳細窓の位置を揃える

2026-09-26（日本時間）／UI0.14.5。選択対象ごとに詳細窓が縦横両軸へ動いて分かりにくい、という指摘への修正。敵・地形の詳細に適用する。

## 従来の位置が変わる理由

0.14.4までは `placeWindow` が選択元と避けたい各要素の上下左右から候補領域を作り、それぞれの端・中央を候補にしていた。選択元との重なり、周辺要素との重なり、寸法不足、対象からの距離を評価して一つ選ぶ仕組みで、最も重なりが少ないことを優先し、近さは補助条件だった。

固定の縦位置や、対象の左右に出す規則を持たない。そのため、他の札や予測・行動順の位置、選択元の矩形が違うと、別の上下左右候補へ移り得る。相手に対する位置関係を見ただけでは予測しにくい挙動だった。

## 今回の規則

1. 相手の詳細は全て上端16pxの共通の高さへ置く。窓は416×384px固定、縦横比13:12を維持。
2. 選択相手の中心が画面の左半分なら右脇、中央以右なら左脇を基本にする。ユーザーの追記どおり、画面中央側へ開く。対象と窓は16px離す。
3. 隣の相手と重なる場合は、その側の空きへ横に寄せる。画面端でその側に収まらない場合も、補正は横方向だけとする。上下の空きを探して飛び移る処理は行わない。

判定には相手枠の矩形を使う。札、場、予測、操作帯の変化によって相手の詳細窓の位置を再選択しない。同じ対象・同じ相手列なら、クリックの順番や予測応答の前後によらず同じ位置へ出す。横スクロールで相手自体が動いた場合は、その現在位置に追従する。

左右に窓幅の空きが全くない密集配置では、選択相手を隠さず画面内の同じ高さへ置くことを優先する。この条件で他の相手との完全な非重複は保証しない。狭い別ウィンドウや上下への退避を無断で追加せず、実環境の密集場面確認へ残す。サンプルの通常配置では敵・地形・場・手札・行動順の非重複を確認した。

札の詳細・予測、メニューから開く窓、親子窓の配置アルゴリズムは今回変更していない。クリックで対象指定＋詳細、相手のホールドなし、札の保持と予測・出札は0.14.4を継承。
