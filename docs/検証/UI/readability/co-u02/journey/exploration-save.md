# 0.11：探索だけの中断・編成の確定時保存・公開表示

2026-09-17。Work `20260910-ui-readability`／`ui/readability-20260910`。

ユーザー補足「中断は探索の途中だけ」「山札編集は完了時のオートセーブ等でよい」を優先し、0.10／0.10.1の拠点編集の中断保存を現行導線から外した。履歴の札名、身構・機転・攪乱すべての数値予測、常時軽減を身構へ含める案も受領した。

## 反映したこと

- 「探索を中断」は探索phaseだけに表示する。探索途中の本文画面でも使用でき、撤退・帰還せず「続きから」で同じ探索へ戻る。再開成功通知を残さない0.10.1の修正も維持する。
- 札組・心得は「確定」または「確定して出発」の確定処理が成功した時点で本体が自動保存する。編集中の内容は同じ画面内で保持し、未確定のまま新しいUIを開いた場合は最後の保存へ戻る。追加の手動保存は設けない。
- 書出しは本体の保存済みデータをそのまま出す。書出し時に未確定案を`save_draft`する処理を外した。旧版が既に保存した変更案は削除せず、読込み・再比較の互換動作を維持する。
- 履歴と短い行動表示に使用札の名前を添える。同一セッションで公開hand／fieldから取得できた、同一カードIDの名前だけを記憶する。探索を中断して戻っても保持し、別探索・別セッションへ持ち越さない。未取得の過去名は「札（名称未記録）」とする。
- 予測の詳細に、公開済み`crit_added`を「機転の加算（消費前）」として表示する。身構札の`guard.evasion`は「攪乱（この身構）」と明示する。これらを行動後の総量や差分と偽らない。
- 現行試作にある身構と軽減の説明をツールチップ・遊び方に追加した。常時分を身構へ統一する変更は下記の計算側対応と一緒に行う。

## 設計Workへの対応依頼

宛先は既存の設計集約Work `20260909-design-assembly`、統合先は`dev_design_tmp_assembly`。ここに保存した依頼は設計の受領・採用・統合を意味しない。D02の既存APIは接続済みであり、以下の追加項目だけが不足している。

| 項目 | 現状と必要な対応 |
|---|---|
| 常時軽減と身構の統一 | ユーザーは「大岩などの常時軽減も、常時身構が加算される扱いでよいのでは」と提案。別能力として覚える必要を減らし、身構の合計と必要時の内訳（札／常時効果）で表す方向を検討する。UIで名称だけを統一せず、下記の演算差を本体と合わせる |
| 履歴の札名 | `exploration.public_history`に、解決時の使用札の公開名を同一`card_id`へ紐付けて保持・公開してほしい。修飾等がある場合もその時点の公開名を保存する。後から現在の名称や別札の知識で代用しない。保存を開き直しても、手札・場を離れた過去の札を判別できることが必要 |
| 全能力の行動後予測 | `previewAction`に公開主体IDごとの解決直後の値を追加してほしい。身構（常時分・札分・持続回数の扱いを含む）、機転、攪乱を表示対象とし、身構終了・機転消費・支援源退場による他主体への変化を反映する。未来のNPC行動は含めず、公開情報から確定する今回一手だけを対象とする |

予測契約では未対応・不明と、変化なしの0を区別できる必要がある。現在の`crit_added`は加算量であり、一閃消費後の残量ではない。`guard.evasion`も札による分であり、常時支援込みの攪乱総量ではない。UIが同じゲーム規則を別実装して埋めない。

常時軽減の調査根拠：現行`src/runtime/core.mjs`は、札の身構に防御側一閃の倍率を掛けてから常時軽減を別に引く。札の身構だけに使用回数・一致時解除と防御側機転の消費が紐付いている。一方、基本設計4.7は常時作用を特性として明示する方針を採用しているものの、仕様案4.6は持続軽減の演算を未確定としている。「硬さを周囲への回避支援と区別する」記述だけでは、身構とは別の計算値にする必要性までは確定しない。

UI側の提案：数値の種類は身構へまとめ、常時／札由来の違いは発生源と持続条件の内訳で表す。本体側では常時分にも一閃を適用するか、常時分だけで防ぐ時にも機転を消費するか、札分が終了しても常時分を維持することを整理する。これらの細部を今回のユーザー発言だけで決定済みにしない。計算・公開値・予測を同じ変更で揃えてからUIを一本化する。
