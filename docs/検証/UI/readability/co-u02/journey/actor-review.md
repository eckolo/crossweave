## 本文の共通規則

文章側は意味のある段落だけを持ち、画面幅のための改行を埋め込まない。表示側は利用できる横幅と共通の最大行長（42文字相当）を使い、禁則処理・自然な折り返し・対応環境での行末調整を適用する。題名、数値、操作ボタンを本文の枠へ一緒に詰め込まない。表示領域の調整はCSSの共通変数と場面ごとの配置で行い、原文や文字サイズの全体縮小で合わせない。

帰還は広幅で結果と本文を横に並べ、小幅では結果の下へ本文を移して横幅を確保する。出発時の場面文も画面の利用可能幅へ広げる。探索先の文章と題名は静的な表示とし、「詳細」だけを押す。背景と本文を重ねる方針は維持。長文は限定した読書領域だけでスクロールし、外枠16:9と主画面全体のスクロール禁止を守る。本文の段落をDOMへ配置しただけでは既読にしない。

## 用語と公開予測の境界

世界観枝 `design/worldbuilding-20260910` の取得HEAD `273f4fb3109594dbc435d947ed30835458bbff4a`、参照ファイル `docs/確定仕様/世界観/正式用語集.md` 1.3、blob `2aa3631fac46b8128503394d0f0ca611131ff99b` を照合した。参照のみで共通原本を編集・統合していない。

正式用語上、隠蔽は残量M−L、探査は札による削り。主体の蓄積critは「機転」、一閃は発生する出来事。現在のruntime表示辞書のcrit→一閃、damage_reduction→隠蔽には相違がある。今回はUI表示だけを正式用語へ合わせ、runtimeの辞書修正は設計へ依頼する。非公開ゲーム辞書や独自演算は新設しない。

予測の表示は公開応答だけを使う。攻撃はactual_hp_lossとposture_before／after、回復はhp_restored、身構はguard.value。削り切った後の隠蔽は「↻残量」で復帰を示し、単純な有利な増加として示さない。予測の対象はこの一手であり、後続する相手の行動は含めない。

**機転の消費後・軽減・攪乱など全主体の解決後値は、現APIの予測に揃っていない。** 値が無い箇所へ±0を置いたり、UIで戦闘処理を再計算したりしない。詳細予測には未提供項目を明記。設計へ、同一view_tokenに対する主体ID別の解決後値（余力、隠蔽、身構、機転、軽減、攪乱）と場の変化の提供を依頼する。返る範囲が増えたら同じ数値横の表示へ接続できる。

予測をview_tokenと完全なchoiceの組に結び付け、同じ選択は再利用する。予測読み取り待ちの対象切替を許可し、古い選択・古いviewの応答は表示しない。実行・再読取中は入力を止める。予測窓の開閉は自動予測から独立し、閉じた後の遅延応答で再び開かない。重複する同じ予測要求を送らない。
