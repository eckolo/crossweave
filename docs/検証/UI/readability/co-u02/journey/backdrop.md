# 背景と文字の重ね方 — 操作試作0.5

2026-09-16。Work `20260910-ui-readability`／`ui/readability-20260910`。

0.4は16:9への収まりを優先して、結果と本文を大きな箱へ分けた。ユーザーは文字の枠だけに使う面積が大きく、背景のある旧結果画面の方がよいと指摘。囲いを縮める・重ねる・一部または全体を消す方向を受領した。はみ出しの許容ではない。

## 変更

- 帰還の背景を戻し、主領域へ広げる。既存のCSS背景を再利用する。
- 金額・回復・素材・記録の数値を囲む大きな矩形を外し、背景上の左下へ置く。押せる入口には矢印とフォーカスを残す。
- 本文は背景上の右下へ重ねる。固定200pxの箱をやめ、内容に応じた高さと枠内上限を使う。薄い背景色で可読性を補い、長文だけ内部でスクロールする。
- 探索先の背景と文字の専用列をやめ、行き先と目的を背景に重ねる。場面文も同様に重ねる。上下の装飾的な仕切りを外す。
- 16:9の外枠、主画面のスクロール禁止、44pxの操作帯、一覧の全ページ、主要操作への到達を維持する。背景は `aria-hidden` と `pointer-events:none` で情報・入力の対象から外す。

狭幅では文字の大きさや画面全体を縮小せず、既存の小さい配置を使う。本文と結果の操作領域が衝突しない位置を確保する。背景と文字の重ねを許容することと、押したい対象や実行操作を参照窓で塞ぐことは分けて扱う。

囲い削減は全画面の方針。札そのものの識別、選択、操作可能性を表す枠まで一律に消さない。今回の変更は帰還・探索先・場面文を対象とし、共通runtime・経済・保存・シナリオ・正式固定原本を変更しない。

## 検証

既存の `verify-fixed-screen.cjs` を現在のビルドへ実行し、[32件の回帰確認](backdrop-checks.json)が合格。本文の実表示通知、任意詳細、帰還内訳、実Campaignの帰還→編成→確定→出発→探索・中断再開、4幅の指定高と状態保持を確認した。新規32件として再計上しない。対象・入力・SHA-256は[backdrop-freeze.json](backdrop-freeze.json)。

JSDOMは描画しない。今回の重ねた配置での実際の切れ・重なり・背景上のコントラスト・物理スクロール・タッチは未確認。正規Browserのローカル入口が拒否された記録を継承し、別経路で回避しない。会話内へ操作版を再提示するが、配置受入済みとはしない。

実API＋設計MemoryStoreの一時保存版を継続する。IndexedDB確認、正式探索UI完全移植、全機能実装、ユーザー受入・CO-U02全体完了は未了。
