## 今回の修正

- 踏破対象の地形は、相手枠・行動順とも背景画像の縮小をやめ、山形の地形記号へ戻した。背景全面の水路画像と敵の潜水服画像は保持する。公開用途 `passage` の地形記号であり、絵からゲーム上の分類を推測しない。
- 手札・場の実札・場の予測札・ドラッグ札を、同じ札面の生成処理へ統一。絵、名称、効果値、属性の順に並べ、残り行動数は手札の属性行の右側に保持する。場には場で働く数値を表示し、内容を手札と同一にしない。
- 248×208の枠を維持。本文は120px、名称48px・効果24px・属性28px、行間4px・内側6px。区画の高さを共通化して、内容の違いで内側の線や絵との境界がずれないようにした。予測・消費の印は本文外へ置く。
- ホールド中の操作名と手札下のボタン名を同じ関数から取得。「場に置く」、一致時の「攻撃」「進む」「身構」等、実際の公開操作に合わせる。別の札をホールドした場合も、その札と現在の対象から算出し、前の選択札の操作名を流用しない。進行リングの横余白は長い操作名も考慮する。
- ホールド成立だけでは出札しない。既存の220ms保持、場へのドロップ、予測・実行条件、取消条件を保持。敵のクリック対象指定／ホールド詳細も、本版ではまだ変更していない。

## 潜水服と今後の作画

ユーザー評価は「潜水服としてのポーズは良いが、背景と描き方が違い過ぎて浮いている」。姿勢の了承を画風・正式採用の了承に広げない。今回は描き直し・再生成・画像加工を行わず、現在の仮画像を保持する。

次回新規制作・差替は、ビジュアル枝 `25e7ce99bffc551e2370568b74704865c3de13e0` の[正式な制作手順1.0](https://github.com/eckolo/crossweave/blob/25e7ce99bffc551e2370568b74704865c3de13e0/docs/仕様案/ビジュアル・演出/Dの制作手順.md)および `UI接続条件.md` 0.5を適用する。着手時はビジュアル担当の最新版を受領する。

独立した敵・道具は基本②「少数の筆で拾う」、背景は③「輪郭を途切れさせる」。共通して大きな形・色面、外周を一周線で描かないこと、しっとりした色のなじみを優先する。対象②では種類・向き・部品の接続を読ませ、精密な立体陰影・細かい鏡面反射・全面の細かい筆触を増やさない。単に「ガッシュ」「柔らかい絵」と指定するだけで準拠と扱わない。

生成前に、基本②の `見本/seal-lost-edges.png` 中央、背景③の `見本/night-tide-lost-edges.png` 下段、および使用背景を実見し、正確な作例と参照箇所を制作指示へ記録する。現在の姿勢は形の参照、画風は正式作例、と参照の役割を分ける。実表示320×108・手番肖像・明暗の背景で馴染みを確認し、ビジュアル担当の精査条件として渡す。今回の資料読取を画像の実合成確認としない。
