# クリックとホールドの統一案

2026-09-25。ユーザーから、手札はクリック詳細・ホールド出札、相手はクリック対象指定・ホールド詳細という逆転を指摘。ホールドをアクションへ寄せたい一方、頻繁な連続ホールドを懸念している。以下は**提案であり未採用・未実装**。UI0.14.2は地形・札枠・操作名の修正版であり、この操作変更の試用版ではない。

## 推奨する共通規則

物そのもののクリックは詳細を開く。ホールドはその物への直接操作を始める。操作名の付いたボタンはクリックで操作する。ホールドをあらゆる操作の必須条件にしない。

| 対象 | 本体のクリック | ホールド | ホールドを使わない操作 |
|---|---|---|---|
| 手札 | 詳細と使用時の予測を表示。確認対象にしても出札はしない | 出札のために掴む。時間到達だけでは使わず、場へのドロップへ進む | 札下の「場に置く」「進む」等の明示ボタン |
| 敵・踏破対象 | 詳細を表示。行動対象は変更しない | 対象指定の近道。詳細は開かない | 対象枠に接して置く「対象指定」ボタン。詳細内からも同じ操作 |
| 取得編成の札・心得 | 詳細を表示 | 掴んで別の置き場へ運ぶ | 現在の「取得」「編成」「外す」ボタン |
| 場の札 | 詳細を表示 | 現仕様では単体の移動操作がないため反応・進行円なし | 使用は手札の対応する操作から行う |
| 通常の操作ボタン | 表示された操作を実行 | 追加の動作は割り当てない | 同左 |

敵のホールドは必須にせず、対象指定ボタンの代替とする。現在の「対象が有効な間は保持する」動作を継承し、毎回の札使用前に指定し直させない。対象が離脱したり使えなくなった場合だけ、公開された候補に従って更新する。確認のクリックで対象指定や出札を起こさない。

ホールドの誤発動を減らす目的は「時間が来たら即使用」にすると弱まる。札では掴むまでをホールド、使用は意図したドロップまたは明示ボタン、と分ける。既存の予測確認・特殊な出札条件を無断で撤廃しない。

## 連続操作への影響

操作数は提案からの机上計数で、実測ではない。窓を閉じる操作が追加で必要にならない配置を前提とする。既存設定による追加確認が必要な場合は別途数える。

| よくある用途 | 明示ボタンの経路 | 必須ホールド |
|---|---|---|
| 同じ対象へ別の札を繰り返し使用 | 札クリック→操作ボタン。対象は保持 | 0回／手 |
| 行動対象を切り替えて使用 | 対象指定ボタン→札クリック→操作ボタン | 0回／切替＋使用 |
| 札の内容を順に調べる | 調べる札をクリック | 0回 |
| 複数の敵の内容を調べる | 調べる相手をクリック | 0回。調べるだけで対象は変わらない |
| ドラッグで場へ出す | 手札をホールド→場へ運ぶ | 1回／出札 |
| 取得・編成を続ける | 現在の各ボタンを使う | 0回。ドラッグを選ぶ場合だけ保持 |

敵をホールドしてから札もホールドする操作は選べるが、標準の必須手順にしない。もし敵の対象指定ボタンが表示密度を悪化させる場合は、敵への札ドロップで対象指定と使用をまとめる案も比較できる。ただし現行は場へのドロップのみなので、これはさらに別の追加操作案であり、本提案の成立条件にしない。

## 評価する点

1. 調べるクリックで対象が変わらないことが理解しやすいか。
2. 「対象指定」ボタンと指定済みの印が、どの相手を使うかを明瞭に示すか。説明窓を毎回開閉させないか。
3. 同じ相手への反復使用、毎手の対象切替、札・相手の比較、取得編成の反復で、必須の保持待ちが増えないか。
4. 現状の札クリックは詳細だけでなく確認札の選択・予測も行う。これを出札と混同させず、ゲーム状態の確定操作は明示ボタン／意図したドロップへ残せるか。

「全操作をホールドだけにする案」は採らない方向を推奨する。待ち時間を操作数分だけ増やし、ゲームパッド等への展開時にも不利になる可能性があるため。後者は設計上の懸念であり、外部調査・実機検証で効果を測定した主張ではない。採用判断後、共通規則を各画面へ適用し、頻用経路を操作可能な状態で確認する。
