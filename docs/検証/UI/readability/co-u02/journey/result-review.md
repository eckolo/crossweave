## 再訪と調査記録の根拠

[基本設計](../../../../../確定仕様/カード探索ゲーム_基本設計.md)2.20・6.4では、繰り返す探索で同じ相手や環境の構成が変わり得ること、撤退・帰還後も得た知識を次の判断へ使うことを定めている。[探索全体の設計](../../../../../仕様案/カード探索ゲーム_探索全体の設計.md)には反復探索の価値があるが、同じ場所だけが永続的な主目的になる構成を避ける方針もある。同じ場所へ行く頻度は固定されておらず、完全クリア直後の再訪を最優先にする根拠にはしない。

調査記録では、公開`knowledge_views`の基本構成と観測した札を分ける。例として、基本構成が判明した相手では札の初期枚数を表示し、未判明の相手では観測した札だけを表示する。実際に見た札の種類から初期枚数や現在の手札を推定しない。非公開の構成・次の札・内部証拠IDは出さない。札の解放は所持や無料編成と区別する。

0.1の「遭遇済み」や対象名のみの一覧では、攻略に使う情報の構造が伝わっていなかった。今回は相手・環境と札を切り替え、対象の基本構成／観測札を開く形にした。出来事本文、関連項目への直通、報酬候補の読みやすい整形は残件。公開APIの過去の用語を含む報酬文字列を、そのまま謎の文章として常設しない。

## 検証と保存の境界

新規28項目は実Campaign＋設計所有MemoryStore、自然帰還保存と未解決の開始保存を使ったJSDOM検査。踏破後の主操作、未解決からの再挑戦、記録の公開範囲、心得の情報構造、実確定、4幅での高さ指定と窓・下書き保持を対象にした。従前の32項目は過去記録として維持し、再合格と数え直さない。

実ブラウザー描画、物理スクロール、320pxでの読みやすさ、実タッチ、IndexedDB永続保存、ユーザー受入は未確認。ブラウザーによるローカル入口の既存拒否を別経路で回避しない。会話内の画面は実API＋一時メモリー版であり、既存の実セーブ入口を置き換えない。

設計Work `20260909-design-assembly`へ本差分と保存コミットの確認・統合を依頼する。共通runtime・保存・経済・シナリオ・採用仕様・固定原本は変更しない。今回のリザルト修正で区切り、UI稼働枠を解放する。受領・正式採用・CO-U02完了を先取りしない。
