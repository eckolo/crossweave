# 0.11：実ブラウザーで残る確認

この段階までの検査は実Campaign＋MemoryStore＋JSDOM。実IndexedDBの永続化、実際の描画・指操作を通過したとは扱わない。作業環境の正規Browserではローカル入口が`ERR_BLOCKED_BY_CLIENT`となったため、別ポート・別ブラウザー・ファイルURL・新しいホストへの迂回はしていない。以下はユーザーが自身の通常ブラウザーで確認する手順。

## 起動

手元にこの枝がある場合は、そのリポジトリのルートでHTTPサーバーを起動する。既存の作業に触れず確認用コピーを作る場合：

```sh
git clone --single-branch --branch ui/readability-20260910 https://github.com/eckolo/crossweave.git crossweave-ui-check
cd crossweave-ui-check
python -m http.server 8000 --bind 127.0.0.1
```

ブラウザーで以下を開く。distとアイコンは同梱済みで、追加のビルド・パッケージ取得は不要。

- 保存検査：`http://127.0.0.1:8000/docs/検証/UI/readability/co-u02/browser-check.html`
- ゲーム：`http://127.0.0.1:8000/docs/検証/UI/readability/co-u02/index.html`

検査ページの「検査を開始」は設計所有`test/runtime/browser-smoke.mjs`をそのまま使い、専用データベースへ毎回一意の検査保存を作る。新規作成、再開、出発、同要求再送、複数controllerの競合、帰還、空枠への読込み、帰還確定の8項目。結果JSONをそのまま返信できる。検査用保存の削除・ゲーム保存の初期化機能は追加していない。

## ゲーム画面での確認

1. 保存がなければ「はじめから」、あれば「続きから」。有効な札組へ編集して「確定」。ページを閉じ、同じURLを開いて「続きから」。追加の手動保存なしで確定した札組が残るか。
2. 札組を1枚外して確定せずに開き直すと、最後に保存した編成へ戻るか。編集中の書出しも最後の保存内容であり、未確定の編集を自動確定・保存しない。旧版で既に保存済みの変更案は互換動作として復元する。
3. 「出発」して探索中にメニューの「探索を中断」を押す。「続きから」で同じ場面へ戻り、中央に「再開×」が残らないか。ページを閉じた後も同じURLから同じ探索へ戻れるか。拠点・編成・帰還では探索中断を表示しない。
4. 保存データからの書出しがファイルになるか。読み込むには空の保存先が必要で、既存保存への上書きはしない。既存保存がある環境を消して確認する必要はない。
5. 幅1024／736／600／320pxで、主画面は16:9のまま収まるか。一覧の最終ページ、詳細末尾、確定ボタンまで届くか。窓・変更案を開いて幅を変えても保持されるか。探索の対象選択・長押し詳細・横送り・ドラッグが意図通りか。

戻してほしい判断は次の3点のみ。

- 画面内に収まり、主要操作が使えるか。
- 編成→比較→確定、帰還→拠点→次の出発が分かるか。
- 現在／変更案／確定後の着想・所持・装備を区別できるか。

問題があれば「画面名・直前にした操作・表示幅」と、保存検査の結果を添える。会話内の操作画面は一時メモリーなので、閉じた後の保存確認には使わない。

## 設計側に残る条件

山札の種類別残数、過去の本文一覧、探索中の主体と調査記録を結ぶ公開キー、過去の使用札名、身構・機転・攪乱すべての解決後予測は現公開情報だけでは不足する。常時軽減を身構へ統一する案も[0.11の依頼](exploration-save.md)へ記録した。UI側で私的saveや名前から推測せず、設計へ公開契約を依頼する。購入・修飾・変換・取得個体はD03待ち。これらの担当作業や、全30画面・最終素材の制作をユーザーに代行してもらう意図ではない。
