操作数だけの最小化を目的にしない。帰還から編成までの移動は従来案の1操作から2操作（拠点へ→札組／心得）に変更する。分かりやすさを優先したユーザーの明示指摘によるもの。札組↔心得の切替と共通下書きは維持する。

## 窓内から次を開く共通規則

1. 選択先の見出しと先頭を直ちに見せる。一覧の末尾へ追記するアコーディオンを標準にしない。
2. 親一覧＋詳細面の2面まで。さらに選択した内容は詳細面を置換する。多段の窓を無制限に重ねない。
3. 詳細面には「戻る」と全体を閉じる操作を置く。戻ると直前の対象・分類・閲覧位置を復元する。
4. 幅がある場合は2面を並べる。窓幅620px以下では親一覧を隠して詳細面を表示し、戻ると同じ一覧へ復帰。DOMをページ末尾へスクロールさせない。
5. 新しい対象は先頭から、同じ内容の再描画・resizeは位置保持。phase等の大きな進行が変われば参照文脈を破棄する。下書き・本体データはこの破棄に含めない。

今回は調査記録でこの規則を実装。探索の共通詳細窓も対象を切り替えたら先頭に戻す。同じ対象の応答更新では位置を保持する。今後追加する所持・候補等の多段参照にも適用する設計規則であり、それらの未実装機能の完了を意味しない。

16:9の外枠・固定操作帯を維持。主画面全体を縦スクロールさせず、小窓の本文だけにスクロールを置く。320pxでは主体の絵と行動予約帯を省き、主体名・残量・4値を優先する。本人は下部に固定した2行。相手が多数の時は帯の横送りで各主体へ到達する。全主体が狭幅でも同時に画面へ入る保証ではない。

## 本文記録と接続境界

短い追加段落を初期DOMへ含めることと、既読にすることを分離する。現在場面のtext_ids／optional_text_idsに属し、IntersectionObserverが可視と報告した段落だけを`continue_scene`の`advance:false`へ送る。未表示の末尾、別の場面、表示可能なだけの任意IDを一括送信しない。

実Campaign、公開view／legal_actions／previewAction／execute、既存session、設計所有MemoryStoreを継承。正式UI-R-002 v0.15・旧UI-F/G・PT-Z/PT-NT、runtime、シナリオ、保存装置、経済は無変更。実IndexedDBは未確認。D03待ちの購入・修飾・変換は未対応理由を表示し、候補なしや所持なしとして代用しない。
