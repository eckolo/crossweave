# 取得可能の空状態（UI0.15.1）

2026-09-26。Work `20260910-ui-readability`／`ui/readability-20260910`。

## 表示の整理

「取得可能／所持／編成」の役割と位置は固定する。見出しを「取得済み」へ変えると所持と役割が重なるため、取得が終了した時は左欄を空にして短い状態表示を置く。取得した個体は中央の所持または右の編成へ残る。

| 状態 | 取得可能の欄 | 所持・編成 |
|---|---|---|
| 取得前 | 候補と費用、取得操作 | 従来通り |
| 取得予定・支払前 | 移動元の印を保持。取消で候補へ戻せる | 仮の輪郭・時計印を保持 |
| 1群1点の取得確定後 | 候補をすべて除き、件数0・チェック印・「今回の取得は完了」。下端は「取得済み 1 / 1」 | 取得した個体を通常の所持・編成として表示。編成・取り外しも可能 |
| 候補なし | 件数0・空トレー印・「取得できる札はありません」／「取得できる心得はありません」。下端は「取得候補なし」 | 所持・編成とその操作を維持 |

取得済みの跡や未選択の候補を無効ボタン付きで残さず、両分類で同じ候補群の終了を反映する。編成だけの確定では候補を消さない。支払前の予定追加・制約違反による確定失敗も取得完了にしない。

空状態でも幅376px・三領域・共通枠352×80pxを維持し、中央と右の位置を動かさない。短い状態文はボタンではなく、操作できそうな偽の札枠も置かない。メニュー・調査記録は右上、戻るは左上のまま。

## 成果なしと候補なし

現行の [offers.mjs](../../../../../../src/runtime/offers.mjs) は、持ち帰った成果がない時には新しい候補群を作らず、前の群を保持する。未取得候補が残っていれば、成果なしで帰還しても空にならない。候補がもともとない場合、または表示中の群を取得済みの場合に空となる。

同実装の `purchase` は1群からの再取得を拒否し、[preparation.mjs](../../../../../../src/runtime/preparation.mjs) は取得済み群の全候補を `available:false` として返す。今回の表示は既存の制限に合わせたもの。取得上限・価格・持越し規則は変更しない。
