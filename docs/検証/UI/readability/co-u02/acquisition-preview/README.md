## 分類と置き場

旧「取得」タブは、札と心得の入手候補をまとめて選ぶための画面だった。物の種類と操作を同じナビゲーションへ混在させたため廃止する。主分類は「札」「心得」の2つとし、各分類に次の置き場を同時に表示する。

| 置き場 | 表示構造 | 含める物 |
|---|---|---|
| 左の候補棚 | 棚板の上に並ぶ札。費用を札の表面へ表示 | 今回選べる未取得の札・心得 |
| 中央の手元 | トレーと重なった札の形。複数枚は数量を表示 | 所持・取得予定のうち編成していない分 |
| 右の編成枠 | 枠に収まった札とチェック印。札枚数／心得容量を表示 | 編成に入れた分 |

同じ1個を手元と編成へ重複表示しない。「選ぶ」「入れる」「外す」「やめる」で置き場が変わる。移動先が別ページならそのページを表示する。移動を追える短いアニメーションを設け、動きを減らす設定では止める。動きの実描画と見やすさは未確認。

未払いの物は、手元・編成のどちらにあっても点線の輪郭、斜線、時計印を保つ。確定すると通常の輪郭へ変わる。着想は現在値と支払後の値を矢印でつなぐ。「取得予定」「未確定」等の説明文を各札へ繰り返さない。読み上げ用には対象と状態を残す。

## 動かせる操作

| 操作 | 配置と結果 |
|---|---|
| 選ぶ | 候補の直下。未払いのまま手元へ移る。正式所持・実残高は変わらない |
| 入れる | 手元の札の直下。同じ個体が編成へ移る |
| 外す | 編成された札の直下。同じ個体が手元へ戻る。取得予定と費用は残る |
| やめる | 未払いの札の直下。その予定分だけ候補へ戻す。既存の所持品には作用しない |
| 戻す | 画面全体の下端。取得予定と編成の変更をまとめて最後の確定状態へ戻す |
| 確認する | 画面全体の下端。支払いと、取得先・編成の差分を表示する |
| 確定する | 確認窓の下端。隣に費用を置き、制約を満たすと支払い・正式取得・編成を一括反映する |
| やり直す | 操作案の外側。確認用の固定入力へ戻す |

対象と費用はボタンの外へ置く。詳細は札の表面から開き、操作を窓下端に固定する。札・心得の切替、詳細の開閉で未確定内容を失わない。確定後も無料で編成を出し入れでき、所持は残る。

16:9固定とし、ゲーム全体は縦スクロールさせない。各置き場をページ切替し、狭幅でも3つの置き場を同時に残す。狭幅では見出しから置き場の一覧を開き、札の表面から詳細へ進める。詳細・確認窓は本文だけスクロールし、操作を固定する。

## ユーザー確認事項

最初は見出しや説明を読まず、どこが候補・手元・編成かを見分けられるか、時計付きの札が仮の取得だと伝わるかを確認してもらう。

1. 候補を「選ぶ」→「入れる」→「外す」と動かし、同じ物を追えるかを見る。
2. 未払いの札の「やめる」で候補へ戻るか、編成の「外す」と混同しないかを見る。
3. 札を1枚入れたら既存の1枚を外して12枚に戻し、「確認する」→「確定する」。位置を保ちながら時計・仮の輪郭が外れ、着想が変わることを見る。

方式の再承認、価格の良否、本編の通し試遊を求める確認ではない。文字を短くした結果、作用範囲が分からなくなった箇所も修正対象とする。

## 入力・実装の根拠と制限

- 参照設計：`7565afca98684186705a4e865d4fdf0e0ae489c1`。札・心得の名称、修飾、効果説明、札12枚・同種2枚・心得枠8は `m1.mjs` と共通の `blueprint`／`cardDetail`／`passiveDetail` から生成する。共通実装は編集していない。
- 修飾の組合せは共通検証を通す。作成途中で不適合・未定義の修飾を指定した入力は検証に拒否され、許可された修飾へ訂正した。最終入力は生成・検査とも成功。
- 開始残高6、候補価格4・8、初期所持の数量、既に所持している心得3個は確認用の固定値。二段階方式採用後の価格・配布を決める成果ではない。
- 一つの提示候補群から1点取得する既存の条件を維持する。確定後に他の候補も試す際は、確認用の「やり直す」で戻す。
- 初期からの無料利用権と所持個体を分けず、画面では全てを数量付きの所持品として扱う。これは新しい方式のUI案であり、既存セーブを実際に移行した結果ではない。
- 所持・予定・編成の一時状態は本UI案内で閉じる。共通経済の代替実装として本番へ統合しない。正式接続は設計Workが用意する統一した取得・編成APIへ置き換える。
