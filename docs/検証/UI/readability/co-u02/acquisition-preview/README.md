## 分類と置き場

旧「取得」タブは、札と心得の入手候補をまとめて選ぶための画面だった。物の種類と操作を同じナビゲーションへ混在させたため廃止する。主分類は「札」「心得」の2つとし、各分類に次の置き場を同時に表示する。

| 置き場 | 表示構造 | 含める物 |
|---|---|---|
| 上段の候補棚 | 棚板の上に並ぶ札。費用を札の表面へ表示 | 今回選べる未取得の札・心得 |
| 中段の手元 | トレーに並ぶ札。複数枚は数量を表示 | 所持・取得予定のうち編成していない分 |
| 下段の編成枠 | 枠に収まった札とチェック印。札枚数／心得容量を表示 | 編成に入れた分 |

同じ1個を手元と編成へ重複表示しない。取得・編成・取り外し・取消で置き場が変わる。移動先が一覧の表示範囲外なら、その物が見える所までスクロールする。未払いの物は点線・斜線・時計印を保ち、確定で通常の輪郭へ変わる。色や説明文だけに依存しない。

## 横長の共通枠

- 全ての札・心得を **212×48px** に統一。前版128×112pxから横長にし、置き場・未払い／正式取得・移動中で寸法を変えない。枠線は全て2px。
- 名称は幅156px、12pxの文字、14pxの行高×2行。全角26文字分の設計容量で、保存済み調査の最長25文字に対応する。[name-metrics.json](name-metrics.json) を現寸法で更新した。共通データ370組合せに変更なし。最長名称の心得候補は継承する。
- 名称28px高＋補助値12px＋上下余白4px＝本文44px。主要操作を44×44pxで右端に並べる。枠線4pxを含め高さ48px。文字を小さくせず、縦積みだった操作帯を横へ移して高さを減らした。
- 一覧は主要操作「取得」「編成」「外す」を右端へ配置。「取消」は詳細の操作部、または候補棚へ戻すドラッグで行える。二段階方式や取消の作用範囲は変えない。
- 少数の物を領域全体へ引き伸ばさない。枠の寸法と、中に並ぶ件数に必要な領域の寸法を分ける。文字の収まりはCSS寸法による計算であり、フォントの実描画は未確認。

## 表示容量とスクロール

標準幅では候補・手元・編成を上・中・下の横長の段へ配置し、各一覧で画面幅を使う。見出しは段の左端に置く。縦いっぱいの候補欄に大きな空きが残る配分をやめ、手元へ表示面積を回す。候補の実件数と編成枠に必要な行を確保し、残りを手元へ配分する。

**1024×576pxでは、候補4件・手元20種類・編成12枚を同時表示できる設計容量**とする。4列、候補1行・手元5行・編成3行。長く続く横スクロールにせず、横へ折り返して並べ、収まらない場合だけ各一覧を縦へスクロールする。全項目をDOMへ残し、ページ送り・表示件数の切捨てはしない。

この件数はUIの検証目標で、通常プレイの最大所持数を決める仕様ではない。

- 現行M1の到達可能Tier Iは候補2〜4件、1候補群からの購入は1点、札組は12枚。根拠は `src/content/economy.mjs` と `m1.mjs`。
- `runtime/offers.mjs` の所持・購入には総所持数の上限がない。長期プレイの所持数分布は未計測のため、全進行段階で無スクロールとは断定しない。
- 手元の同じ性能・同じ取得段階の複数枚は従来どおり数量付きでまとめる。「20種類」は20個の表示枠を意味し、修飾が違う物は別枠として数える。
- 幅が狭い場合や蓄積数が容量を超えた場合はスクロールを残す。640px未満では3領域の横並びと盤面内横スクロールを維持し、物自体の寸法を変えない。

## 動かせる操作

| 操作 | 配置と結果 |
|---|---|
| 取得 | 候補の右端。未払いのまま手元へ移る。正式所持・実残高は変わらない |
| 編成 | 手元の札の右端。同じ個体が編成へ移る |
| 外す | 編成された札の右端。同じ個体が手元へ戻る。取得予定と費用は残る |
| 取消 | 未払いの札の詳細下端、または候補棚へ戻すドラッグ。その予定分だけ候補へ戻す。既存の所持品には作用しない |
| 戻す | 画面全体の下端。取得予定と編成の変更をまとめて最後の確定状態へ戻す |
| 確認する | 画面全体の下端。支払いと、取得先・編成の差分を表示する |
| 確定する | 確認窓の下端。隣に費用を置き、制約を満たすと支払い・正式取得・編成を一括反映する |
| やり直す | 操作案の外側。確認用の固定入力とスクロール位置へ戻す |

対象と費用はボタンの外へ置く。詳細は札の表面から開き、操作を窓下端に固定する。札・心得の切替、詳細の開閉で未確定内容を失わない。確定後も無料で編成を出し入れでき、所持は残る。

## ドラッグとスクロール

探索画面と同じ、**220ms保持して移動／保持前のスワイプはスクロール／短いタップは詳細**の分け方を使う。ボタンからの操作も維持する。

| 移動元 → 移動先 | 結果 |
|---|---|
| 候補 → 手元 | 未払いで取得 |
| 候補 → 編成 | 未払いの取得と編成を一緒に反映 |
| 手元 → 編成 | 編成 |
| 編成 → 手元 | 外す。取得予定・所持は保持 |
| 未払いの物 → 候補 | 取得取消。予定分の編成も外す |
| 正式所持の物 → 候補 | 移動不可。売却・返還・削除にならない |
| 同じ領域、領域外、中断 | 内容を変えない |

ドロップ可能な領域を枠と操作名で示す。保持中に一覧の端へ寄せると自動スクロールする。移動後の余分なクリックで詳細を開かない。Esc、ポインター取消、capture喪失、フォーカス喪失、別ポインター、表示サイズ変更で移動を中断する。

ページ送りは廃止し、全ての物を同じ大きさで詰めて並べる。余白ドラッグ、保持前のスワイプ、ホイール、一覧内での上下左右キー、通常のスクロールバーで連続スクロールできる。分類切替・詳細の開閉で位置を保持する。

16:9固定とし、ゲーム全体は縦スクロールさせない。詳細・確認窓は本文だけスクロールし、操作を下端に固定する。初期の候補・手元・札組、および上記の容量確認用ケースを配置計算とDOMで確認した。実ブラウザーの表示幅・文字の収まり・操作感は確認を残す。

## 入力・実装の根拠と制限

- 参照設計：`7565afca98684186705a4e865d4fdf0e0ae489c1`。札・心得の名称、修飾、効果説明、札12枚・同種2枚・心得枠8は `m1.mjs` と共通の `blueprint`／`cardDetail`／`passiveDetail` から生成する。共通実装は編集していない。
- 修飾の組合せは共通検証を通す。作成途中で不適合・未定義の修飾を指定した入力は検証に拒否され、許可された修飾へ訂正した。最終入力は生成・検査とも成功。
- 開始残高6、候補価格4・8、初期所持の数量、既に所持している心得3個は確認用の固定値。二段階方式採用後の価格・配布を決める成果ではない。
- 一つの提示候補群から1点取得する既存の条件を維持する。確定後に他の候補も試す際は、確認用の「やり直す」で戻す。
- 初期からの無料利用権と所持個体を分けず、画面では全てを数量付きの所持品として扱う。これは新しい方式のUI案であり、既存セーブを実際に移行した結果ではない。
- 所持・予定・編成の一時状態は本UI案内で閉じる。共通経済の代替実装として本番へ統合しない。正式接続は設計Workが用意する統一した取得・編成APIへ置き換える。
