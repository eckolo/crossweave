## 公開情報からの接続

| 操作・表示 | 接続先・結果 |
|---|---|
| 取得可能／所持／編成 | `home.acquisition`／`owned`、公開`blueprint.key`による同性能の表示集約、個体`id`。送信には実個体IDのみ使う |
| 取得予定・ドラッグ | `draft.plan.acquire`と、公開された`pending_selection_id`。編成・外す・取消は同じplanの編集 |
| 予測・確認 | `previewPreparation`。金額・残高・枠使用・拒否理由は公開比較結果。無効な札組をUIで補充しない |
| 一括確定 | 確認した同じplan／revision／tokenで`commit_preparation`。保存成功／replayed後だけview全体を更新 |
| 失敗・再送 | 変更案と現在値を保持。同じ意味の再送は同じrequest_id。応答喪失後のreplayedも二重支払なし |
| 失効 | 古い案のまま停止。「読み直す」で明示的に現在へ戻し、再選択・再確認。新tokenだけを古いIDへ付け替えない |
| 戻す | 通常の画面内編集は現在の確定編成へ戻す。保存済みdraftだけ`discard_draft`を使う |
| 移行旧案 | 要再確認を表示。「組み直す」は新契約の未確定案を作り、「確認する」→「確定する」で保存。「戻す」は確定編成へ復帰。自動返金・自動決済なし |
| 出発 | 未確定／保存待ち／失効を遮断。確定後は最新capabilitiesと編成に従って実`depart`。確認用ローカル確定による遮断を本編経路から除去 |

帰還群の取得済みと取得可能全体の空を分ける。別の群に候補があれば取得可能へ残り、帰還分は下帯のチェックで取得済みを示す。分類内が空なら「今回の取得は完了」または候補なしを表示する。成果なし帰還でも公開された持越し群は残す。ロード・失敗は空所持／候補なしへ変換しない。

初期／後日／修飾付きで編成操作を分けない。追加習得、忘れる、習得費返還、UI独自の支払はない。確定後の公開ハンドルへ更新し、pending個体の名前からIDを推測しない。探索中は非公開の`home`を参照せず、戻った時に新しい公開状態で同じ部品を更新する。

通常入口は `docs/検証/UI/readability/co-u02/index.html`。リポジトリの同一originから開き、`entry.mjs`が設計所有のCampaignを使用する。開始／再開／ファイル読込み → 探索先の左上「編成」 → 札／心得 → 取得・編成 → 確認 → 確定 → 戻る → 出発。確定と出発の保存は共通CampaignのIndexedDB経路へ接続済みだが、実IndexedDBの動作確認は未実施。

- 「本編：はじめから／続きから」：自然開始。着想0・元の初期所持から。開き直して続きから選ぶと同じ一時保存を再開する。
- 「確認用：帰還後（自然初回）」：D03R公開の自然初回帰還。着想3。高額候補が買えない場合も公開値のまま。
