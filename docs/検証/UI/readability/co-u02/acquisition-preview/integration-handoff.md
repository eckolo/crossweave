## 提供済みの仕組みと今回の差分

旧D03のUI接続は[CO-U02-B](../u02b/README.md)で完了している。以下はその再実施ではなく、採用された新方式との差分。

| 論点 | 提供済みの実装 | 新方式への接続条件 |
|---|---|---|
| 支払前の確認 | `Campaign.previewPreparation` → `preparation.preview`。状態のコピーで購入・編成結果を計算 | この読取専用経路を利用する。未払い取得・編成・取り外し・取消のたびに実残高や保存を変えない |
| 一括確定 | `commit_preparation` が同じ計算を再実行し、結果をまとめて保存 | 再利用する。UIから購入・習得・編成の個別命令を順次発行して確定を代替しない |
| 初期所持と取得個体 | `items.resolve` は `base:` と `owned:` を区別。無料利用権と在庫個体が別 | 入手経路による操作の違いを解消できる公開所持一覧・数量・選択用識別子が必要。UIが無料利用権を仮の所持個体へ水増ししない |
| 心得の利用 | 所持していても `profile.learned` に種類がないと編成不可。`owned_but_base_not_learned` を返す | 正式取得した心得を、追加の種類習得なしで編成できること。初期所持・修飾付きも同じ規則 |
| 計画入力 | `retain_learning`、`cancel_learning`、`next_preparation.learn`、`purchase_timing` が必要 | 利用者が購入と習得の順序を選ばず、取得予定と編成だけで確認できる公開契約へ整理。互換層を残す場合も費用・権利の意味は設計側で一意にする |
| 取得予定の参照 | 既に `$purchase` が編成中の購入予定品を指せる | 取得可能一覧→所持／編成への仮移動と取消へ対応させる。現在の1群1点を増やさない |
| 費用・返還 | 取得費と種類習得費が別。習得取消で実支払額を返す | 取得前取消は未払い見積りを除くだけ。取得後に「忘れる」で習得費全回収するモデルを新UIへ持ち込まない。既存支払履歴の移行・取得価格・変換額は設計側で整合させる |
| 競合・再送 | `expected_revision`、`view_token`、`request_id` と保存失敗処理がある | 継承する。古い見積りの自動決済、二重取得、保存失敗後の見た目だけの確定を防ぐ |

根拠：[preparation.mjs](../../../../../../src/runtime/preparation.mjs)、[items.mjs](../../../../../../src/runtime/items.mjs)、[campaign.mjs](../../../../../../src/runtime/campaign.mjs)。参照時点で共通実装は未変更。「確認API・一括確定APIが存在しない」という待ち理由にはしない。

## 設計から受け取る入力

1. 共通の所持一覧、編成済み分、取得可能な物、候補群の制限。初期入手と後日入手を同じ操作へ渡せる識別子・数量を含める。表示の集約キーと個体の選択用識別子を混同しない。
2. 取得予定と編成を渡す確認／確定の契約。現在・取得後の所持と編成・支払額・残高・制約違反を公開情報として返す。心得の効果説明と編成コストも共通情報を使う。
3. 新規開始時の数量、統一取得価格、既存の無料利用権・習得履歴・個体・編成・残高を移行する規則。旧セーブの扱いと互換版を明記する。UI案の残高6・価格4/8・個数は確認用の固定入力であり、採用値ではない。
4. 既存の個体変換・ロック・候補選択との整合。新UIの「取消」を所持品の売却・返還へ転用しない。利用者に入手経路別の操作規則を覚えさせない。

具体的なフィールド名や互換APIの作り方は設計担当が既存契約との整合を決める。新APIが完成済みであるかのような名前や呼出しは追加しない。

## UI側の再開作業と完了条件

UI内識別子 `UI-ACQ-INT-01`。担当は本Work、共通管理・経済・保存移行の入力元は設計 `20260909-design-assembly`。とりまとめのCO採番を代行したものではない。

- 共通契約を受領後、操作案の固定入力とローカル確定を公開情報・確認・一括確定へ置き換える。見出しは「取得可能／所持／編成」、分類は「札／心得」。取得前の印、同じ物の寸法、横移動は維持する。
- 同じ個体を所持と編成へ重複表示せず、未払い分は仮表示とする。正式所持分を取得可能へ戻す操作は無効。UI独自の返金・価格計算・種類習得は加えない。
- 初期所持・後日取得・修飾付きの双方の種類で、取得前編成・取り外し・取消・再選択・一括確定を固定場面から確認する。制約・費用と出発時の実編成が一致することを確かめる。
- 保存失敗・古い版・再送で二重決済や途中反映がないことを、変更された経路に絞って確認する。旧検査の全再実行は目的にしない。
- 通常配布物と会話内の操作入口へ接続し、設計参照版・保存互換版・検査範囲を保存する。実IndexedDB・実ブラウザー確認は別記録とする。

画面構造のユーザー再承認は不要。現時点でUI側の要件整理と共通実装との差分照合は完了。設計Workの受領・着手・統合は未確認。探索画面のFHD調整はこの契約を待たず進められる独立タスク。
