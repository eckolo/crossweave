# CO-U02-B後の実機確認（未実施）

本手順はCO-D04／CO-P02への入力。UI0.12.0の実装・DOM確認と、実機合格を混同しない。今回の依頼B4は入口・確認記録・操作画面・本手順の提出まで。

既存の正規HTTP入口の`review/index.html`を用いる。以前の正規Browser接続は`ERR_BLOCKED_BY_CLIENT`。別ポート・別browser・file URL・新規ホストで拒否を迂回していない。許可された同一入口で実機確認できる環境から実施する。

1. `case=offers`で修飾詳細→「編成と比較」→購入前／編成後の順序、札組／心得の往復、現在・案・確定後の金額と所持を確認。`case=owned`でロック解除、変換額、最後の1点の警告、実行後の表示を確認する。
2. `case=carried`で撤退リザルト→拠点→取得の持越し、`case=return-d03`で帰還確認前の書込み禁止と資金不足を確認。これらの入口は確認用MemoryStoreで、既存セーブを書き換えない。
3. `case=explore-d03`で本人と全相手の一手後差分、場の予測、身構・攪乱詳細、履歴名、山札内訳、文章の既読／未読、主体から内容版に対応する調査記録を確認。付与札の具体場面は自然進行または設計から追加の自然保存を受け取り指定する。公開例の部品試験を自然進行としない。
4. 1024／736／600／320pxの16:9枠で主画面がスクロールせず、一覧末尾と確定・変換操作へ到達できること。小窓の末尾は小窓内でスクロール可。resizeで案・窓の内容を保持し、親子窓が操作元を隠し続けないこと。長押し、札の横送り、ドラッグ、取消、演出中の入力は実機で確認する。
5. 永続保存は通常入口`co-u02/index.html`へ戻して確認する。編成確定・購入・ロック・変換→再読込みとブラウザー終了後のopen、書出し→空slotへのimport、保存失敗→同request再試行、2タブで古いview→open・再選択を記録する。実IndexedDBに接続した版・オリジン・端末・セーブを固定する。

人に求める評価は、収まりと主要操作、帰還→拠点→比較・確定→再出発の理解、現在／案／確定後の金額・所持・装備の区別の3点。正式画像・演出の前後を明記する。合否は実施後に当該担当が記録し、UIから受入済みと先取りしない。
