# UI-G-001 v0.2 — 対象と結果を見せる

2026-09-15。UI Work `20260910-ui-readability`の継続。CO-U02の準備描画へのユーザー指摘対応。検討版であり、ユーザー受入・正式採用は未了。

## 受領した問題

取り消し・購入・習得・取得といった語を並べても、何を対象にして何が起きるか分からない。「修正する」は実際には窓を閉じる操作で、「次の準備へ」も行き先を示していない。用語の統一を理由に同じ語を画面中へ繰り返さず、語を極力減らす方針を受領した。

用語集や常設説明を増やす対応にはしない。対象名・個数・価格・変更前後を先に示し、操作に必要な動詞と影響だけをその場に置く。既存の制度や用語の正式な名称変更ではなく、UI上の表現と導線を見直す。

## 変更

| 対象 | 今回の表示・動作 |
|---|---|
| 帰還の取り直し | 「心得を選び直す」で一覧だけを開く。全心得を自動で取消対象にしない。個別に「忘れる」を選ぶ |
| 帰還からの遷移 | 「札を組む」と行き先を示す。ack_return後、新viewに基礎IDの取消意図だけを再投影し、まだ確定しない |
| 心得 | 覚えているものと覚えられるものを分ける。選択中の対象に「覚える／忘れる」、詳細に装備への影響を示す |
| 買い物 | 品名・価格・1枚／1個と「買う予定にする」を同じ詳細へ置く。選択だけでは支払・所持増加・自動装備をしない |
| 変更の確認 | 抽象的な取消・購入・習得の帳簿を、忘れる心得名、増える品物名、戻る／支払う着想、外れる装備名へ置き換える |
| 金額 | 現在と変更後を並べる。0の支出・返還行、常設の既払額、取消直後の中間残額を外す |
| 所持・装備 | 名前のない小アイコン列を、名前と個数を伴う一覧へ変更。買っただけで持参しない場合を区別する |
| 窓を閉じる | 「修正する」を使わず「閉じる」。閉じても下書きを戻さない |
| 支払い順 | 買う品と新たに覚える心得の両方を選んだ場合だけ、折りたたんだ「支払いの順番」を出す。選択肢は実際の対象名。「習得→取得」の用語列は出さない |
| 待ち・未対応 | D03の未対応理由を維持。品物なし・資金不足へ置き換えない |

`preparation-render.js`は公開viewとcomparisonだけを描画する。準備のイベントと非同期境界は`preparation.template.js`／既存`session.js`を使用する。経済・保存・シナリオ原本を変更せず、支払い順の内部値と明示planも維持する。単に語を隠して操作を削る対応にはしない。

旧`co-u01` v0.1.1、正式探索UI-R-002 v0.15、UI-F、PT-Z/PT-NTは原本のまま。v0.1.1のコンテナ基準・一覧スクロール・窓配置を引き続き使用する。
