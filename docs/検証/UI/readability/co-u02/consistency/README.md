## 共通の考え方

**一覧で状態を見分け、名前から詳細を読み、下端の操作で変更する。**
画面ごとにカードの読み方や操作位置を変えない。アイコンは名前の横に小さく置く。件数によってカードを縦に引き伸ばさない。

| 画面 | 決めること | 一覧に出す状態 | 主な操作 |
| --- | --- | --- | --- |
| 札組 | 持ち込む札と枚数 | 現在の枚数 → 変更案の枚数 | ＋／− |
| 心得 | 覚える能力、装備する心得 | 習得済み・装備中と変更予定を区別 | 覚えるだけ／覚えて装備、装備／外す |
| 購入 | 探索成果の候補から入手する1点 | 価格、購入済み、購入予定 | 購入／編成と比較 |
| 所持 | 入手した個体を残すか | 使用中、保護中、変更対象 | 保護／着想に変える |

- 心得の習得は基礎の能力を覚えること。修飾付き心得の購入は個体を入手すること。購入だけでは習得・装備されない。
- 心得画面で「すべて／習得済み／装備中」を切り替える。後二者は確定済みの現在を基準とし、一覧内に変更予定も示す。
- 札組・心得の編集は変更案。共通の「比較」「確定」で反映する。直接の購入・所持品の変換は確認窓から実行する。
- 保護は着想への変換を防ぐ。着想に変えると個体が失われる。最後の修飾個体が失われる警告は確認窓に残す。

## 説明と窓

- 公開された説明を「条件：」「効果：」「対象：」「持続：」「性質：」に分ける。必要な項目だけ出す。複数の条件・効果は一項目ずつ改行する。
- 区切りと用語の整形だけを行う。公開されていない条件・効果を名前やIDから補完しない。数値・費用・資格・計算はCampaignから受け取る。
- 窓の寸法は画面サイズと窓数から決める。押した場所は位置だけに反映し、大きさを変えない。二枚の窓は同寸法で並べる。
- 上端の閉じる操作と下端の変更操作を確保する。スクロールは説明部分に限定する。拠点メニューはページで切り替え、末尾の操作をスクロールの先へ送らない。
- 本画面は16:9を維持し、縦スクロールしない。320／600／736／1024pxのレイアウト計算を確認する。

## 本人の次回予約

公開予測の `next_self_reservation` を行動予約の列へ挿入する。現在の本人の予約から矢印で区別し、本人の次回を「次」と表示する。同時刻は同じグループに置き、未公開の同時刻処理順を推定しない。退場が公開された相手は除く。

これは現在の他者の予約との比較であり、途中の行動を解決した未来の全手番ではない。狭い画面では予測ボタン内に「本人→予約位置」を出す。同時刻は位置の範囲で示す。詳しい制約は遊び方に置く。画面を短い但し書きで埋めない。

## 確認結果

- [対象検査](checks.json)：67件。実Campaign＋設計MemoryStore、Node24.19.0／JSDOM26.1.0。
- [会話内実行](inline-checks.json)：10件。自然保存のSHA-256照合、習得のみの確定、実購入、直接の場面切替、探索の一手。外部通信・実IndexedDBの利用なし。
- 1024／736／600／320px：一覧の全項目への到達、端／中央の窓寸法、親子窓の同寸法・非重複、resize時の窓・下書き保持を検査。矩形は検査入力であり、実フォントの改行やブラウザーのピクセル描画を測った結果ではない。
- 会話内の初期状態は「心得・習得と装備」。D03自然保存をそのままimportし、公開commit_preparationで2種を習得・1種を装備したもの。所持金の増設や保存の書換えはしていない。
- runtime・保存装置・経済・シナリオ・固定UI原本は不変。旧検査の全通し再実行はしていない。

実描画・タッチ・実IndexedDBは未確認。前のローカルURLに対するBrowserの `ERR_BLOCKED_BY_CLIENT` を別URL・別経路で回避していない。会話内は実API＋一時保存で、永続セーブ合格とは扱わない。
