# CO-U01 — 準備・成長・取得の操作試作

UI-G-001 v0.1／2026-09-14（日本時間）。UI Work `20260910-ui-readability`。

**準備を中心に、必要な変更だけ選び、比較してから確定する案。** 帰還から直接準備へ入り、札組・心得・所持・取得を下の帯で切り替える。選択元を左、今回の構成と変更案を右に置き、全機能の巡回を必須にしない。

今回は**CO-U01の模擬応答による操作試作を提出する単位**。UI-F-001 v0.1の構成方針を継承し、新しいIDと入力へ分けた。実API・永続保存・探索への接続はCO-U02。探索の正式参照版UI-R-002 v0.15、旧UI-F、PT-Z／PT-NTの固定原本は維持する。新画面の正式採用・人の評価は未了。

## 入口と操作

- [操作版 preview.html](preview.html)：取得してブラウザーで開く。GitHubのソース表示上では動作しない。通信不要。
- 会話内の入口も同じソースから生成。枠外の「操作試作・模擬応答」「入力」「確認用」は検証専用で、ゲーム内の導線には含めない。
- 初期はBCの精算済み帰還例。「次の準備へ」から進む。帰還の再表示は獲得額を再加算しない。
- 札をクリックして詳細を開く。再クリック、窓の外、Escで閉じる。マウスでは180msの一時表示、クリックでピン留め。小さい操作は選んだ札の詳細内に集める。
- 初期札と所持札を分ける。購入予定は破線の別枠で、未取得のまま札組への追加を比較できる。追加・装備は本人の別操作。
- 心得は習得／所持／装備を分ける。習得取消で外れる装備と、残る所持個体は比較に表示する。「取消を戻す」だけでは装備を自動復帰させない。
- 「下書きを保存」は模擬controllerの下書きだけを保持。「比較」→「変更を確定」で初めて模擬応答上の資源・所持・装備・札組を更新する。ページを閉じた後の保持は未接続。
- 所持品の「変換」は別の見積と確定。未保存の下書きがある場合は、先に下書きを保存して個体を選び直す。使用中や保護中なら拒否理由を表示する。

### 最初に確かめる一続きの例

1. BC帰還から「次の準備へ」。現在は未使用3、既払2、所持5。
2. 心得→属性連携→「習得を取り消す」。これは取消予定で、現在額は3のまま。
3. 取得→軽い踏ん張り→「購入予定にする」。選んだだけでは所持に増えない。
4. 札組で沈み石の槌を1枚外し、購入予定の軽い踏ん張りを1枚加える。
5. 比較で返還+2、取消後5、購入−4、確定後1、装備3→0、所持5→6を確認する。
6. 「変更を確定」。成功後の新しい応答で所持6・残額1を読む。
7. 所持から未使用・未保護の基礎「借り札の守り」を選び、変換見積+0.5→確定。残額1.5、所持5。

取得を見送れば元候補を維持し、そのまま準備を続けられる。心得取消と別の基礎心得の習得・装備だけを選び、購入なしで確定することもできる。初期の資金不足を解消するために報酬を上乗せしていない。

## 画面構成と常時表示

| 領域 | 常時出すもの | 必要な時に出すもの |
|---|---|---|
| 上の細い帯 | 現在の未使用着想、既払額、現在地 | 内部版・制御情報はゲーム画面に出さない |
| 左の広い領域 | 今開いている札組／心得／所持／取得の一覧 | 個別の効果・修飾・価格・操作は詳細窓。全一覧を同時に並べない |
| 右の準備欄 | 選んだ札の小さな一覧、枚数、装備と容量 | 変更時だけ返還予定・支出予定・確定後額。細かな内訳は比較窓 |
| 下の帯 | 札組・心得・所持・取得、手持ち枚数 | 操作説明や仕様の長文を置かない |
| 帰還 | 精算済みの獲得、喪失、種類解放、未使用／既払 | 心得取消だけの比較を任意で開く。次の準備へ直通 |

PCの基準は16:9、1024×576。通常の帯は約46px。狭い幅では一覧の列数を減らし、540px以下で準備欄を下へ送る。一覧の枚数が増えた場合は領域内をスクロールし、実測で続きがある時だけ「↓ 続き」を出す。詳細は最大345px、比較は最大660pxを使う。実描画での寸法・重なりの確認は後述の未確認範囲。

帰還での比較は基礎心得取消だけ。`ack_return`で新しい準備を受け取ってから、安定した基礎IDによる同じ取消意図を変更案へ写す。購入や所持個体を含む任意計画の帰還→home移送は、古いhandleを流用せず、接続要求U-G02へ残した。

**UI専用の補助応答**：名称・アイコン・心得の短い効果説明・修飾説明を明示した固定辞書で補う。基本札名はUI-Fの表示案、踏ん張り／溜め打ちと心得名は既存の試行呼称、修飾語はAO条件のラベルを参照。PS01「守りからの設置」等は機能を示すUI仮ラベル。正式な新名称の採用ではない。UI描画は`details[id]`を読み、blueprint.keyから名前や性能を推論するフォールバックを持たない。

## 失敗・不足時の次の操作

| 状態 | 表示と回復操作 |
|---|---|
| 空候補／前回候補保持／購入済み | 「今回の候補なし」「前回の候補」「購入済み」を分ける。準備を続けられる |
| 資金不足 | 不足額を示し、見送りか心得の取り直しへ。未使用と既払を合算しない |
| 装備不可／容量超過／札不足 | 未習得なら習得・装備外し、容量なら装備を減らす、札不足なら札組へ。下書きを失わない |
| 取消を含む比較失敗 | `draft_discarded`は計算コピーだけ。画面の取消意図・選択中の札を保持して修正 |
| 古い候補・表示 | 最新を読む。古い下書きと名称を残し、同名新候補へ付け替えない。「今の準備に戻す」を明示操作で選ぶ |
| 使用中／保護中の変換 | 準備から外して確定／保護解除後に再選択。自動で外して売らない |
| 変換価格・機能未接続 | 空所持や資金不足とは別の接続待ち。ほかの準備操作を続ける |
| 保存失敗 | 下書きと現在状態を保持し「再試行」。模擬応答だけ成功にして資源を先に変えない |
