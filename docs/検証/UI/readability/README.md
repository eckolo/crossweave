## すぐ操作する

このブランチのリポジトリルートで、Node.js標準機能だけを使って組み立てる。

組立済みの [preview.html](preview.html) も同梱。ファイルをダウンロードしてブラウザーで開ける（GitHubのコード表示画面上では動作しない）。これは下記buildから生成する閲覧用出力であり、直接編集する正本は画面テンプレートとview.js。

```sh
node docs/検証/UI/readability/build.cjs crossweave-readable.html --standalone
```

生成したファイルをブラウザーで開く。初期表示はPT-Z-001と同じ通常入口W seed32・guard5。別の構成は画面下部「出発構成・入口からやり直す」を開き、構成を選んで開始する。選択だけでは現在の探索を変更しない。

会話内で操作画面を提示するときは、その環境のvisualizeスキルを読み、次を実行して表示する。

```sh
node docs/検証/UI/readability/build.cjs /workspace/crossweave-readable.html
```

比較元は既存fixedを使う。元ファイルは変更していない。

```sh
node docs/検証/試遊/terrain-build-z/fixed/build.cjs /workspace/crossweave-ui-baseline.html
```

同じ手順を両方へ入力すると同じゲーム経過になる。比較元での途中状態や、過去のユーザー操作は自動復元しない。UIの表示を切り替えて同じ状態を共有する機能、保存再開・セーブ移植は今回追加していない。

## 操作と情報の置き場

1. 主体のHP・命中蓄積・防御を見て、必要なら常設の攻撃対象を切り替える。
2. 手札を選ぶ。対応する共有の場の枠が強調され、「場へ置く／一致して使う」と関係が文字でも示される。
3. 実行ボタン横の今回の変化を確認する。期限切れ、消滅、防御終了は折りたたまない。選択札の主効果・場効果・コストと従来の計算説明は「選択札の効果・計算を確認」にある。
4. 実行後は「直前の変化」で自分の行動と次の自分の手番までのHP・防御・退場・再構築・成果変化を確認する。「直前の行動を順に読む」には元版の経過を残す。
5. 山札は未ドロー分の用途・属性別残数を要約。「全種類の残数・属性・効果を確認」から常に全文へアクセスできる。未ドロー・手札・初期持込・消滅予定を別集計する。

詳細は[情報設計](情報設計.md)、使用条件と出所は[使用版](使用版.json)、確認範囲は[検証記録](検証記録.md)。UI実装は `play.fragment.html` と `view.js`。ゲーム演算・入力は固定版をハッシュ検証して読み込む。

## 途中の比較局面

固定入力からAIが合法な選択を行い生成した表示確認用局面。ユーザーの実操作記録ではない。`fixtures.json` に構成、開始からの正確な札ID・対象の選択列、時刻、HPを保存した。`make-fixtures.cjs` で再生成でき、数値や乱数状態の上書きはない。

```sh
node docs/検証/UI/readability/build.cjs crossweave-mixed.html mixed --standalone
```

第3引数の局面名を次のいずれかに変える。指定局面で開いた後も、そのまま手札を操作できる。画面内で入口からやり直すと、局面の自動再生は行わず新しく開始する。

| 局面名 | 構成 | 実行済みの自分の手数 | 時刻 | HP | 主な確認対象 |
|---|---|---:|---:|---:|---|
| `deadline` | guard5 | 1 | 8 | 60 | 使用しない札の期限切れが実行前に分かる |
| `guard_end` | guard5 | 3 | 30 | 60 | 現在の防御と一致による防御終了 |
| `mixed` | guard5 | 7 | 70 | 60 | 他主体由来の札と、現在山札の要約・詳細 |
| `multiple` | guard5 | 9 | 90 | 60 | 後続の環境と敵の対象切替、予約と一致の関係 |
| `vanishing` | guard5 | 9 | 90 | 60 | 退場由来・回収消滅札の警告と参照 |

通常入口の札順・構成・数値を全局面で共通にし、選択列の長さだけを変えている。前に試遊した途中HPを復元したという意味ではない。

## 試遊担当への観察依頼

使用版はUI-R-001、初回の比較は上記固定条件。PT-Z-001/F01〜F03への追加質問や、3構成全部の完走は不要。UIの人評価記録はUI-R-001として分け、使ったコミット・開始局面・取得できた操作だけを記録する。

- 札を選んだとき、対応する場と対象、今回起こる変化を追えるか。詳しく調べたいときに説明へ到達できるか。
- 混入後や一手を実行した後、現在の札の構成と重要な状態変化を見失わないか。

ゲーム理解・先読みの難しさと、表示を読む負担を区別して受け取る。ブラウザー描画の未確認事項（幅、折返し、キーボード・タッチ、配色）は[検証記録](検証記録.md)に記載。UI WorkではブラウザーのURL制限により実描画を確認できず、確認済みとは報告しない。
