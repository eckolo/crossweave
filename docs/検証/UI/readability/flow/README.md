# UI-F-001：拠点・準備・帰還の構成案

版：0.1／2026-09-13（日本時間）。担当：UI Work `20260910-ui-readability`。

**古道具屋を拠点に、依頼は窓で開き、準備と帰還は広い面積で扱う案。** [全画面のUI検討](../UI検討.md)のS03〜S06・S16を中心に具体化した。構成試作であり、画面の分け方・配置の正式採用はまだ行っていない。既存の探索画面は[正式参照版UI-R-002 v0.15](../正式参照版.md)を維持する。

## 操作する

[preview.html](preview.html)を取得してブラウザーで開く。GitHubのコード表示では操作しない。外部通信・追加素材の取得は不要。会話内は同じソースから組み立てたフラグメントを使用する。

1. 依頼の紙または下帯の「依頼」を押す。依頼の内容を読み、その窓から「準備へ」。
2. 札にマウスを置くと一時詳細、クリック／タップするとピン留めして枚数を変更できる。同じ札の再クリック、窓外、Escで閉じる。
3. 枚数が不足・超過した途中状態でも、拠点と準備を往復できる。出発は12枚が揃ったときだけ可能。
4. 「出発」は探索側へ渡す情報と接続位置を確認する。**この試作内では探索の演算・操作を行わない。** 表示される接続位置は製品に追加する確認画面ではない。
5. 枠外上部の「表示例」で踏破後・撤退後・緊急脱出後へ切り替える。帰還から「次の準備へ」、拠点、依頼、記録を確認する。

上部の表示例切替は構成確認用の操作で、ゲーム内の終了方法を選ぶ機能ではない。編成を変えても固定の帰還結果は再計算されない。表示例ごとに別の下書きを持ち、通常の画面往復で変更を失わない。試作を閉じた後の永続保存は今回の対象外。

## 画面を分ける方針

| 場所 | 構成案 | この置き方にした理由 |
|---|---|---|
| 拠点（S03） | 古道具屋の絵を主にし、依頼の紙と下帯の入口を置く | 毎回の戻り先を「場所」として認識できる。全機能の一覧表や数値を拠点へ常設しない |
| 依頼（S04・S05） | 拠点上の窓で場所・目的・傾向を確認し、準備へつなぐ | 詳細を見るためのページ往復を減らす。今回の素材は1依頼で、複数案件の選択・送りは次の具体化へ残す |
| 準備（S06・S07） | 広い作業面に利用可能な札を並べ、採用枚数を重ねる | 同種札を個別に何枚も展開せず、今回の構成と選択元を一緒に見られる。0枚の札も残し、追加先を別窓で探させない |
| 札詳細（S18） | 選んだ札の近くに情報と枚数変更を置く | 札の表には属性・絵・名称・枚数だけ。能力・補正・期限の文章を全札へ常設しない |
| 帰還（S16） | 持帰りを主、調査記録を隣に置き、必要な場合だけ喪失を示す | 確定した成果と知ったことを区別。踏破・撤退・緊急脱出を同じ画面の状態違いで扱う |
| 次の準備 | 帰還から直接開け、拠点へも戻れる | 成果確認のあとに拠点の同じ入口をもう一度探す手間を減らす。習得・取得等を必ず一通り開く経路にしない |

依頼の解決状態、解放された札、今回利用可能な札、編集中の枚数を分けている。踏破後の依頼を未解決の浸水へ戻さず、SCN-001の再訪案「管理用の道筋を確かめる」へ表示を分けた。再訪のゲーム内容・解放条件を採用するものではない。

心得は準備から開く入口と、初期プロフィールの「習得0・所持0・装備なし」だけを置いた。習得・返却・装備・購入・変換の配置と操作はS08〜S12の次の検討で扱う。今回の空表示で設計済みとはしない。

## 常時表示と必要時の表示

| 情報・操作 | 常時 | 必要時 |
|---|---|---|
| 場所・主な移動先 | 短い場所名、下帯の拠点・依頼・記録と主操作 | 依頼の内容は窓へ |
| 依頼 | 拠点では紙のタイトル・短い症状 | 場所、目的、傾向、相談の文。本文の重複表示を避ける |
| 準備する札 | 絵・属性・名称・採用枚数、合計、短い用途別内訳 | 効果・場の補正・期限・コスト・選択札の枚数変更 |
| 件数の増加 | 画面内で読める大きさを保持 | 一覧領域を縦に送り、下に続くときだけ矢印を表示。全件を縮小して詰め込まない |
| 余力・着想 | 下帯へ小さく表示。帰還時だけ全回復を添える | 学習・購入時の資源比較は次段階 |
| 帰還の成果 | 着想の獲得、解放された札、必要な喪失 | 札の詳細と調査の本文は個別の窓へ |
| 窓の状態 | ピン留め／一時表示を記号で表示 | 操作説明は画面案の案内へ。ゲーム内に常時手順を追加しない |

横長16:9を基本とする。通常幅の下帯は1行・約48px。760px以下では札の列数を減らし、520px以下は高さ640pxと下帯2行の仮設定で可読性を優先する。これは狭い幅向けの例外であり、通常の横長画面へ厚い帯を戻す提案ではない。札一覧と長い窓だけをスクロール対象にし、ページ全体の横はみ出しを作らない構造にした。

背景はCSSで置いた棚・窓・机の大きな形、札は仮の記号。最終の絵柄・素材の採用ではない。会話内では提供されたLucide記号、単独表示では種類別の文字記号が代替する。専用の絵へ交換できる領域として確保している。窓は背景だけを半透明にし、文字は薄くしない。

## 試遊へ接続するために渡すもの

- 出発：`model.depart()`の結果、イベント `crossweave:departure-preview`。依頼ID、表示例、再訪の区別、編成、利用可能な札を持つ。現段階は構成確認用で、製品の保存・API形式ではない。
- 帰還：`fixtures.json`の`returns`。精算結果、保持・喪失の出所、獲得量、解放、実際に見た場面を分けた入力例。画面を開くたびに精算や加算を実行しない。
- 編集：通常の画面往復は同じ下書きを参照。出発時には複製を渡し、探索側の変更で編成の下書きを壊さない。出発条件の確定判定は接続するゲーム側へ合わせる。
- 再訪：表示文の接続例のみ。PT-NT-001の一往復を周回仕様に改変しない。準備プロフィール・再訪内容をどうゲームへ接続するかは設計・シナリオ側で扱う。

配置と操作の専用差分は `screen.fragment.html`・`screen.css`・`view.js`、画面の状態は `model.cjs`。元試遊のファイルへのパッチではなく、探索外の画面を接続する別コンポーネントとして保存する。対象コミット付きの依頼は[自Work設定](../../../../作業資料/Work/20260910-ui-readability.md)末尾を参照する。

## 再生成と確認

リポジトリルートで実行する。組立はNode.js標準機能のみ。画面状態の検査にだけjsdom 26.1.0を使う。

```sh
node docs/検証/UI/readability/flow/generate-fixtures.cjs --check
node docs/検証/UI/readability/flow/build.cjs docs/検証/UI/readability/flow/preview.html --standalone
CW_JSDOM_PATH=/path/to/node_modules/jsdom node docs/検証/UI/readability/flow/verify.cjs
```

fixturesの再生成には固定コミットのGitオブジェクトが必要。足りない場合は参考の `playtest/terrain-build-z-20260909` をfetchしてから実行する。スクリプトは一時フォルダへ固定ソースを展開し、PORT保存状態のハッシュ一致を確認する。ゲームの優劣比較や全試行の再実行は行わない。

会話内の提示では、その時点のvisualizeスキル全文を読んでから、`build.cjs /workspace/<new-name>.html`でフラグメントを出す。HTMLを通常のファイルリンクで代用しない。

[確認結果](verification/checks.json)はDOM・仮時計による14項目。下書き保持、枚数不足時の出発禁止、窓を閉じるだけのクリック、終了例ごとの精算・公開情報、解放札の次の準備への反映、帰還例切替時の非加算、ホバーからピン留め、再クリックとEsc、通信なし・生成物の整合を確認した。

実ブラウザーの描画、端末ごとの操作、各幅での重なり・スクロール量、最終画像での読みやすさは未確認。既存環境のローカル表示制限を別のブラウザー経路で迂回しない。DOM検査を実機確認として扱わない。
