# CO-D03R 新旧対応と保存移行

2026-09-26。R1・R3。D03本体7671ded／完了7565afca、計画64150a31のD03R0.1、UI102b2439の了承済み方式を受領。

## 判断の区分

| 区分 | 今回の扱い |
|---|---|
| 既了承 | 札／心得の取得可能・所持・編成、初期／後日取得の同じ編成操作、未払いの確認と一括確定。正式取得した心得への追加種類習得は不要。取消は未払い見積りの除去 |
| 既存採用・維持 | 重複所持・制限内の重複利用、低効率変換、ロック、共有札循環、探索中の編成固定、持帰り／知識／案件の規則。無料の探索用札生成を変換資源にしない |
| 記録付き試行 | 初期札10種類×2個、編成12枚・同種2枚、心得容量8、基礎心得取得200units、帰還候補400units、普通品変換50units、基礎棚の在庫1、候補群1点。初期札の変換不可 |
| 正式採用は未了 | 価格・配布量・容量・基礎棚の提供方法と在庫、取得テンポ、製品バランス・面白さの評価。今回の共通実装を止める必須判断はない |

1pt=100units。UIモックの残高6・価格4/8・心得3個・20種類表示は採用しない。新規残高0、初期心得0、報酬は既存内容のまま。

## 新旧対応

| 旧保存／契約 | 新保存／契約 | 根拠・影響 |
|---|---|---|
| 初期無料札10種類の `base:` 選択権 | 各2個の実個体を `inventory` に初回だけ付与 | 旧同種上限2の全合法構築を維持。合計20個のうち12個を従来の初期札組へ割当て、残り8個は未編成。UIの仮個体ではない |
| 初期札の無料生成と無制限な再選択 | 固定個体を無料で編成・取り外し、変換不可 | 変換資源の新規付与や再移行による増殖、初期札全売却による出発不能を避ける。公開 `convertible` / 理由を利用し、UIが入手経路を判定しない |
| `profile.learned[base]` と実支払額 | 各習得種類を基礎心得1個へ付与。旧支払辞書は会計履歴として凍結 | 残高・支払済額・効果・所持済み派生品を保持。旧支出は返金せず二重請求もしない。新しい取得はこの辞書へ追加しない |
| 未習得の基礎心得を200unitsで学ぶ | 基礎棚 `basic:PS01`〜04から200unitsで1個取得 | 旧全4種類へアクセスできる経路を保持。棚由来／移行由来の現所持は各種類1個まで。変換後は再取得可。候補群由来の重複個体は別枠で従来通り可能 |
| 取得候補の個体400units＋種類習得の要件 | 同じ個体400unitsのみで直接編成可能 | 未習得時の追加200unitsと順序選択を除去。これは了承済み方向の反映。取得価格全てを同額にする意味ではなく、両経路を共通 `price_units` / 一括決済へ統一 |
| 購入済み個体UID、修飾、価値帯、ロック、売却台帳 | そのまま保持 | 追加付与分と別の来歴で検証。旧購入が新初期個体へ変化することはない |
| `base:` / `owned:` の編成、`$purchase` | 公開 `owned-N` / `pending:<取得ID>` に統一 | 集約キー `group_key` は性能ごと、選択IDは個体ごと。編成済みと未編成は同一個体の別状態 |
| 取消習得の全額返金・購入前後の順序選択 | 新planから除去。取り外し0円、取得前取消0円 | 取得済み品を手放すときだけ既存の明示的変換を使う。変換と取消を混同しない |
| 旧編集中の案 | 原案を保存内部へ退避、公開案を新参照へ写して要再確認 | 旧返金前提の案を無言で実行・破棄しない。`migration_review` がある間は確定・出発不可。ユーザーの明示的な戻す／新案確定で解消 |
| 候補群・未取得群持越し | 同じ保存台帳、同じ抽選、1群1点 | 取得済み群では候補配列を空にし `acquired` を公開。成果なし帰還は未取得群を保持。基礎棚の残在庫と帰還群の空状態を区別 |
| 探索／帰還／案件／知識／領収／乱数 | 既存情報を保持して選択参照だけ変換 | 途中の実カードの型・値・配置・効果・乱数を変更しない。engine0.1〜0.4に必要な既存D56/D57形式移行だけは既存通り |

初期配布量・基礎棚在庫・価格の差替え箇所は `src/content/acquisition.mjs`。帰還候補の価格・分布・変換率は従来の版付き入力。保存に関わる方針変更時は `CW-M1-acquisition-1` を据置きで書き換えず、互換移行と版を追加する。

## 保存互換

新形式は save2／engine0.7／economy2／acquisition1。戦闘rules0.5・内容0.2・offer0.1・修飾AO1は不変。

- save1＋engine/rules0.1〜0.4＋内容0.1、save1＋engine/rules0.5＋内容0.2、save1＋engine0.6/rules0.5＋内容0.2を受ける。旧探索内の内容版と領収の内容版は保持する。
- 旧整合性を先に検証し、D03以前は既存の候補移行を経て、D03Rの個体割当てへ進む。`preparation-legacy.mjs` は旧案検証のためのD03計算を保全したもの。新コマンドから返金APIとして使わない。
- `Campaign.open` はコピー上の移行を検査し、旧revisionとのCASで1回だけ保存。revision+1・新view_token・移行request記録を加える。2回目以降は無変更。競合時は再読込みし二重移行しない。
- `Campaign.importSave` は空スロットへの通常の1回保存で移行する。輸出元は変更せず、既存スロットを上書きしない。
- 不正／未知形式／混在版／不整合会計は理由付きで拒否。読込失敗は例外を返し、空所持や初期保存へ置換しない。保存失敗も旧保存を残す。
- 旧保存のrequest_logを保持し、旧版で完了済みの同一request_id再送は移行後も再実行しない。異なる内容で同じIDは `request_conflict`。
- `profile.learned` は新取得の権限ではなく凍結した旧会計履歴。残高＋旧支払額＝保持報酬−旧候補／新取得支出＋変換収入。古い領収の `paid_learning_units` も履歴として維持する。

[10資料の移行結果](migration-examples.json)と[代表保存](save-manifest.json)を参照。`migrated_review` は旧編集中の案が要再確認として保存された例。通常プレイヤーの自然進行、既存の固定セーブ、派生境界fixtureを区別する。
