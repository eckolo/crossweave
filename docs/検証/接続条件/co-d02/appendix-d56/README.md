# D56 — 効果別の防御と張り直し

2026-09-19 JST／Work `20260909-design-assembly`。ユーザー「張り直し方式で進めてよい」を受領。**効果別管理・同じ発生源と種類の張り直し・本人一致での共通解除を実装し、保存と公開予測まで接続した。** 全員付与の共通処理は明示試行札で確認。SCN-001への付与札の配置・供給はまだ行っていない。

## 採用と実装

- 効果ごとに身構・攪乱・残り回数を保存する。合計を別の正本として保存しない。
- 同じ使用主体・同じ効果種は新しい三値へ丸ごと置換する。同種の別札個体でも増枠しない。弱い再付与では値が下がり、各成分の旧最大値を引き継がない。
- 別発生源・別効果種は加算。有限回数は本人への合法な一致攻撃で適用後それぞれ1消費。削り0・未到達・0ダメージでも同じ。回数制限なしは消費しない。
- 本人の一致では外部分も含め旧効果全体を解除する。新しい防御はその後に付与。不一致の設置は維持する。
- 身構合計へ受け手の解決時の一閃倍率を適用。攪乱へは掛けない。機転消費はダメージ解決時の既存規則を維持する。

正式仕様は[基本設計0.56・4.6](../../../../確定仕様/カード探索ゲーム_基本設計.md#section-4-6)。D54/D55の旧結果は各時点のコードへ対応する固定履歴として保全する。

## 版と保存互換

| 対象 | 今回 |
|---|---|
| 規則／engine | `CW-M1-rules-0.3`／`CW-M1-engine-0.3` |
| 公開契約 | `CW-M1-public-0.3` |
| 保存／viewの外枠 | `CW-M1-save-1`／`CW-M1-view-1`を維持。内側は規則・engineで識別 |
| 内容 | `CW-M1-SCN001-0.1`、固定入力0.1・既存札性能・配置を維持 |
| 生成registry | `source.rule_amendments`にD55・D56を明記。元入力を書き換えない |

現在版の探索状態は`defense_rule:'D56'`、各主体の正本は`defense_effects`。一効果は次の形。`source_actor_id`は使用者であり札の元所有者ではない。`effect_kind`は効果の種類であり札個体IDではない。

```json
{"source_actor_id":"V0","effect_kind":"ward","guard":2,"evasion":10,"uses":2}
```

`uses`は1以上の整数、またはJSONの`null`（被攻撃による回数制限なし、本人一致では終了）。欠落・0・負・小数・NaN・Infinityは拒否。身構は非負整数、攪乱は既存の場補正に合わせ負も含む整数。合計の整数範囲、発生源の存在、同じ発生源・種類の重複も検査する。

既知のrules/engine **0.1同士、0.2同士**だけを変換する。旧`guard`を本人の`self_guard`一効果へ移し、値・残り回数を維持する。旧`guard:null`は空配列へ。旧guardと新配列の二重持ちは受け付けず、現在版の配列欠落を旧保存として補わない。履歴・札・乱数・領収・候補保留等は再計算しない。旧パッシブ配列も自動で札へ変換しない。

開く・inspect・previewは保存装置を書かない。exportは変換後のコピー、次の更新成功または空slotへのimportで新しい形式を保存する。新規Campaignも0.3を使う。0.3保存を旧0.2エンジンへ戻す逆変換はない。旧5保存は原本のまま残してある。

## UIへ渡すもの

| 公開場所 | 内容・使い方 |
|---|---|
| `exploration.actors[id].defense`（本人は`self`にも同じ値） | `guard`・`evasion`の合計、`effects`の公開済み内訳、`duration`、`clear_on:'owner_match'` |
| `defense.duration.all / guard / evasion` | 全効果／身構へ寄与する効果／攪乱へ寄与する効果ごとの集約。能力別は補正0の効果を除く |
| 各duration | `effect_count`、`finite_min`、`finite_max`、`unlimited`、`status`、`uniform_uses` |
| `action_preview.actor_changes[id].defense.before / after` | 今回一手の前後を共通演算で算出。UIで解除・消費・張り直しを再計算しない |
| 既存`guard` | 効果なしはnull。効果ありは`value`・`evasion`に合計。全効果が同じ有限回数の場合だけ`uses`にその回数を返す。混在・無制限は`uses:null` |
| 既存`values.guard_uses`の予測 | 前後とも単一の有限回数で表せる時だけknown。混在・無制限を含む時はunsupported／null。0や最大回数へ変換しない |

空durationはstatus=`empty`、uniform_uses=0。単一の有限回数なら`uniform`、全部無制限なら`unlimited`、それ以外は`mixed`。有限効果がなければfinite_min/maxはnull。`null`だけで意味を推測せずstatusとunlimitedを読む。量0でも残る効果はallへ含む。`guard.uses`の変更は0.3で明示した互換拡張で、UIが`??0`や最大回数への埋合せをすると不正確になる。

既存の能力差分・stance・公開履歴等は維持。新しい未知発生源が予測へ現れる場合は従来同様unknownとし、カード山札・乱数・未公開主体を漏らさない。未来のNPC行動を確定予測しない。公開応答の実例は[examples.json](examples.json)。

**常設する情報はUI全体で選ぶ。** 主体欄の長文・縮小文章、毎手の詳細窓操作を前提にしない。合計＋最大／最小／範囲などは省略を許容して実画面で比較する。全内訳を常設する要求ではない。今回UI専用原本の描画変更は0。

## 全員付与の接続と試行範囲

共通resolverは手札の`kind:'defense_support'`一致で`defense_grant:{effect_kind,guard,evasion,uses}`を使用者以外の活動主体へ付与する。自身・退場済み・後から入る主体にはその解決を遡及適用しない。札の出自でなく現在の使用者を発生源にする。不一致の設置、場の一致材料としての消費では付与しない。回収・期限・行動間隔は通常札と同じ経路を使う。

試行札は[test/runtime/d56-trial-input.json](../../../../../test/runtime/d56-trial-input.json)。身構2・攪乱10・2回、属性A・間隔10・期限2は**検査専用値**。場補正を一斉付与量へ流用しないことも試行条件。既存防御札は従来の2回と場補正を維持。将来の個別防御札は`defense_uses`で有限数またはnullを明示でき、検査では5回・無制限を使用した。

SCN-001の現在の主体は環境防御パッシブを生成していない。内容registryへ新札を登録せず、検査内のTrialGameだけが試行札を供給する。共通のplay／predict／効果保存を使うが、製品Campaignの札registry受入を済ませたという主張ではない。既存成長パッシブを廃止せず、初手からの常時付与・専用無限供給も追加しない。

**次の判断は、付与元の退場時の終了条件。** 推奨は付与済み分を残す。回数または受け手一致で終了し、退場した付与元からの更新は止まる。相手の支援を即座に消す手段にはならず、場を去った後もしばらく補正が残る。代案は付与元退場でその発生源分だけ即時解除する方式で、発生源を倒す判断が強くなる一方、共通の回数・本人一致とは別の解除条件が増える。現在の共通処理は前者を明示仮条件として検査した。採用判断前に環境札を本編へ配置しない。再付与方式の承認をこの退場条件の承認へ広げない。
