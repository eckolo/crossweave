# D57 — 防御効果の終了を受け手側へ統一

2026-09-19 JST／Work `20260909-design-assembly`。**付与元が退場しても、付与済みの防御効果は残す方式をユーザーが承認。** 通常防御は付与元と受け手が同じであり、退場時に消える理由も「受け手が退場したから」とする。CO-D02R-J01の今回の判断待ちは解消した。

## 採用した規則と修正

| 起きたこと | 受け手の防御効果 |
|---|---|
| 付与元だけが退場 | 付与済みの量・回数を維持。更新は止まる |
| 受け手への合法な一致攻撃 | 各有限効果を適用後に1回消費。無制限効果は維持【D55】 |
| 受け手が一致行動 | 本人分・外部分を含む旧効果全体を解除。新しい防御はその後付与【D56】 |
| 受け手が退場 | 由来・残り回数を問わず、その受け手の全効果を解除【D57】 |
| 受け手が不一致で設置 | 維持 |

発生源の識別は張り直しの枠・由来を覚えるために使い、存続条件には使わない。退場した主体自身が受けていた効果を消しても、その主体が別の受け手へ付与した効果まで辿って消さない。同じ解決で複数主体が退場する場合も、各受け手について解除する。

前版0.3は他者への付与を残す動作は既に持っていたが、退場した主体自身の状態にも効果配列が残っていた。`CoreGame.retire()`でその配列を空にし、現在版の保存検証も「退場済み受け手に現在効果がない」ことを確認するよう補った。受け手の帰還・探索終了から次探索へ効果を持ち越さない既存の扱いは維持し、過去の行動ログ・終了時の記録を再演算しない。

対象は今回の付与型防御効果。成長パッシブ等をこの配列へ一律変換する変更はない。正式仕様は[基本設計0.57・4.6](../../../../確定仕様/カード探索ゲーム_基本設計.md#section-4-6)。

## 保存と公開契約

- rules/engineを`CW-M1-rules-0.4`／`CW-M1-engine-0.4`へ更新。
- 保存外枠`CW-M1-save-1`、効果配列の形式とマーカー`defense_rule:'D56'`、公開契約`CW-M1-public-0.3`は維持。内容・札性能・配置は入力0.1のまま。
- 既知のrules/engine 0.1同士・0.2同士は旧guardを変換。0.3同士は既存配列を引き継ぐ。いずれも退場済み受け手の現在効果だけを取り除く。
- 活動中の受け手にある効果は、付与元が退場済みでも量・回数・由来を維持する。行動履歴・乱数・領収・候補保留等は変えない。発生源の主体記録は由来として残る。
- 旧版にも生値の検査を行い、壊れた回数や重複枠を「退場済みだから削除」で隠さない。NaN/InfinityをJSONのnullへ変えて無制限として受理しない。
- open／inspect／previewは保存装置に書かず、更新成功・空slotへのimportで正規化した0.4を保存する。現在版の退場主体へ効果を注入した保存は拒否する。

**UIへは既存の現在値と`actor_changes[id].defense.before/after`をそのまま渡す。** 退場した受け手はafterが空、他の受け手は量・回数を維持した結果になる。UI側で付与元のactive状態を見て付与を削除しない。`clear_on:'owner_match'`は従来の一致解除情報を維持するフィールドであり、有限回数の終了や今回の受け手退場を除外する意味ではない。

既存の合計・内訳・回数集約・一手予測の対応表は[D56](../appendix-d56/README.md)、今回の実応答は[examples.json](examples.json)。長文の主体欄付記・縮小表示、毎手の詳細窓操作を追加する要求はない。UI原本の描画は変更していない。
