# AT1 — 可変の取得候補と、購入・装備・変換の接続

2026-09-11（UTC）。基点`e827d35b58afcf7e47b73f9ef401bd83fd65313d`。候補選択型の補助取得の大枠をD53・基本設計0.53へ採用し、三候補固定を外した。踏破難易度等による選択肢の変動は許容された方向であり、以下の区分・数値・配分・更新条件は試行。

## 1. 今回接続した範囲

実際の帰還精算から、持ち帰った成果元の設定難度を選び、候補を一度生成して保存する。内容を見た後、習得点で一個を取得し、通常の所持・心得装備・低効率変換へ渡す。無料の基礎取り直しや、同じ購入・帰還処理の再実行で取得個体を増やさない。

候補数は難度Iが2〜4、IIが3〜5、IIIが4〜6。修飾数の抽選重みは通常／一／二／三の順でI＝6/4/0/0、II＝3/5/2/0、III＝2/3/4/1。実カタログで成立する組合せから抽選し、個々の威力等へ新しい数値乱数は加えない。通常版、または利点を含む修飾の組合せを使い、欠点だけの組合せはこの試行の候補へ入れない。欠点を含む複合修飾は残す。

取得価格は共通4pt、一組から一個。候補数が増えると比較対象が増えるが、購入上限は増やさない仮条件とした。候補内は同じ性能の重複を避け、二個目には可能なら異なる基礎を置く。次の帰還で同じ性能を再購入でき、所持の重複は禁止しない。A/B/Cでは心得の基礎候補の重みも変え、探索先ごとの傾向を残す。

## 2. 難度は、成果を持ち帰った対象から決める

A/Bの今回の成果元とCの入口の道をI、Cの支援霧・目的敵をIIと仮置きした。一回の帰還に複数の成果元があれば、持ち帰れた元の最も高い区分を使う。死亡は今回の成果を失うため更新しない。撤退は保護済み成果だけを対象とし、高難度側へ入っただけで候補を増やさない。

経過時間、残り余力、行動回数、装備の弱さは生成条件へ入れない。同じ成果を持ち帰れば、手早く攻略しても候補の条件は落ちない。これは今回の難度算出の第一案であり、あらゆる案件に同じ二段階を当てる正式設定ではない。

今回の探索で得た成果を伴う帰還で一組を更新する仮案。現在の探索で再度踏破した既知の対象も対象になり、図鑑の初回登録だけに限定しない。無成果撤退・死亡では前の候補を維持する。購入・変換・無料取り直し・表示し直しでは更新しない。次の有資格帰還では未購入候補も置き換える。保留する品の固定機能は未実装。

IIIは将来の高難度を想定した生成例だけに使った。IIIの新しい探索・敵・報酬経路は実装していない。

## 4. 初期状態から購入して次の準備へ

初期0pt・取得品なし、seed配置二つ×A/B開始×購入なし／購入ありの8経過、各6探索＝48探索を実行した。既存ARのguard3構築と公開情報方策を使い、基礎全習得に必要な未使用点を確保してから購入する準備方策を固定した。購入する場合は既存ARの探索先別重みによって習得済み心得を優先し、次に解放済み札を選ぶ。未来の抽選や相手の未公開行動を見ない。

今回の方策は全基礎の習得を優先したため、購入はC初クリア後に集中した。購入がC攻略を助けたという結果にはしない。購入なしと同じクリア件数でも、4ptの価格、提示頻度、自由な取得判断が適切かは別。札の購入・現物生成は確認したが、48探索では購入札を山札へ差し替えていない。

## 5. 16項目の生成・購入・保存確認

- 候補の再表示で所持品・資源・戦闘乱数が変わらない。
- 購入は未使用の習得点だけを消費し、一個の所持加算と同じ新しい状態として確定する。3.99ptでは4ptの品を買えず、基礎習得を勝手に取り消さない。
- 同じ購入IDの再実行、別候補を同じIDで買う競合、購入済み組からの二個目、更新前の候補指定、無効な操作IDを区分する。拒否時は元の状態を変更しない。
- 購入心得は基礎の習得・所持個数・装備容量を必要とする。装備中の個体を変換できず、無料取り直し後も個体は残る。
- 無料取り直しは基礎の実支出8ptを全額戻す。購入費を返還せず、端数と所持品を保持する。
- 通常品を4ptで購入し0.5ptへ即変換すると差引3.5ptの支出。売却後に購入処理を再実行しても、その個体は復活しない。
- 購入札を同じ修飾の探索用実体へ生成しても、売却できる恒久個体は増えない。
- 最終行動後、帰還精算・候補生成より前の保存から、通常の完了時と同じ一組だけを復元する。購入後の保存からも同じ個体・支出・候補へ戻る。
- 候補内容・価格を書き換えた保存を拒否する。現在は同じAT条件での復元のみで、条件変更時の移行は未実装。
- 未保護の高難度成果、無成果撤退、死亡、長い経過時間、低い余力によって上位候補を作らない。別の帰還で同じ性能を取得する場合は別個体を作る。

詳細16項目は[results.json](results.json)の`checks`に記録した。難度選択の境界は帰還メタデータを人工的に与えて分離した確認で、48探索の勝敗へ加算していない。実探索側は1,433行動予測、保存復元後の同じ続行44件、帰還再実行48件、購入再実行6件を照合した。

## 6. 次の調整と再現

候補数は可変のまま、難度I/II/IIIで2〜4／3〜5／4〜6を試行基準とする。最大数だけで固定三候補へ戻さず、比較の負担が増える場合は表示・並べ方・候補の差の分かりやすさから確認する。今回の購入方策を、そのまま製品のおすすめ購入機能にはしない。

価格4ptはまだ仮値。今後は基礎習得より個体取得を優先する方策、候補を見送る理由、欲しい系統への到達、購入札を含む本人の構築変更、未購入候補の保持を比較する。提示量と取得量を分け、探索報酬を候補購入だけで置き換えない。

リポジトリ直下で`node docs/検証/資源用途/at/study.cjs`を実行する。[conditions.json](conditions.json)、[offers.cjs](offers.cjs)、[study.cjs](study.cjs)、[results.json](results.json)、[verification.json](verification.json)に条件・実装・全結果・出典照合を保存。既存のPython3 seed生成器を使う。
