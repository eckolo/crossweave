# UI改善と全体評価の検討メモ

2026-09-09（UTC）。試遊Work `20260909-playtest-terrain-build-z` の提案。出典は[試遊記録F03](試遊記録.md)。検討材料の保存であり、新しい正式仕様、他Workの割当、UIの人評価結果ではない。

## 現時点の判断

UI改善を先に進める優先度は高い。現行画面の読み取り負担があるまま混入後の判断や構築の納得感を評価すると、ゲームの仕組みによる難しさと表示の負担を区別しにくい。表示改善の効果は新しい比較で確かめる。

画面全体の情報整理・操作・視覚表現を継続的に扱うなら、UI/UX専用Workへ分ける案を推奨する。設計Workは公開する情報の範囲・ルール・共通エンジンと成果統合を担当し、UI側は表示と操作の試作、試遊側は人評価と原記録を担当する。現在の割当は変更しない。UI担当が追加される場合も、設計仕様と試験版を明示して接続し、互いの完了待ちを全作業の停止条件にしない。

## UI担当へ渡せる最初の作業範囲案

1. 現行の情報と操作を棚卸しし、今の一手に必要な情報、選択に応じて必要になる情報、調べるときに開く詳細へ整理する。
2. 現在の公開範囲内で、対象・手札・一致する場の関係、行動順、今回の結果と状態変化を位置・形・短いラベル等で見分けられる候補を作る。色や意味を覚える必要のあるアイコンだけに依存しない。効果説明を読める経路は残す。
3. 山札は現在残数・属性・効果の参照を保持しつつ、一覧の要約と詳細を使い分ける。初期持込・手札・未ドロー分を混同させず、期限切れ・消滅予定・防御終了等の重要な結果を単に隠して文字数だけを減らさない。
4. 初期状態だけでなく、札が混ざった中盤、多主体、選択結果が大きく変わる場面でも比較する。比較用状態は実際に取得できたものか、取得元・入力・生成手順を明示した試験状態を使い、ユーザーの未取得操作の再現と偽らない。
5. 最初の比較では同じ公開情報・ゲーム条件を使い、読み取りや選択のしやすさを評価する。D40/D41等の新情報を追加する比較は別途版と条件を定める。

最初の成果は操作可能な画面案、情報の対応表、同条件で比較できる材料を想定する。完成イラストや製品の全画面を先に揃える必要はない。出発構築・戦闘探索・報酬と帰還の画面が接続する見通しは初期段階から持つ。

現行PT-Z-001（`e9b5b0a27b6fc51694c347c7e941a28ff97856f5`）は維持。画面を変更した版は専用差分・新しい試験ID・使用版を記録する。共通演算や情報の解放条件の変更はUI改善だけを根拠に採用しない。

## 個別イベントを越えて優先する評価の案

基準は基本設計0.41の1章・2章・6章と、要検討事項Q01〜Q05。探索による自己強化と再探索は既に採用された基軸であり、今回新しく提案する目的ではない。以下は、その基軸を人が通して遊べる形で確かめる優先案。

| 優先 | 大きな論点 | 次に確かめたい体験 | 既存資料との関係 |
|---|---|---|---|
| 1 | 探索・獲得・構築／強化・再探索のつながり | 何を得たいかを考えて出発し、成果と知識を使って次に試したいことが生まれるか。短い一周と次の出発を接続して見る | 基本1、2.4、2.12〜2.19、6.4／Q05。報酬精算・帰還・知識保持の採用済み方針を蒸し返さない。既存の機械比較を未実施扱いにせず、人の連続体験を補う |
| 2 | 一手ごとの駆け引きと結果の理解 | 出す札が他者の材料や後の循環を変えることを、選択理由と振返りに結び付けられるか。異なる状況でも選び方を変えられるか | 基本1、4、6、7／Q02〜Q04。設置率や選択肢数だけを目的にしない |
| 3 | 自分の構築と探索中の変化の関係 | 目的を持って組んだ強みと、借りた札を使う適応が両立するか。攻防枚数以外の札の組合せ・探索目標も含めて見る | 基本2.6〜2.7／Q01。循環中に常時同じ組合せを保証する目標ではない |
| 4 | 探索全体の緩急と続行判断 | 危険、資源、獲得成果、区間の長さから、先へ進む・成果を追加で狙う・帰還する判断が生まれるか。待ちが続くだけの区間や単調な反復がないか | 基本2.5、2.11〜2.13／Q03・Q05。探索全体と一環境の長さは区別する |

UIの読み取り負担の改善を先行させながら、設計Workでは優先1の小さな通し試作の不足を整理できる。報酬内容等は最小の記録付き仮条件で具体化し、人の体験が必要になる前まで進める。優先2〜4はその一周の中で観察する。大岩の持越しは優先2・4の個別の試験材料として保持し、並行イベント実装を全体評価の前提にしない。

UIやこのメモによる具体的な改善効果、面白さ、優先順の正式採用は未確認。原文の「検討するのはいい」は前回の検討継続を認めるもので、このメモの候補一式への採用判断とは扱わない。
