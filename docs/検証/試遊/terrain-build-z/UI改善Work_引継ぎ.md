## UI改善の最初の仕事

現行画面は、上部の状態情報、主体別の数値、手札の主効果と場効果、文章の結果予測、初期状態で開く山札全種類一覧が並ぶ。以下の順で具体化する。

1. 情報と操作の棚卸しを行い、常に見る情報、札選択に応じた情報、必要時に開く詳細へ優先順位を付ける。既存情報の移動・要約・詳細参照先を対応表に残す。
2. 手札・属性の場・選択対象の関係と、「一致して使う／場へ置く」「今回何が変わるか」を視覚的に追える画面案を作る。HP、行動順、重要な期限・状態変化を把握しやすくする。
3. 自分の山札の全種類・現在残数・属性・効果をいつでも調べられる状態を保ちながら、一覧を読み続けなくても大まかな構成を把握できる案を作る。持込・手札・未ドロー分・消滅予定を混同させない。
4. まず1案を操作可能な試作として提示する。分岐する設計上の理由がある場合に比較案を加え、案の列挙だけで止まらない。初期状態だけでなく、混入後、多主体、期限切れや防御終了が判断に関係する状態でも必要な描画・操作確認を行う。
5. 人に確認したい点を1〜2点に絞り、使用版と開始条件を添えて試遊担当が利用できる状態にする。UI Workで直接受け取った画面への所感も、出典と版を付けて自分の専用記録へ保存し、試遊・設計側が参照できるようにする。

色や暗記が必要なアイコンだけで意味を伝えず、短いラベル・形・配置を併用する。効果詳細へのアクセスを残し、文字数削減のために消滅予定・期限切れ・防御終了などの重要な結果を隠さない。非公開の相手手札・未来の札順・次行動を、新たに公開しない。

最初の対象は戦闘・探索画面だが、出発前の構築、探索中、報酬・帰還、次の探索へつながる全体の情報設計も見通す。大岩専用の画面や処理に過度に特化させない。製品の全画面・完成イラストを揃える前に、今の判断の読み取り負担を改善した操作案を見せる。
