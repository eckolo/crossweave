# 固定試作からのUI比較用局面

試遊WorkがUI改善待ちの間に準備した、PT-Z-001と同じ演算・入力からの比較材料。ユーザーの実際の選択列・途中セーブ・新しい人評価ではない。UI Work `20260910-ui-readability` の `UI-R-001` で必要に応じて利用する候補。ケースIDは試験局面の識別子であり、新しい人の試行数を表さない。

## 材料

- `prepare.cjs`：固定入力から単一の行動列を生成し、指定した最初の選択待ち局面を抽出。保存済みデータの再実行と最低限の受渡し確認も行う。
- `comparison_cases.json`：各局面の合法な前置き選択列、公開情報の表示用データ、状態・表示用データ・経過のハッシュ。敵の私有札や全ドロー順・乱数状態は格納しない。
- 依存元は隣の `../fixed/` の5ファイル。元ファイルを編集しない。コード・入力基準は `e9b5b0a27b6fc51694c347c7e941a28ff97856f5`、seed32、guard5（攻撃6・防御5・回復1）。開始HP60等は元入力のまま。

## 抽出した局面

| ケース | プレイヤーの位置 | HP | 再構築回数 | 確認対象 |
|---|---|---|---|---|
| CMP-Z-START | 1手目の選択前 | 60/60 | 0 | 入口の読み取り |
| CMP-Z-MIXED | 8手目の選択前 | 60/60 | 1 | 再構築後の札の把握 |
| CMP-Z-LATER | 17手目の選択前 | 30/60 | 2 | 循環が進んだ複数対象の把握 |

STARTは初回の選択待ち、MIXEDは初回再構築以降にPの手札・山札へ他主体由来札が入った最初の選択待ち、LATERは再構築2回以上で後続の敵・環境が共に生存する最初の選択待ち。HPを作為的に減らしていない。

当初「初回混入」と「再構築後の後続2主体の参戦」を抽出したところ、どちらもP8手目の同じ状態だった。その重複を3種類・独立3試行と数えず、3点目は2回目の再構築以降という条件で同じ一経過から抽出し直した。終端結果での選別・別seedの探索・構築の比較は行っていない。3点を得たP17手目で生成を止める。

前置きの方策は設計側 `study.cjs` の `choose` 関数を変更せず利用（参照コミット `8f86da70a8519ad3db88bde4a701ba1b1fa51ada`）。対象優先environment_first、防御評価defenseを指定。Pの手札と公開状態による単一の機械方策であり、人の典型・推奨手・最適構築を表さない。通常プレイでの到達頻度も評価していない。

## 再生成と確認

リポジトリルートから以下を実行する。Node.js標準機能のみを使用する。

```sh
node docs/検証/試遊/terrain-build-z/fixtures/prepare.cjs
node docs/検証/試遊/terrain-build-z/fixtures/prepare.cjs --verify
```

初回コマンドは本フォルダのJSONを再生成する。既存データを保持して照合だけ行う場合は `--verify` を使う。固定5ファイルのGit blob SHAを照合してから実行する。

今回確認した範囲：3局面の前置き再実行と状態・表示データ・経過ハッシュ一致、ファイル読み戻し後の同じ生成結果、山札／手札の表示枚数、表示用DTOに相手の私有札配列が無いこと、各局面から1手進めた状態が保存復元経由でも同じであること。新しいゲームルールの検証・広い数値比較・UI描画確認・人の使いやすさ評価は含まない。

## UIへ受け渡す際の使い方

1. 同じ固定 `input.json` を `CWTerrain.prepare(input, fixture.build)` に渡し、`new CWTerrain.Game(bundle)` を作る。
2. `game.advance()` でPの選択待ちへ進める。各 `fixture.prefix` の選択を順に `game.step(choice); game.advance();` で適用する。各選択待ちで `CWFeedback.attributes(game, knownAttributes)` を呼び、既出属性を保つ。
3. この状態で通常の画面を描く。以後の操作は人が選ぶ。JSONの `observable` は同条件比較の参照用で、静止データだけを操作可能なゲームと見なさない。
4. 画面変更前後に同じケースを使ったことと、表示差分コミットを記録する。全3ケースの人評価を開始条件や完走義務にしない。

`current_choices` の予測は、現在の公開状態から確定する自分の一手のみ。相手の次行動や未来の結果は含まない。エンジン内部のtraceを丸ごと画面に出さず、既存の公開ログ用整形に沿って表示する。正確な状態ハッシュ等は開発・再現用で、プレイヤーの通常画面に常設する項目ではない。

この材料だけでは、D40/D41の新表示、自由構築、報酬の具体価値、帰還後の強化、次の探索までの評価はできない。その準備は[次回試遊計画](../次回試遊計画.md)を参照する。
