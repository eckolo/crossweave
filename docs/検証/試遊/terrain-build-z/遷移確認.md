# PT-Z-001：環境先行時の大岩退場の確認

2026-09-09。対象はF01の「先に環境を倒すと大岩が消え、新しい環境と敵が出た」という報告。

## 実装の根拠

`input.json` の `initial.state.successor` は `replace_environment`、`entry_delay` は10、`selection.seed` は32。

`engine.js` の `dispatch(victim,attacker)`：

| 解決条件 | 取得・保護 | 退場と後続 |
|---|---|---|
| O（大岩）破壊 | R取得、未保護 | O退場。`replace_environment`なのでV0も退場し`followup()` |
| V0（最初の環境）踏破 | T0取得、獲得済み分をまとめて保護 | V0と生存Oを退場させ`followup()`。未破壊OのRは取得しない |
| E1（後続敵）撃破 | E取得、未保護 | E1だけ退場、V1は継続 |
| V1（後続環境）踏破 | T1取得、獲得済み分を保護してクリア精算 | V1と生存E1が退場。未撃破E1のEは取得しない |

`followup()` は `current_event='followup'` とし、V1/E1を現在時刻+10で参戦させる。Oの退場で支援は終了する。大岩を迂回して「場からいなくなる」ことと、大岩を破壊してRを得ることは別。

根拠となる原文の該当行：

```js
followup() {this.s.current_event='followup';for(const w of ['V1','E1'])this.enter(w,this.s.now+this.s.entry_delay);}
```

V0分岐では `traverse('V0','T0')`、`retire('V0')`、生存Oの`retire('O')`、`followup()`の順。O分岐はR取得後、`keep_environment`ならV0を継続する対照もあるが、今回の入口はその条件ではない。

## 仕様・試行条件との関係

固定版の基本設計0.39の2.2・2.13・9.1では、岩を壊す／環境を削って迂回する複数経路を許容し、具体的な後続と残存対象はイベントごとに定める。統合検討54.1〜54.3、55.2に、今回と同じ両経路の後続・報酬差が記載されている。報告の挙動はその仮イベント実装に一致し、直ちにコード不具合とは判定しない。全イベントで大岩が消える正式な一律仕様とはしない。

両経路の違いは、攻撃対象の軽減・回避等による攻略負担、獲得するR/T0、直後の保護状態、持ち越すHP・札・場・会心等。次に現れるV1/E1は同じ。R/T0は識別用成果であり、具体的な内容・価値は未設定（55.2）。したがって報酬選好に基づく迂回の意味は十分評価できない。

## 設計への申し送り

ユーザーは「こうなるなら大岩無視する意味が無い」と述べた。期待する経路差を未確認のまま、敵戦回避を要求した・大岩と支援を残すべき・同じ後続は禁止と読み替えない。次の回答で意図を確認し、設計Workで経路の意味・提示情報・報酬価値の論点へ接続する。
