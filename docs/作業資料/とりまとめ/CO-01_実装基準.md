版：0.7／2026-09-20（日本時間）。担当：とりまとめWork `20260913-project-coordination`。計画0.9に対応。固定入力・演算を維持し、D03公開0.5と今回のUI接続単位を反映。

**CO-D01・S01・01A・U01の提出物を照合し、M1の試行実装へ渡す基準を確定した。CO-01は計画上の照合完了とする。** 共通runtime・実保存・画面接続の完成や、ゲーム仕様・試行値・新画面の正式採用を意味しない。後続担当がこの基準を受領した事実も別に記録する。

D03は本体7671ded・完了記録7565afcで公開済み。現行提供版はengine0.6／public0.5、rules0.5／内容0.2／save schema1。今回のUI実行範囲は[CO-U02-B](着手指示/CO-U02B_公開情報と取得経済の接続.md)。以下のD02時点の未対応・将来D03という記述はA時点の条件として読み、現行の公開契約は設計枝 `co-d03/ui-handoff.md` を参照する。

個体のUID・候補batchは保存内部の参照で、UIへは現在view専用の `owned-N`／`choice-N` handleを返す。UIは新viewへ全体更新し、古いhandleに新tokenを付け替えない。U-G03の正確な参照保持はcontrollerの責務であり、UIによるprivate UID参照を意味しない。

## 3. 本文の表示記録と保存・実行環境

CO-01Aの`continue_scene`互換拡張を試行実装条件として使用する。既定`advance:true`は従来の`{scene_id}`と同じ停止解除。`advance:false`は現在の適格な本文を実際に開いた記録だけで、時刻・ドロー・報酬・停止位置を進めない。homeの現在依頼場面でもfalseだけ許す。`displayed_text_ids`に未知・別scene・未適格なIDを入れた場合や古いtokenは拒否する。

この追加はUI-Gの準備操作とplanを変更しない。U02でS05/S15/S18/S16の本文・詳細へ接続する。hoverで利用可能になっただけの任意詳細を一括既読にせず、実際の表示に対応させる。inspectは純粋な読取りを維持し、CL05を未閲覧で観測済みにしない。表示記録を人が理解した証拠にはしない。

| 項目 | M1試行の基準 |
|---|---|
| 実行 | 共通JavaScript核＋静的な内容入力。安定した同一オリジンの静的アプリ、デスクトップChromiumを初回確認対象。起動コマンド・URL・ブラウザー実版はD02の案内で固定し、実接続時にU02も同じ条件を使う |
| 保存 | `CW-M1-save-1`。IndexedDBで1slotを1レコード（状態＋request_log）として一括確定。コピーで演算→永続側revision再確認→一括保存成功→現状態更新。UIは成功前に額・所持・解決を変えない |
| 起動・輸出入 | D01の`Campaign.create/open/importSave`と`controller.exportSave`を使う。create/importは空slotのみ。既存slotへの上書き・複数枠管理画面は今回追加しない。open失敗で新規作成へ自動フォールバックしない |
| 一時環境 | fileスキームや会話の一時iframeを永続保存の確認先にしない。NodeのJSON往復・DOM検査だけでIndexedDBの実保存を合格にしない。ブラウザーで確認不能ならコードと再現手順を提出し、その確認は未了として残す |
| 非対応保存 | 旧PT-Z/PT-NT、研究snapshot、UI-Fを自動移行しない。不明版・破損は元データを保全して拒否。旧PT-NTのHTML・localStorageキーを使い回さない |
| 実装版 | A→BではAの保存を保持して機能追加できる形を優先。互換性を破る場合は新しい版と明示変換／拒否を記録し、過去保存を黙って初期化しない |

モジュールのファイル名とbuild方式は設計担当の実装判断に残すが、公開入口・読み込み方・対応機能を最初の利用可能なコードと一緒に保存する。UIはCampaign/controllerを注入できる接続部品として作り、未発行のパスやexport名を推測して固定しない。UIからの呼出しはawait可能な形で扱い、永続操作の非同期完了を待つ。UIに独自の保存・経済処理を実装させない。

## 4. 実装単位と受渡し

| 単位 | 今回から行うこと | 完了の境界 |
|---|---|---|
| CO-D02 | `src/runtime/`・`src/content/`へ既存演算と入力を接続し、単一controller、公開view、基礎成長、出発・探索・3帰還・再訪・保存再開を実装。利用可能なAPIを先に通常保存してU02へ渡す | 実コードによる途中到達A。UIの完成を待って基礎実装を提出しない。D03へ自動続行しない |
| CO-U02の今回の単位 | U01の画面を、実controllerを注入できる非同期接続部品へ分離。起動・保存再開・エラー・本文表示・探索画面の公開view接続を作り、D02が提供した単位から実接続 | 接続層はCO-01＋U01で先行可。実接続にはD02の利用可能APIが必要。全経済機能の完了にはD03が必要。API待ちだけになれば保存・提出して枠を空ける |
| 後続D03/U02/D04 | 個体・修飾・候補・購入・変換を有効化し、同じ保存の次出発まで接続。必要なUI差分と素材を一つの入口へ統合 | 途中到達BからM1接続確認へ。人の理解・面白さはP02/CO-02で別に記録 |

D02で生成未対応の候補は、適格帰還の情報と台帳を保持し、取得機能が未接続であると示す。将来D03を有効にするときの版互換性・候補生成の一回性を明記する。今回その場で任意個体を配って不足を埋めない。nt_*はAでも探索内に登場するため、3札の性能・署名・間隔と知識IDはD02で対応が必要。所持個体としての修飾・購入はD03である。

D02の新規確認IDは`CW-M1-A-001`、U02の接続確認IDは`CW-M1-UI-001`を用い、条件・実コードSHA・入力版・保存例・確認範囲を担当の新規検証フォルダへ置く。共通の必須境界は、初回から再訪への一続き、保護前後の撤退、緊急脱出、保存前後同一性、拒否時不変、同要求の再送、古いrevision、本文表示による再精算なし。機能が未実装の時点のUI確認はテスト用応答の範囲として記録する。
