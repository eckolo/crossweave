# crossweave — 全体計画

版：0.6／2026-09-15（日本時間）。担当：とりまとめWork `20260913-project-coordination`／`ops/project-coordination-20260913`。

**当面の目標は、夜潮の排水路を題材に、準備→探索→帰還→成長・編成変更→再出発を、同じ保存データで通して遊べる小さな本体を作ること。** 一往復の試遊が既にあるため、その先の接続を優先する。これは今回委任された制作上の目標設定であり、案件・個別数値・未採用の装備方式を製品仕様に確定する判断ではない。

**同時に実作業するのは最大2Work。今の着手対象は設計CO-D02とUI CO-U02の接続層先行・提供済みAPI接続。** 前回のCO-01A・CO-U01は提出と枠解放を確認し、[CO-01実装基準](CO-01_実装基準.md)へ最終照合を保存した。設計は同じ保存で成長・再出発する途中到達Aを作り、UIは画面はみ出しの修正・再提示を先に行い、独立した非同期接続部品・保存再開の導線も進める。UIの実動作接続には設計の利用可能APIが必要。とりまとめ自身も実作業時は1枠に数える。具体的な依存と担当への指示は[Work別実施計画](Work別実施計画.md)に置く。

**UIのユーザー確認は残っている。** CO-U01の提出をUIの受入完了とはしない。画面はみ出し対応のv0.1.1は保存済みで、U02はその実表示点検・必要な追加修正・再提示を先に行う。新しいChatGPT Workへ同じWorkIDとブランチを引き継ぐ。設計D02と配置に依存しないUI接続部品は進行可能。[確認内容と影響](CO-01_実装基準.md#提出後に残っているユーザー確認)を併記して次の割当を行う。

## 1. とりまとめWorkが管轄すること

- ゲーム作成までのマイルストーン、優先度、依存関係、達成を判断する証拠を管理する。
- 現在の目標に必要な仕事へ各Workのタスクを並べ替え、成果物・担当・受け渡し条件を具体化する。
- 仕様決定、機能実装、画面への接続、人による評価のどこで止まっているかを区別する。
- 新しい課題が出たら、現在の目標に必要か、後の段階でよいか、独立して深める候補かを判定する。
- ユーザー判断が必要なときは、既存の判断を再質問せず、未決部分の具体案・推奨理由・影響をまとめる。

各分野の原本と共通エンジンは既存担当が更新する。とりまとめは各Workの実行順を設定するが、専門担当の採用判断・原記録・実装の所有権を引き取らない。追加のユーザー指示に基づき、全Workは本ブランチの計画成果を必須同期する。設計・コードの既存同期も維持し、[計画同期手順](計画同期手順.md)で対象範囲と順序を定める。

## 2. 現状の評価

1. **探索の一往復はある。** PT-NT-001は夜潮の排水路の依頼・初期編成から水門復旧・帰還まで操作できる。ただし次の新規試行は初期化され、周回成長を保持しない。人の試遊記録も未取得。
2. **成長・取得の処理材料はある。** 設計側には自然取得・修飾・心得構成・購入・無料取り直し・保存の個別検証があり、BDは準備差分、BEは公開局面の表示材料を持つ。完成本体への実適用は未接続。
3. **成長・準備の操作試作がある。** UI-G-001 v0.1は心得・札組・取得・変換・帰還を公開契約に沿って模擬操作できる。実出発・実保存は未接続で、現在の同期的なmock呼出しを実controllerへ置き換える必要がある。全30単位のUI検討を一度に終える必要はない。
4. **題材と制作方針は使える段階にある。** SCN-001と初回・再挑戦・再訪の入力0.1、世界観設定1.14・正式用語集1.3、正式制作手順1.0がある。UIから実寸・透過の素材要求も提出された。実素材の制作・合成確認は後続へ残る。

計画0.4時点では、CO-01Aの版付き入力0.1・接続条件0.2とUI-G-001 v0.1を確認し、U-G01〜06・本文表示記録・保存環境・試行版の扱いをCO-01で照合した。実装を進める基準は揃ったが、新runtime・永続保存・新UIへの実接続は未実装。D02とU02の先行部分を開始し、実装済みの範囲から一続きの操作へ進める。

したがって、当面の主な不足は、既存成果の共通状態・実行処理・画面・再訪内容への接続である。細部の設定が全て完成していないことだけを本体着手の停止条件にしない。詳細と出典は[棚卸し](現状棚卸し.md)。

## 4. 今回の目標M1の範囲

初回題材は既に試遊依頼のあるSCN-001／夜潮の排水路を使う。未解決の再挑戦と解決後の再訪を区別し、後者は既存の「管理用連絡路の確認」案から最小の内容を具体化する。新しい全編シナリオや地図システムの採用を前提にしない。

| 段階 | M1で必要なこと | 既存材料・追加が必要なこと |
|---|---|---|
| 準備 | 探索先・既知情報・実際の札組・習得と装備・所持を確認し、本人が変更できる | UI-F-001、BD、AU等を基に実状態へ接続。空表示を機能完成にしない |
| 探索 | 正式探索UIを継承し、環境への進展、任意の相手、借り札、進退を判断できる | PT-NT-001の一往復を固定参照。共通演算へ接続する差分を記録 |
| 帰還 | 踏破・撤退・緊急脱出の持帰り／喪失、知識、解放、所持を区別する | 再表示や再読込で成果を二重加算しない。本文閲覧で回復・報酬を増やさない |
| 成長・取得 | 基礎心得の習得と無料取り直し、所持個体と修飾、装備、候補取得と見送り、低効率変換を使える | D47・D50〜D53の方向を接続。候補数・価格・容量・変換率は版付き試行値。全基礎を初回で買えることや取得品の強さを保証しない |
| 次の探索 | 帰還後の変更が次の出発へ反映され、恒久成果・知識・案件状態が残る | 新しい出発の手札・場と、前回の恒久成果を区別。新規ゲームの初期化を流用しない |
| 中断と再開 | 拠点と探索中から再開し、途中操作の状態を保つ | 既存の異なる保存形式を無条件で混用しない。今回の対応範囲を決める |

実行は小さく分ける。**途中到達A**は帰還成果・習得・編成変更を次へ持ち越す接続確認、**途中到達B**は取得個体・修飾・購入・変換までを同じ状態へ接続したM1候補。Aは早く触れる中間版として提示できるが、Bを終える前にM1全体を完成扱いにしない。価格等の理由で自然な初回に使えない機能は、別の固定検証状態で機能を確認し、初回へ報酬を水増ししない。

M1の受入では、正常な一巡に加え、保護前後の撤退、緊急脱出、実行不可の準備、帰還と購入等の再適用、保存再開を確認する。人には「帰還後に何を変え、それが次の探索でどう役立ったか」「途中で対象や進退を選び直す理由が分かったか」を主に確かめる。技術的な接続合格と、人の理解・面白さの評価を別欄で残す。

## 5. 優先度と作業の調整

| 優先度 | 意味 | 今回の扱い |
|---|---|---|
| P0 | M1の接続・進行・保存を止める、または複数Workの前提になる | 共通状態と実適用の条件、案件状態・再訪データ、成長UIと本体接続を先行 |
| P1 | M1の判断・識別を成立させる、またはM2の評価に直結する | 必要な用語と短文、実表示用素材、現在の試遊観察、判断負担や反復への対処 |
| P2 | 後段の完成に必要だがM1を止めない | 別探索先の本格展開、全30単位の残りUI、全編の進行・素材・仕上げ |
| P3 | 直近の完成条件から独立した比較・設定候補 | 世界観の広い案出し、未使用素材や演出の追加比較。必要となれば昇格 |

着手枠を割り当てられたWorkは、指定されたP0/P1成果を一つ受け渡せる単位で仕上げる。前提待ちの場合は、同じ割当範囲で独立して進められる部分を完成させる。待ちしか残らなければ保存して枠を空ける。新しいWorkや別タスクへ自動的に広げず、次の割当へ引き継ぐ。

設定の深掘り・広い案出しも後続タスクとして維持し、空き枠と現在の目標への必要性で着手順を決める。最大2Workは埋め続ける目標ではない。前提が揃わなければ1Workで進める。新案を必須機能へ自動昇格させない。

## 6. 受け渡しと計画の更新

本計画はユーザーが委任した優先度設定として保存する。**計画登録／担当の受領／着手／成果提出／接続済み／確認済み**を分ける。今回、他の会話やWorkを起動したり、担当が受領したことにしたりしない。

各Workは開始・再開時と成果反映前に、計画同期手順に従って最新の計画成果を自ブランチへ取り込み、自分の行を確認する。次の情報を自Workの既存記録に残す。とりまとめは次の作業単位でその記録を読み、実施計画を更新する。常時監視やユーザーによる所感の毎回の転記を前提にしない。

1. 対象タスクID、着手または待ちの状態、満たしていない依存。
2. 成果コミットとファイル、使った仕様・コード・入力の版。
3. 完了した範囲、仮置き、試験と人の所感、未確認事項。
4. 次の担当が接続できる入力・出力と、既存成果への影響。

追加タスクは必ず「どのマイルストーンに必要か／何を解除するか／誰が受け取るか」を付ける。目標に影響しない深掘りは後段へ置く。進行不能や重大な解釈違いが見つかった場合は優先度を変更し、理由を記録する。仕様の正式採用は引き続きユーザー判断とし、タスクの着手・保存とは分ける。
