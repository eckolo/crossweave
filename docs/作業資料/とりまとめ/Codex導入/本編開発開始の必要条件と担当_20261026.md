# ゲーム本編の開発開始に必要な条件と、担当間の受渡し

ゲーム本編の実装と変更確認を開始できる状態を作るため、最新の本編プロジェクト定義と固定ツール情報を照合し、共通環境・正式ソースの受渡し・依存復元と最小ビルドを既存の各窓口へ順に割り当てた。基本環境の利用は利用者から確認済みと報告されたが、本編用の準備と受渡しは未確認であり、今回は必要条件・指示・承認境界と計画を整える段階である。環境準備や本編開発の完了は、各担当の実結果を受領して別に判定する。

版：1.0／2026-10-26（日本時間）。計画担当：開発計画とりまとめ／20260913-project-coordination／ops/project-coordination-20260913。

## 今回の目的・受領した現在地

今回の目標は、既存「ゲーム本編実装」が、指定されたコードの実装と変更確認を開始できる状態を作ること。夜潮の排水路を一巡して保存・再開できる小さな遊べる版という上位目標は維持するが、描画・UI適合・Windows配布・実機試遊・全回帰・M1受入をすべて実装開始の前提にはしない。

次は利用者の最新確認結果として受領したもので、とりまとめによる環境の独立実測ではない。

### 取得元と、最小準備案を作る際の制約

本編の`apps/crossweave-godot/packaging/toolchain.lock.json`（blob `a690cc5f2d91b2653aded0d592bea61f7a57c944`）に、GodotのOS別ZIPとsha256、SDKのOS別archiveとsha512を保持している。インフラは実OSに合う項目を選ぶ。固定URLを取得済み・到達可能・許可済みと確認した意味ではない。

- Godot：`https://github.com/godotengine/godot-builds/releases/download/4.7.2-stable/`配下の`Godot_v4.7.2-stable_mono_linux_x86_64.zip`または`Godot_v4.7.2-stable_mono_win64.zip`。
- SDK：`https://builds.dotnet.microsoft.com/dotnet/Sdk/10.0.401/`配下の`dotnet-sdk-10.0.401-linux-x64.tar.gz`または`dotnet-sdk-10.0.401-win-x64.zip`。
- NuGet：現在の実NuGet設定とサービスindex／cacheをアプリ側で確認し、実際に必要なfeedと取得先を固定する。新しいfeed・ミラーや接続先を推測して追加しない。
- リダイレクト先を含む必要な許可は実設定と実取得方法で照合する。新しいドメイン許可・通信経路・認証・package導入が必要なら、その対象・理由・影響を具体化してから承認を求める。

ツールは既存版を上書きせず、許可済み書込み範囲内に分離する案を基本にする。既存の`UiProbe/runtime.py`は`apps/crossweave-godot/.tools/dotnet`と`.tools/godot`を固定参照する。共通配置が別pathなら、アプリの最小コマンドでその絶対pathを使う方法か、承認済みの配置対応を明記する。単にPATHへ追加しただけで既存補助が再利用できるとはしない。

`packaging/bootstrap.py`のmainはexport templates取得・ユーザーデータ領域への展開・font上書きを含む。`UiProbe/runtime.py`のprepare(acquire=True)は取得・font配置・chmodを行う。`UiProbe/launch.py --prepare-only`はrestore／buildに続けてGodot importを行う。これらを、今回の共通ツール準備や最小ビルドへ無条件に一括実行しない。

### 公開版と利用側の対応

インフラは環境ID・保存設定ID／版・公開版・実機を対応付けて返す。既存公開版で要求を満たすなら、形式だけの保存・再公開はしない。導入が編集実機にしかない場合は、後続に必要な保存・公開の要否と権限を確認する。

再公開で既存アプリタスクへ自動反映されるとはしない。既存実機で共通ツールへ到達できるのか、公開版を利用する別の実行単位が必要なのか、実在する適用方法を確認する。新しい実行単位・環境切替が必要なら、既存未保存差分・WorkID・正式枝の保全と必要操作を具体化して判断へ出し、無断で新Work・枝・タスクを起動しない。

### ソースの保存窓口と実行窓口

本編Work原本では、通常Git保存はChatGPT側の同名窓口、Cloudは観測・実行側として区別されている。今回もGit保存担当を無断でCloudへ移さない。C4の2文書取込は完了受領済みで、同一内容の再作成・形式だけの再取込は不要。新計画の実同期と新しい受渡し記録は今回の別の作業として行う。

Cloudでは現枝・HEAD・refs・未保存／未追跡を先に確認して保全し、正式ソースの固定コミット・path/blobと実配置を確認する。単なるリンク・コピーをGitの正式checkoutへ読み替えない。許可済みGitHub手順で対応できないsource適用操作は、具体的に確認してから行う。直接cloneや無断のfetch／switch／reset・新枝で不一致を修復しない。

## アプリ側の最小ビルドと判定

作業ディレクトリは`apps/crossweave-godot`。インフラから受け取った固定dotnet実行ファイルの絶対pathを使い、受領したソース・ツール・承認条件がそろってから次を実行する。ここに記載したこと自体は、とりまとめが実行した／未成立前提を解除したという意味ではない。

```sh
dotnet restore Godot/Crossweave.Proof.csproj --locked-mode --disable-parallel -p:Configuration=Debug -m:1
dotnet build Godot/Crossweave.Proof.csproj --no-restore -c Debug -m:1
```

対象は本編Godotプロジェクトと参照Core／Infrastructure。直列ビルドは原本の既存経路を継承し、Debug.portable lockとRestoreLockedModeを維持する。全solution・Tests・SaveProbeの実行やGodot importを自動追加しない。復元内容の承認がなければ、feed・固定package・cache／生成先・コマンドの具体案を完成させて確認する。

実コマンド・cwd・環境とソース版・SDKとGodotのpath／版・開始終了時刻・終了コード・ログ・追跡差分を記録する。失敗は共通ツール／native、通信・認証／取得、source受領・版不一致、固定依存、既存コード、未特定に分ける。正しい入力・環境を確認できていない段階でコード由来やインフラ不備と断定しない。準備依頼の範囲でコードやlockを変えて通さない。

成功と、所定の入力・ツール・差分保全・利用権限を確認して「今回準備の範囲で実装開始可」とする。UIの実表示・機能全体の正常・配布可・M1受入は別判定。失敗した場合は報告単位を終えても、準備は未完了として具体残件と次の操作を返す。
