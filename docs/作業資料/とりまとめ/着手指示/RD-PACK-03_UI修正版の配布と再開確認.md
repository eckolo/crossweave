## CO-D04Cへ続ける条件

P4までの受渡しが確認できたら同じ既存Workの[CO-D04C](CO-D04C_Windows本編の実機確認.md)を修正版で継続し、P5の引継ぎへ統合する。利用者の「起動はできた」は旧版の報告として保全し、新版起動済みとはしない。最初は修正版フォルダーのCrossweave.exe起動→短い探索→中断して終了→閉じるまで待つ→同じ修正版を再起動→続きから。UI修正箇所の確認は直接場面へ案内し、毎回最初からの一巡を要求しない。

実操作は担当「人」の[CO-H02→CO-H03](../人の担当タスク.md)へ対応させる。本Workが新版の正確な所在・版・起動箇所・既存確認票を示して開始可能にし、原文・観測・未確認を受領して保存する。納品だけを人の確認完了にせず、利用者の報告だけをCO-D04C全項目合格にも変換しない。旧版の報告は保全する。

利用者の保存は削除・初期化せず、新旧アプリを同時起動しない。既存セーブはアプリ終了後に控えを取る案内を使う。旧版でまだ開始していなければ修正版の新規開始から確認する。Godot／SDK／Python導入やソースからのビルドを利用者へ要求しない。

CO-D04C・ENV／PROOF・親D04は項目ごとに判定し、実機結果待ちなら未完了と再開入力を記録して区切る。旧版の結果を新版へ使える範囲はソース・環境・影響に基づいて理由を記録。CIの合成入力・ソフトウェア描画を物理入力・可読性・DPI・音・GPU性能へ一般化しない。実機で具体的な不具合が出た場合だけ担当を切り分け、とりまとめ受領後にCO-P02→CO-02へ進む。
