### 確認を行う範囲

今回新たに確認するのは「本編コードを配布物へした結果」の境界。既存の72試験・14ケースを一から設計し直さず、変更とexportに必要なケースを選んで再利用する。本編一巡・再開は、既存の通常sceneと実FileGameSessionを通る合成操作を配布exeへ接続して確認する。検査用入口が必要なら専用slotに限定し、通常起動では有効にしない。

Windows CIにSDKが導入済みの場合は、その事実と開発ツールを参照させない確認方法を記録する。PATHを変えただけで完全なクリーンWindows11実機を検証したとはしない。同梱runtimeと資源の利用は生成manifest・実行ログ等で確かめる。配布物から得られる描画結果も確認し、物理入力・DPI・音・実GPU性能の未確認とは分ける。

保存失敗や成否不明・復旧は既存の実装契約を維持する。配布の変更がその経路に影響する場合のみ該当検査を追加する。実ディスク満杯・停電・全旧版移行を今回一括で増やさない。具体的な本編不具合が出た場合は影響を特定し、配布阻害を解消する最小修正を行う。規則・UIの大きな変更が必要なら独立した成果を保存し、未了条件と修正依頼を引き継ぐ。

### 保管と利用者への提示

大型ZIPは既存Dropboxルート `/久乃銑泉/gist/crossweave/` の版別新規パス、例 `docs/検証/crossweave-m1-<配布版>-<短縮SHA>-win-x64.zip` に保存する。本指示はこの本人向け本編ZIPの生成・既存保管先への保存を対象に含む。実パス・リビジョン・bytes・SHA-256とmanifestは自担当の配布記録へ残し、外部成果物一覧への登録項目も引き継ぐ。旧ZIPは保全する。一般公開・Steam配信・公開範囲変更は対象外。

利用者向けの案内は、入手場所、全展開、起動する一つのファイル、セーブの場所、更新・再開、確認票の返却物を中心にする。開発者向けSHA・CIの説明を起動操作の必須知識にしない。署名等で起動を止められた場合は症状を記録し、セキュリティ設定の無効化を通常手順にしない。

GitHubへはコード・軽量資料・manifest・読戻し結果を保存。外部ZIPの保存・取得照合が失敗した場合、ローカル生成だけで配布完了にせず、生成済み成果と阻害工程を残す。通常保存を特別な承認待ちへ置き換えない。

### 実機残件と学習条件

基盤ENV/PROOFのWindows11実機結果は未受領のまま。実画面・日本語の読みやすさ・実マウス／タッチ・DPI100/125/150%・音・GPU性能・応答・メモリーはM1受入前に確認する。今回、その確認票を本編版と旧proof版で対応付け、同じ項目の無条件な二重確認を要求しない。旧proofでしか確認できない項目は入口と理由を示す。実機結果が未着でもP1〜P6の配布準備・自動確認・提出は進められる。

新規・変更コードは[コメントと解説の共通条件](../完了報告と引継ぎ規則.md#5-コードを学習教材として読むためのコメントと解説)に従う。`docs/検証/実行基盤/rd-pack-02/コード解説.md`に、Godot export／C#・.NET runtime／Python等の生成補助／本作の梱包処理を区別して、なぜ同梱が必要か、保存場所を分ける理由、生成→展開→起動→再開を説明する。資料・ソースはリポジトリルート相対パスで案内する。
