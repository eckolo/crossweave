## 今回まとめて実施すること

1. **UI成果を受領・統合する。** PRの現行入口・専用コード・必要資料を照合し、本Workが所有する設計枝へ通常の方法で統合します。旧mockや固定UI資料を現行ゲーム入口と混同せず、通常入口と確認専用入口を案内してください。取り込むコミットと実ファイルの範囲を記録します。取り込み時に古い計画コピーが戻った場合は、最新計画の全対象を再照合します。masterへの統合やUI枝の直接編集は含みません。
2. **本人を含む全能力の解決直後予測を公開する。** `previewAction`から公開主体ごとの身構・機転・攪乱等の現在／今回一手の解決後値を取得できるようにします。身構終了・置換、機転消費、常時支援源の離脱を共通の実行演算に合わせます。未知・未対応と変化0を区別し、未来のNPC行動、未知札、乱数の内部状態を公開しません。UIでの別演算や`crit_added`の最終差分流用を不要にしてください。
3. **履歴と参照情報の不足をまとめて補う。** 解決時に公開された札名を同一card_idの履歴へ保持し、保存再開後も参照可能にします。旧保存で記録されていない名前を現在の名称から捏造しません。山札の種類別残数・参照一覧、公開済み／既読の過去本文、主体と調査記録を結ぶ公開キーも既存要求に沿って実装し、UIが私的saveを読まずに使える応答例を添えます。未知情報が混ざる項目は公開条件を決め、範囲を明示してください。
4. **身構・常時軽減の統一案を具体化する。** ユーザーの常時分も身構へ含める方向を受け、現行との差、常時分の持続、一閃倍率、機転消費を少数の具体例で整理します。既採用仕様と通常の実装判断で決められる部分は進め、遊び方が変わる未決部分だけ推奨案・影響を付けてユーザー判断へ残します。細部を採用済みにせず、未決の間も現行規則による予測公開と他の追補を完成させてください。

公開入口は既存APIとの互換性を保つ追加を基本とし、不可避な変更は版・対応表・UIへの移行方法を明示します。UI描画・専用コードに必要な変更は、公開値の受取例と対象ファイルをUIへ渡し、別担当の実装を先取りしません。
