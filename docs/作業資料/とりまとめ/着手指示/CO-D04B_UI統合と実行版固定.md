## B1〜B4

| ID | 実施・完了条件 |
|---|---|
| B1 同期と受領範囲 | 自会話末尾・自Work・未保存差分を確認保全。最新計画フォルダ全体を必須同期し、設計／UIの最新HEADと公開済み差分を確認。受領元SHA・必要なUI専用path・既に受領済みの範囲を記録 |
| B2 UI統合 | 既存の受領方式で必要なUI専用差分を設計枝へ取り込む。共通本体・シナリオ・過去固定試験・自担当のD04A成果を保持。UIに含まれる旧計画コピーで最新計画を戻さず、統合後に全path/blobを再照合 |
| B3 開発者用の試作実行版 | 同じCampaignを使う通常入口、ビルド／起動手順、必要ファイル・依存と使用版を揃える。新規開始→探索→帰還→取得／編成変更→再出発を辿れる構成を固定し、通常入口と一時保存の会話内入口を区別する。統合で影響した経路・参照先だけ必要確認 |
| B4 保存と受渡し | 専用領域`docs/検証/接続条件/co-d04b/`等へ統合記録・起動案内・確認結果・残件を保存。開発・試作確認の担当者が再取得・起動できる実行一式または再現可能な生成手順とファイル一覧を用意し、通常公開・読戻し・自Work引継ぎまで完了 |

既存のUIビルドと開発者用起動手順を整理し、別UI・新しい保存装置・新サービスの開発へ広げない。現在の試作はメモリー保持でよく、選んだ実行条件と終了時に消える範囲を明示する。既存IndexedDB入口・コードは保全するが、実保存合格をBの前提にしない。黙ってMemoryStoreへ切り替えて永続化成功に見せない。M1の利用者向け提供物・起動方法はCO-M1Rの結果で別途具体化する。既存33項目・旧37件・50件の結果は出典付きで継承し、統合で影響する差分または具体的な失敗だけを再確認する。UI本体を再実装せず、必要なUI修正があれば問題箇所・再現・期待結果をUI担当へ引き継ぐ。

試作実行一式には本編入口とD04A検証入口の用途を示す。開発用サーバーの手順と利用者向け配布手順を混同せず、実行確認できた環境と未確認を記録する。メモリー保持での一巡確認は先行できる。D04Aの入力準備・結果JSON取得手順は既存原本へつなぎ、同じ検査を新たに作り直さない。通常PCのブラウザーや将来のローカルCodexで実行する場合も、現在のCloud Browser制限の迂回とせず、正当な利用権限を持つ環境で既存手順を実行する。Codex設定の導入・外部公開を本依頼の必須作業にしない。

## 担当境界・報告

設計集約はUI成果の受領・統合と通常入口・使用版を固定する。新たなUI見た目調整、札・心得・価格・素材の仕上げ、探索先追加、旧試遊への差替えは今回含めない。ビジュアルの未公開成果はこの統合の前提にしない。master更新・新規PRの乱立・強制更新は不要。

CO-M1Rで実現方式を先に具体化し、D04E/Aは保留して必要性を再評価する。B1〜B4は試作統合として継続可能。Bが保存関連コードを変えた場合は影響を引き継ぎ、必要な確認を選定方式で行う。試作統合版の固定を、利用者向けM1提供物・永続化・実操作・人評価の完了にしない。

[完了報告と引継ぎ規則](../完了報告と引継ぎ規則.md)に従い、最終応答冒頭に「今回の依頼全体（CO-D04B）は完了／未完了」と示す。B1〜B4、成果commit・入口・起動手順、未保存／未反映、確認済み／未確認、D04Aの残件、利用者に必要な操作があれば実行可能な具体手順を自Workへ保存して提示する。
