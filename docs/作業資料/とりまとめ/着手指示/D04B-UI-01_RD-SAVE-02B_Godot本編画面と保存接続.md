### 表示・操作・保存の条件

- 1920×1080・16:9を基準に、全体縦スクロールなし、了承済みの配置と操作を継承。専用UIの再設計・画像の新規制作・数値調整・探索先増設は追加しない。既存素材・仮入力は採用状態を変えず利用し、Godotへの変換で必要な差は対応表へ記録する。
- 表示はInspect／Executeの公開viewを原本とし、保存DTO・乱数・非公開札順を画面へ渡さない。UIの選択・ドラッグ・窓・未確定案と、Coreの確定状態を分ける。
- 画面のイベントから同一commandを重複適用しない。同期保存APIの実行と描画スレッド・ノード寿命の扱いは、採用版の公式資料で確認し実装判断を記録する。複数の所有者や並行書込みで回避しない。
- 明示保存された既存draftは保持しつつ、通常のドラッグごとにsave_draftしない。拠点の札組・心得は確定時の保存を使い、画面用の独立保存を増設しない。
- 起動診断・復旧のUIは既存APIの結果に対応させる。未来版・壊れた保存を無断上書きせず、技術情報だけのエラーコードで利用者に判断させない。詳細ログは別に残す。

### 確認の範囲と実機への受渡し

既存72試験は変更の回帰確認として利用し、Core／保存部の全比較を新たに作り直さない。追加確認はGodotの画面・入力・session寿命・保存結果表示との境界に集中する。正常一巡は自然初回、そこで使えない取得・変換と失敗分岐は別の合法fixtureへ分ける。検査用の残高・状態を通常起動へ混入させない。

通常入口と同じ画面経路で合成操作を行い、ファイルと次回起動まで確認する。CLIだけの成功やモック画面をGodot本編接続の成功にしない。可能な実描画経路があれば起動・準備・探索・帰還・異常表示の画像を保存し、実表示のはみ出し等を点検する。画像を取得できない場合は実描画を未確認と明記し、headlessのノード寸法だけで表示合格にしない。

利用者が実機で確認できる起動手順・場面・期待結果を新しい検証資料へまとめる。今回は本編の実装・自動接続確認を区切りとし、Windows11実マウス・文字・音・DPI・GPU性能、正式ZIP差替え・人の操作感は後続の実機受入に残す。実機での成功は実測結果が揃ってから判定する。

既存基盤が提供するWindows確認経路が新本編で阻害された場合は、失敗した工程・再現・影響を特定し、独立した作業を終えて未了範囲を引き継ぐ。Cloud Browserのlocalhost:8000を代替検査経路へ戻さない。
