| ID | 実施内容と終了条件 |
|---|---|
| A1 実行条件 | 同一originの実ブラウザー・IndexedDBで専用DB／使い捨て保存枠を使用。OS・ブラウザー版・使用コードSHA・入力出典・起動／再現手順を固定。既存の確認入口を最小限で流用する |
| A2 実保存の限定確認 | 下表の代表経路を、現在のcontrollerと実IndexedDBで確認。既存の保存例・移行例を使い、作例用の新しい札・報酬・価格は作らない。保存前後と再読込後の実結果を記録 |
| A3 不具合対応 | この確認で見つかった保存・移行・二重適用等の具体的な不具合だけ担当範囲で修正し、該当経路を再確認。公開契約を維持し、仮データの性能調整やUI原本の変更へ広げない |
| A4 保存・引継ぎ | 新しい専用領域`docs/検証/接続条件/co-d04a/`等へ結果・使用版・再現物・残件を保存。通常公開・読戻し後に自Workの完了引継ぎを提示。修正があればUIへ渡すコードSHAと影響を明記 |

| 代表経路 | 確かめること |
|---|---|
| 新規作成・再読込 | 実保存後、ページを開き直した新しいcontrollerで同じ状態を再開する。初期化や無記録のMemoryStore切替で成功扱いにしない |
| 取得・編成の一括確定 | 既存の適切な保存例から公開操作で確定し、所持・残高・候補消費・編成が一体で永続化する。未確定の確認／取消は保存を変えない |
| 探索中と帰還後の再開 | 対応する既存保存例を読み、進行・編成・獲得／精算状態が再読込後に保たれる。機械的な保存照合を人の通し試遊とは扱わない |

## UIとの境界と終了

UIは公開済みD03Rを基点に、了承済み0.15.1の本編接続を進める。本タスクを必要と判断して再開する場合、最新UIの完成・取込みを待たず公開controllerと既存保存例で確認できる。UI担当の原本を取り込んで同じ接続を別実装したり、進行中のUI枝全体をマージしたりしない。相互の終了を開始条件にせず、CO-M1Rに対応する提供物・保存の成果と統合版を揃えてCO-D04の実確認へ進む。

UIが使用中の公開契約に変更が不可欠な場合は、必要性・対象・差分・互換版を具体化してとりまとめへ引き継ぐ。相手へ同期済みと仮定せず、共有条件に影響しない確認・保存を先に終える。新しい正式データの採用や全体バランスの調整は含めない。

実行環境に阻害があれば、実行できた範囲・正確な失敗・未実施項目・再開に必要な条件を保存して「未完了・外部条件待ち」と報告する。文書だけで実確認完了としない。実行可能な準備・保存を済ませ、常時ポーリングや目的を広げた代替検査は行わない。

[完了報告と引継ぎ規則](../完了報告と引継ぎ規則.md)に従い、最終応答冒頭は「今回の依頼全体（CO-D04A）は完了／未完了」。A1〜A4、成果commit・使用版、確認済み／未確認、依頼内残件、ユーザー判断／作業、UI・D04への受渡しを自Workへ保存して提示する。完了時にD04のUI統合や新規試遊を自動開始しない。
