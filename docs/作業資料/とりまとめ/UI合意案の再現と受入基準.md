## 判断の基準

ユーザーの2026-10-02指示：UI改善での承認は合意案に対するものであり、そこからずれたUIは未承認。**最終的に合意案へ合わせることを実装・審査の終了条件にする。** 既了承の細部を再現する作業は、任意の見栄えの仕上げや新しいデザイン提案ではない。

従来レビューの38項目は機能・情報・大きな配置を中心とし、review.jsonのdifferences_not_promoted_to_defectsにはHTMLとGodotの文字組・標準スクロールバーを描画部品の違いとして扱った記録がある。また計画0.31は7指摘とU01・変更影響箇所の再確認に限定していた。この組合せでは細かな不一致を取りこぼすため、今回訂正する。旧判定は当時の記録として保全し、機能の既確認を取り消さない一方、**外観適合を既確認のまま引き継がない**。

「試作」「Godot標準部品」「実装上の都合」「操作できる」「人が後で気付けば直す」は許容差の根拠にしない。AA・フォント描画などエンジン差も無条件で免除しない。差異を解消できない場合は、再現を試みた根拠、合意案と実装の実画像、代案、影響を具体化してユーザーの個別判断へ渡す。未回答・沈黙・成果保存を承認へ変換しない。

## UI原本担当が固定するもの

1. 原本72d0eb58と最新の明示された後継・了承記録から、M1の各画面・状態について「どの合意案が正か」を示す。原本コミット・path/blob・該当節・了承根拠・後継関係・基準画像を対応づける。枝の最新保存全体を一括で承認済みにしない。取得UI5.1、UI0.14.8、空状態0.15.1、接続0.16.0を一律同じ承認範囲とも扱わない。
2. 準備・取得編成、探索、主体／行動順、手札／場、詳細／予測、本文・帰還・記録・共通案内等のM1対象を、通常・選択・ホバー・固定詳細・ドラッグ可否・確認・空・無効／ロックなど適用する状態で列挙する。未採用の全30画面や新規素材制作には広げない。
3. 同一FHD論理寸法・表示倍率・了承済み暗色・等価な公開状態／文言で比較する。実ウィンドウ寸法、外側縮小率、フォント、OS／描画環境を記録。合法な状態を使い、通常セーブに触れない。内容の差と描画の差を混ぜない。
4. 位置・幅高・比率・余白・整列、文字種／サイズ／太さ／行高／改行、色・不透明度・罫線・角・影、札枠・アイコン・画像の大きさと切抜き／重なり、詳細窓・スクロールバー・選択／ホバー／無効表示、合意済みの表示タイミングを確認する。共通部品は規格と使用先を対応づけ、特殊状態も落とさない。
5. 実際の原本／実装の全画面画像と必要な拡大比較、寸法・スタイル値を根拠にする。差分画像・重ね合わせは補助証拠で、生成した模写・コード上の数値・ピクセル差の総数だけを合格根拠にしない。取得不能な画像・再現不能な状態は未確認として処置と担当を示す。拒否済みlocalhostアクセスや制限回避は行わない。

成果はUI側の既存godot-ui-review-01/配下に、原本対応表・再利用可能な寸法／スタイル基準・状態一覧・比較画像・差異台帳を保存する。例：visual-baseline.md/json、visual-diff.md/json。ファイル名は既存形式へ自然に統合可。とりまとめ側には専門仕様を複製して独立編集しない。

## 差異台帳と判定

各行にID、画面・状態・部品、原本／実装SHAとpath/blob、期待値と実測／画像、承認根拠、判定、影響、修正担当、必要な確認、解消証拠を記す。

- **一致**：合意案の再現を証拠で確認。
- **不一致・修正必要**：細部を含め、合意案との差異が残る。
- **未確認**：原本の根拠・画像・実装状態・描画確認等が不足。合格にしない。
- **個別承認済み例外**：差異そのものに対するユーザー承認の記録があり、その範囲だけ適用。
- **根拠付き対象外**：そもそもM1に採用されていない画面・機能等。合意案からの見た目の差を仕上げ扱いでここへ移さない。

機能の適合、外観の適合、実機受入、人の試遊を別欄にする。既存23適合の機能証拠と根拠ある対象外4件は保全し、外観の網羅性は今回の基準で点検する。既存の大きいPNG3件の取得不能も解消済みと書かない。

## 配布へ進む終了条件

M1対象の了承済み暗色の合意案に対して、全対象画面・状態が台帳に対応し、**未承認の差異と判定に必要な未確認が0件**であること。例外が必要なら差異単位の明示承認が先にあること。加えて既存R01〜R07・U01と変更影響の機能確認が成立し、固定対象SHA・基準版・検証環境・証拠が対応していること。

UIレビューの調査・指摘提出は、要修正を残して完了できる。実装提出も成果として受領できる。しかし、それをUI適合・配布許可・M1受入とは扱わない。描画不可の2ケースは合法な公開状態での証拠、または既存契約に基づく今回の適用外の根拠を示すまで必要未確認として保持する。再現できないことだけを免除理由にしない。

本編修正は、共通部品・テーマ／スタイル値を基準に揃え、画面ごとの推測で近似を増やさない。代表画面の比較を早い区切りで行い、差異が残った実装を全画面へ広げない。新規・変更コードの日本語コメント・教材は同タスク内で更新する。最終的な担当間の照合は固定提出に対して行い、毎部品のユーザー承認待ちは作らない。

配布でソース・フォント・資源・テーマを変更した場合は影響する外観の確認を追加し、無関係な機能試験を一律反復しない。人は新版で実機表示・操作を確認するが、細かな差異の全列挙やコード・Git・ビルドを担当しない。
