## UI差異への対応

最終的に合意案へ合わせる目標は維持するが、従来手順だけではその保証が不足していた。初回レビューには文字組・標準スクロールバーをエンジンの違いとして扱った記録があり、計画0.31は7指摘等の再確認に限定していた。ユーザーの今回の指示に従い訂正する。

1. UI改善が合意案の版・画像・了承根拠と、画面／状態／部品ごとの寸法・スタイルを固定する。
2. M1全対象の外観を比較し、細かな差異までID付きで記録する。「試作」「Godot標準」「見栄えの仕上げ」を免除理由にしない。
3. 同じ本編Codexが基準に沿って修正。共通部品・代表画面を先に合わせて横展開する。ユーザーへ違いの全列挙を委ねない。
4. UI担当が固定修正SHAを再判定し、未承認差異・必要未確認0件を配布条件とする。差異を残す必要がある場合だけ、具体的比較と代案をユーザー判断へ渡す。既了承案の承認を取り直さない。

[UI合意案の再現と受入基準](../UI合意案の再現と受入基準.md)、[レビュー指示0.4](../着手指示/UI-GODOT-REVIEW-01_了承UIとの適合確認.md)を参照。専門の外観数値・基準画像はUI原本担当が保存し、とりまとめは担当・依存・受入条件を更新する。
