## 1. 今回受領した根拠と適用範囲

ユーザーの説明を原文で受領した。

> こちらとしてはUI確認時に暗色のものしか見ていなかった（そもそも明色に関して存在を伝えられていない）  
> なので暗色前提で諸々確認し承認している  
> この前提で調整できるか

続く質問「暗色モードってウィンドウ背景が概ね緑っぽい色になるやつで合ってる？」に対し、UI原本の暗色値を確認した。探索紙面は#202820／半透明窓#202820e6、journey／取得shellは#1d2b27、文字は明るい色。暗い緑〜緑灰色の表示を指している。これは識別用の原本例で、全背景を同じ色にする新仕様ではない。

| 区分 | 現行の扱い |
|---|---|
| 既存UIの了承された表示 | 暗色で確認・承認したという今回の説明を根拠に記録。対象画面・状態・後継は既存A01〜A06等の了承範囲を維持 |
| M1の再現条件 | 原本の暗色値・状態差・透過・影・gradient・文字・細部を再現。暗色を任意仕上げ／未採用候補へ戻さない |
| 通常表示 | OS設定によらず暗色。撮影だけのdark強制を通常表示の修正とみなさない |
| 明色／二色切替／OS自動切替 | 今回の採用範囲・実装／受入の必須条件から外す。新しい設定画面・保存項目は追加しない |
| 既存lightコード／画像／CI | 履歴・検証用資料として保全。構造／機能へ再利用する範囲と暗色での再確認を区別 |
| 最終画風・素材の正式採用 | 既存の留保を維持。今回の暗色での了承を、未採用の新しい素材や追加routeの一括承認へ拡張しない |

[旧出所調査](明暗モード_出所と承認範囲の調査.md)は説明前の保存原本調査として保全。二種類／OS連動の採用記録を確認できなかったことは維持するが、暗色の提示／了承が未確認という現行判断は今回の説明で更新する。過去にこの説明が保存済みだったと書き換えない。
