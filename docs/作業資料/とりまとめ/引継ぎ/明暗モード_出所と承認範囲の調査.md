## 2. 現在コード上の「モード」の意味

現コード8e992501a8b4ac633ee78d6f41e66a2de431bdb2（実行コードc761cbf4）では、[AcceptedStyle](https://github.com/eckolo/crossweave/blob/8e992501a8b4ac633ee78d6f41e66a2de431bdb2/apps/crossweave-godot/Godot/Application/GameScreen.AcceptedStyle.cs)と[Layout](https://github.com/eckolo/crossweave/blob/8e992501a8b4ac633ee78d6f41e66a2de431bdb2/apps/crossweave-godot/Godot/Application/GameScreen.Layout.cs)が darkTheme = ThemeDarkOverride ?? DisplayServer.IsDarkMode() を使う。通常起動はWindowsの明暗設定に基づき紙面・文字・枠等の色を切り替え、検証時は[UiAutomation](https://github.com/eckolo/crossweave/blob/8e992501a8b4ac633ee78d6f41e66a2de431bdb2/apps/crossweave-godot/Godot/Application/UiAutomation.cs)の--ui-theme=light/dark、[verify.py](https://github.com/eckolo/crossweave/blob/8e992501a8b4ac633ee78d6f41e66a2de431bdb2/apps/crossweave-godot/UiProbe/verify.py)の--theme light/darkが撮影条件を固定する。GodotのThemeオブジェクト一般と、アプリが明暗二色へ切り替える機能は別。

旧配布元0765f158のLayoutには当該暗色処理がない。今回のOS連動追加は9月30日の既配布exeへ自動反映されていない。バイナリを新たに実行・検査した報告ではない。

## 3. 承認根拠の照合

- [正式参照版](https://github.com/eckolo/crossweave/blob/099d4adeaa025e78ca069c4eca0d54d75fdf0c3b/docs/検証/UI/readability/正式参照版.md)はUI-R-002 v0.15の概ねの方向性／参照方針を登録し、「仮のアイコン・背景表現・配色」を最終画風／素材の採用とは分けている。明暗二モード・OS自動連動の個別採用は記載されていない。
- [画面操作・描画方針](https://github.com/eckolo/crossweave/blob/099d4adeaa025e78ca069c4eca0d54d75fdf0c3b/docs/検証/UI/readability/interaction/画面操作・描画方針.md)は明色約88%／暗色約90%の窓透過率を併記するが、ユーザーが許容した半透明の試行値と説明している。窓透過の許可を二モード機能の採用へ広げない。
- A01〜A06の了承対応表は二段階取得／横三領域、探索FHD／選択と窓位置、ナビ統一、空状態、D03R接続、Windows保存を対象とする。明暗二種類・OS連動の採用はscope／user_recordにない。
- UI Work設定、UI検討、操作表示原則、取得画面了承、探索詳細了承、設計基本設計／要検討事項も照合した。明暗二種類をM1へ採用する明示記録は確認できなかった。

**確認できるのは「試作CSSに両配色があった」「ユーザーは提示UIの構造・操作・方向性を了承した」「現コードに明暗分岐がある」。これを「両テーマとOS連動をユーザーが採用した」へ読み替える根拠は不足する。**

U-C02は採否未確認と記載しながら、darkを廃止する承認がないことを残件の理由にしていた。採用を確かめる前に廃止承認を求める形であり、保存コードにある試作機能を既定の採用範囲へ押し上げやすい。とりまとめも採否の根拠を確定しないまま、その両テーマ確認条件を計画に継承していた。これが今回の拡大経路という判断であり、当初のCSS発案者／未取得会話での要求の有無まで特定したものではない。

## 4. 計画側の訂正と担当外への反映案

- **明暗二種類・OS自動切替の採用状態を「根拠未確認」に訂正・明示する。** 試作CSS・色の表・検証成功・dark廃止承認の不存在を採用根拠にしない。
- 本編D04B-UI-02は了承された提示UIと状態の再現・判断不要修正を継続する。採用未確認の二色対応の追加実装・仕上げ・全画面展開を判断不要の必須修正へ含めない。既存darkコード・色値・明暗証拠は保全する。調査を理由にとりまとめが削除・明色固定・設定追加を直接行わない。
- UI原本担当への反映案：B03／U-C02の「CSS宣言の存在」「ユーザーへ提示・了承された配色／状態」「明暗二種／OS連動の採否」「検証結果」を別欄にする。A01〜A06等で根拠を特定できない部分は試作／未採用候補とし、単に原本に残っていることをM1採用へ拡張しない。次の既存UI再判定に含め、今回別UI Workの追加起動・新規調査枠を作らない。
- 承認された提示状態を固定できる箇所の再現は継続する。採否未確認だけで色を任意変更・基準撤去せず、基準状態を特定できない具体箇所は既存UIへ返す。明色固定をユーザー判断済みと推測しない。
- 明暗二種の正式採用を新しく望む場合に限り、用途・必要性・実表示比較・実装／確認負担を揃えて具体的な採用案を人へ出す。今回はその新規採用判断をユーザーへ要求せず、人の新タスクを追加しない。

UI099d4adeへの57ID／17群判定は過去の固定レビュー結果として保全し、今回0件に読み替えない。未承認差異33・未確認ID3・必要15群は受領時集計で、今回の新規UI適合再判定は0。U-C02は採否／基準状態の不足として残すが、両テーマの実装／全画面検証が採用済みの一律条件という扱いは訂正する。その他の本編修正、合法入力、人H11〜H13、配布→実機→試遊／M1の担当・順序は維持する。
