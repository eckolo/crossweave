# crossweave — 仮置き・未決事項

版：0.11／2026-09-26（日本時間）。対象：当面の目標M1。担当：とりまとめWork。仕様の正式採用を代行する台帳ではない。

**仮置きがあることと、何を試しているか分からないことを分ける。** 選択理由・成長・進退・持帰りが仮処理で抜けている場合は本体の優先課題にする。性能・価格・素材を全て完成させるまで試遊を待つ方式にはしない。

## 制作コストの方針（2026-09-26訂正）

**「ひとまず遊べる形に」を優先する。仮データは利用可能。仮置きであることを理由に正式化へ全面移行したり、仮データを磨く作業を常設したりしない。** 現時点では次のAを推奨し、Bは対象・効果・追加負担を具体化した後の選択肢とする。

| 選択肢 | 進め方 | 利点・負担 | 現在の扱い |
|---|---|---|---|
| A：既存の仮データで接続を完成 | 現行入力を維持し、取得・編成・保存・再出発をつなぐ。進行不能・誤解・評価不能の原因だけ最小修正 | 遊べる版へ最短で進める。内容の面白さや製品バランスの結論には限界が残る | 推奨。UI本編接続P0を先行。仮の札名・絵・性能の仕上げは追加しない |
| B：少数の正式採用候補を整えて接続 | ゲームに残す意図のある札・心得を選び、役割・効果・設定の骨格と基準値を具体化。必要な制作だけ行う | 後に残る成果を狙える。選定・設計・採否変更の手戻りが増える | 選択肢・未割当。既存仕様に収まり追加負担が小さい場合や、内容不足で遊びを評価できない場合に具体案を比較 |

Bを採る場合も正式採用・全数値確定をM1の一律前提にしない。用途に必要な題材・効果の骨格が未定なら画像を先行量産せず、設計側で具体案と影響をまとめる。試行入力を「候補」と改称しただけでは選定にならない。最終採用判断は既存のユーザー判断の扱いを維持する。

Aで許す追加作業は、特定の接続・操作・評価を成立させる最小入力または修正。目的と終了条件を持たない数値調整、命名の仕上げ、画像生成・専用UIの追加・反復合成は行わない。共通runtime・保存・公開APIの整備は再利用する本体作業であり、仮内容の仕上げと混同しない。

制作手順の採用、試行への実装、元データの正式採用、個別画像の採用は別の状態。根拠は[今回の棚卸し](現状棚卸し.md)に固定する。

## 区分と実行条件

| 区分 | 例 | 扱い |
|---|---|---|
| 採用済み | 一致・共有循環、体勢、帰還時精算、取得・編成UIの了承済み方向 | 正本と最新ユーザー判断の差分は設計で更新。新方式へ旧種類習得・忘却返還を戻さない |
| 実装前に接続条件が必要 | 保存状態の所有、実適用、帰還から再出発、案件状態と報酬の対応 | 担当が入力・出力と失敗条件を先に定める。仕様変更がなければ実装判断として進める |
| 試行として固定可能 | 初期枚数、個別札・敵の数値、候補価格・数、装備容量、変換率、seed | 目的・適用版・維持前提・差替え先を記録。UIへ製品定数として埋め込まない |
| 意味が伝われば仮素材で進められる | 背景・道具絵・短文・音の未完成 | 判断対象と結果を識別できるかで判断。見えない／意味を誤るならP1へ上げる |
| 正式化にユーザー判断が必要 | 未採用の装備方式、個別内容の正式採用、製品全体の範囲 | 比較・推奨・影響を担当が具体化。試行の実行許可を同じ判断として求め直さない |

TMP-01〜05は「どのように接続するか」を先に具体化する。方式・値・内容を全て正式採用する必要はないが、実装担当が無記録で穴を埋める状態ではCO-01を完了にしない。TMP-06〜09も担当と差替え条件を持ち、試遊結果がどの仮条件に依存したか追えるようにする。

計画0.4では[CO-01実装基準](CO-01_実装基準.md)を確定し、実装前の対応不明を解消した。P-01/P-02はM1試行に使用する。各項目は実装・確認が終わるまで台帳へ残し、文書照合だけで仮置き解消済みとはしない。素材「Mを1個」へ新しい用途・価格を補わない。

## 新しい仮置きを加えるとき

既存IDに追記できるものは追記する。新規には、目的、担当、依存タスク、採用済みの維持前提、正確な試行値・素材、固定する入力と版、結果から言える範囲、解消・再評価の条件を記録する。本人の試遊中に入力を変更せず、別試験へ分ける。

未決項目の解消は「文書に書いた／試作へ接続した／正式採用した」を分ける。目標に不要な新設定が増えた場合は、その設定を完成条件へ追加せず、後段または独立した候補として全体計画へ戻す。
