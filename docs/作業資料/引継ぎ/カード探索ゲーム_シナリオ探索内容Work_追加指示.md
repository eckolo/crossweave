## 2. 追送用の追加指示

既存の「代表案件のシナリオ・探索内容設計Work」（`20260912-scenario-content`／`design/scenario-content-20260912`）を続行してください。設計本筋側で挙げた「探索コンテンツ設計」は、このWorkの既存範囲と重なるため、別のWorkへ分ける必要はありません。

原引継ぎの、一案件を依頼受領から帰還・次の準備まで通す作業へ、次の観点を補ってください。既に書けている項目は対応箇所を示せば足り、同じ内容を作り直す必要はありません。

### 1. 主要な判断を、選び方による得失まで書く

対象を残す／除く、敵を先に狙う／道を進む等の主要な判断について、選ぶ時点で分かる情報、各選択の利点・負担、その後に変わる対象・札供給・消耗・成果を対応させてください。

異なる札構成や心得、現在の借り札によって、選び方が変わると見込む理由も添えてください。供給元の除去や最大の進展を出す札が、常に同じ正解になる構成は点検対象です。特定の希少品を唯一の解法として要求する案は、通常の準備による対処と区別してください。未実測の優劣や勝率は補わず、仮説として記します。

### 2. 一往復の中で、判断が変わる地点を示す

最初に持込の狙いが働く場面、成果を得る場面、既存の踏破で成果を保護する場面、続行・帰還を考える場面、後半で対処が変わる場面を示してください。毎回同じ順序に並べる義務はありません。

道のりや耐久を減らす反復について、何を考え直す余地があるか、単に長さを増やしている部分がないかを点検してください。必要な途中の判断と、短縮・省略できる描写や区間を分けます。演出や画面操作の長さは各担当への確認事項とし、本文上の所要時間を実測扱いにしません。

### 3. 帰還後の変更と、次の出発を具体例でつなぐ

成功時と、途中帰還または失敗時について、持ち帰る成果・残る調査記録から、札の入替え、心得の組み直しや装備変更、候補からの取得、別の探索先の選択へどうつながるかを示してください。各操作を全て行わせる必要はありません。

新しい品を受け取るだけで終えず、「何が分かった／何を得たため、次に何を試せるか」を短く具体化してください。実際の保持・喪失と、取得物が使える時点は本筋の現行仕様に合わせます。

### 4. 別の攻略体験との違いを、短い比較で残す

原引継ぎの候補比較を活かし、仮選定した一本と性質の異なる候補について、狙う準備、現地の判断、消耗の仕方、成果の役割の違いを簡潔に残してください。初回から二本目を完成させる必要はありません。既存A〜Eへの名称・内容の固定や、新しい分類体系の作成も不要です。

### 5. 設計側が試せる確認事項を添える

主要な判断に場面IDを付け、次の項目を小さな表でまとめてください。

- 参照するWB-ID、既存の札・心得・効果または新規案ID。
- 比較の前提となる準備・公開情報・開始状態。数値を仮置きした場合は値と出典。
- 比較したい選び方と、後続状態のどの違いを見るか。
- 狙う体験と、どのような結果なら内容を見直すか。
- 既存仕様への接続箇所、未採用案への依存、新機能の要否、描写のみの部分。

このWorkの初回成果は内容案と比較仮説です。共通エンジンの改修や大量の数値試験を追加の完了条件にしません。効果・数値の仮案は提案できますが、横断的なバランス調整と正式仕様への統合は設計本筋が行います。素材要求はビジュアルWork、表示する内容はUI Workへ渡せる形にしてください。

## 3. 設計本筋から渡す前提と、受け取った後の担当

確認時点の本筋は基本設計0.53・D53。候補選択型の補助取得、三候補固定ではない点、踏破難易度等による変動の許容は採用済み。価格・候補数範囲・配分・更新条件・総装備コスト方式は試行または未決定。ATの購入接続は、取得札を含む自由な構築変更、新UI、人の評価まで完了したものではない。

設計本筋は、共有の場・循環・構築の関係、探索の長さと進退、成長と装備、報酬と再挑戦を共通条件で検証する。成長段階・探索先解放・一通り攻略した時点の手段を仮置きし、物語上の節目は世界観・シナリオ側と照合する。現在の課題と着手順は[要検討事項](../カード探索ゲーム_要検討事項.md#design-priorities-after-work-split)を参照。

別Workの成果待ちを全作業の停止条件にせず、本筋は既存A/B/Cで比較を進める。代表案件を受領したら、その内容を新しい固定条件として検証し、内容上の課題と共通ルール上の課題を区分して返す。各Workの原本・既存の固定試験を直接上書きしない。
