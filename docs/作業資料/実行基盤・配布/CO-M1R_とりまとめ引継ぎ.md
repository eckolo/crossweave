## 2. 採用方針と実装前に固定する項目

| 区分 | 内容 |
|---|---|
| ユーザーが選択済み | 当面はGodotを採用して進める。今回の技術選定待ちから外す |
| 継続する開発構成 | Godot .NET＋C#。ゲーム状態・命令・計算は純C# Core、Godotは画面・入力・音・資源と接続。独自UI／演出を既製の演出に合わせることを要件にしない |
| M1の提供計画 | Windows 11 x64、本人向け限定ZIP、通常プレイはオフライン。プレイヤーにGodotや開発SDKを要求しない |
| 最終アプリへの継続 | 同じアプリを拡張しSteamへ提供する。実績・Cloud・overlayは必要範囲を別段階で接続。Steam Deck・他OS・ゲームパッドは未約束 |
| 版の固定 | RD-ENV-02で安定版Godot.NET・対応templates・SDK・TFM/C#・renderer・test adapter・拡張を固定。.NET10／C#14・Compatibilityは初期確認候補で、組合せの実出力成功は未確認 |
| テスト・IDE | 一つのリポジトリー／solution／普段使うC# IDEを入口にし、Core・ファイル・Godot画面の試験を分類。Godotエディターはシーン／資源の制作確認。IDE変更・購入は今回の完了条件にしない |
| 保存 | `user://saves/local/m1.json`。custom user dir名を`crossweave`に固定する案で、Windowsは`%APPDATA%/crossweave/saves/local/m1.json`。配布フォルダーから独立 |

GodotのUI・文字・描画等の基礎と制作支援を利用でき、商用・Steamにも公開事例がある。一方、C#とノードの境界・寿命、独自配置・入力・演出の所有者、テスト環境は管理が必要。これらを受入と編集境界へ残した。ユーザーがどの論点を最終決め手にしたかは推測しない。普及度・有名作だけで本作の性能や作業量を保証しない。

## 3. 保持する性能・配布条件

- 基準PCは低消費電力4コア級CPU・8GB RAM・SSD・内蔵GPU、Windows 11 x64。FHD60fps、視覚応答100ms以内、常用メモリーはアプリ関連合計500MB程度を目標。
- 起動は初画面と操作可能時点を別計測。起動画面・進捗等で体験を補えるなら5秒超を一律不合格にしない。
- 配布は通常権限・開発環境不要・依存同梱。Export Projectで作った実行一式をZIP化し、資源だけのExport PCK/ZIPを完成配布物としない。
- 新規・取得／編成確定・探索の一手の確定境界・帰還精算で保存。中断を撤退へ変えず、同runと乱数の続きへ復帰。二重払い・二重報酬・更新での消失を防ぐ。
- 全項目は開発目標・計画であり、最低スペック確定値・性能合格・保存検証成功ではない。
