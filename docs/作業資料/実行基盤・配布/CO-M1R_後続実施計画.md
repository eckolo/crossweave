# CO-M1R 後続実施計画

版0.5／2026-09-27。**全て後続割当案・未着手。** 現行推奨はGodot 4系 .NET版＋C#。主要対抗はMonoGame＋C#。C#習熟と独自UIの追加条件は[C#対応と独自UI](CO-M1R_CSharp対応と独自UI.md)。ユーザーによる試作コードの全面作り直し許容を受け、Electronホスト＋既存UI受領を前提とした0.1の計画を差し替える。[方式案](../../仕様案/カード探索ゲーム_M1実行基盤と配布案.md)・[条件と再比較](CO-M1R_性能・配布条件での再比較.md)を入力とし、とりまとめが採否・担当・統合先へ反映する。今回の稼働は本Workだけ。

**統合先の提案**：M1ネイティブ実装は新規アプリ統合枝で管理し、担当はアプリ実装・統合。仕様原本・既存試作・UI設計原本の担当を一方的に移転しない。今回の自Work成果は`design/runtime-delivery-20260926`に保存し、横断計画は`ops/project-coordination-20260913`のとりまとめへ引き継ぐ。

各後続Workは計画全体→必要な共通仕様の順に同期する。新アプリと基盤の相互必須同期を作らず、固定成果を順次受領する。新実装を始める前にとりまとめが具体的な担当ファイル・統合先を設定する。

### 0.3で追加した確認

- RD-ENV-02は.NET10／C#14を第一の確認候補とする。Godotの公式最低基準.NET8と、採用するTFMを分ける。.NET8／9を長期固定する前提にしない。SDKを入れただけで対応確認済みとしない。
- RD-PROOF-02は標準UIだけの見本では足りない。独自配置とContainerの競合、見た目と選択領域、演出中断・再入力、同一プロパティを複数制御が書く競合を確認する。独自の演出を既製プリセットへ合わせることを合格条件にしない。
- 純粋なC#モデルをエンジンのNode／Resourceから分離し、Godotとの境界変換・interop・GCを確認する。GDScriptの併用を必須にせず、GPU効果のshaderは別言語になり得る。
- 配布は.NETランタイムを含め、開発SDKがない対象PCで実行確認。Godot4.6 C#のWeb出力は未対応であり、ブラウザー版の自動提供は約束しない。Steam用拡張もC#呼出経路と.NET出力との組合せを固定。

### 0.4の多角比較から追加した確認

- [Godot／MonoGame比較](CO-M1R_GodotとMonoGameの多角比較.md)を選定根拠へ追加。GodotはCompatibilityを初期確認候補とし、必要な演出の対応範囲を固定する。対抗MonoGameはDesktopGL＋.NET10を初期候補とし、UI・フォント補助の有無と版を明示。WindowsDXを使う場合は追加runtime等の条件を含める。
- 同じ素材・日本語・機能を揃え、空のMonoGameと機能を積んだGodotを比較しない。文字差替え・札追加・演出順変更の作業量も記録する。全候補の同時実装は開始しない。
- 日本語追加文字、句点優先改行、拡大時品質、DPI、フォーカスを確認。Godot内蔵ProfilerでC#を計測済みとせず、外部.NET計測とGPU等の観測を分ける。
- 配布物はSDKなしのPCで音・入力・終了再開まで確認。Steam販売経路とゲーム内API接続を別項目にし、拡張未確認だけでM1全体を待機させない。

### 0.5のAI支援時の作業量予測

- [作業量予測](CO-M1R_AI支援時の作業量予測.md)は未実測の相対モデル。Godot=100に対しMonoGame＋補助120〜150、自作多め140〜190。確定工数・納期・最終ゲーム全期間の倍率へ転記しない。
- RD-PROOF-02では人の有効作業、AI／ビルド待ち、実操作確認を分ける。初回作成と文章・札・窓寸法・演出順の変更を分けて測る。基礎準備、基盤への調整、確認修正の内訳から再見積もりする。
- 対抗との直接比較が選定に必要な場合は、小さい同範囲を順番に比較する案。共通の仕様理解や素材準備を分離し、2回目の実装が学習済みになる点も記録する。全体の二重実装・他Work起動・サンプルへの自動続行はしない。

## 仕様判断が必要な具体点

新実装における仕様通りの計算・状態管理はアプリ担当の責務。次の意味が不明／変更される場合だけ既存原本担当へ渡す。

1. 丸め、同時解決順、乱数・配札・時刻の扱いが言語差で変わる場合。固定seedの試験は乱数方式の差も明示し、都合よく期待値を上書きしない。
2. 取得・変換・帰還で残高や個体、候補の寿命・知識・喪失が変わる場合。
3. 再開点の変更によって巻戻し・再抽選・二重精算・中断時撤退が生じる場合。
4. 必要と判断した旧保存の移行で、失われるゲーム上の意味がある場合。

ファイルパス、保存キュー、UIイベントの重複、配布依存等は原則アプリ／基盤で扱う。ゲームバランスの判断待ちを、仕様通りに資料化・通常保存できる作業の停止条件にしない。

## 配布・引継ぎ

限定ZIPの大型生成物は既存運用に合わせ、Dropboxの登録済み領域配下に版別の新規パスを追加する案。候補は`releases/m1/<版>/crossweave-m1-<版>-win-x64.zip`。現時点で登録・生成・アップロード・共有は0。GitHubにはコード・軽量資料・manifestを保存する。Steam配布は別段階で同じゲーム内容・保存互換を継続する。

受渡しにはソースSHA、Godot／templates／renderer／拡張の版、生成手順、配布hash、基準PC、性能の測定方法と結果、保存形式・互換範囲、通常開始とfixtureの区別、未確認一覧を含める。プレイヤーには入手・起動・更新・再開の案内を渡す。

とりまとめには、0.1のElectron前提・0.2のGDScript優先を自動適用しないこと、Godot .NET＋C#推奨は未採用であること、D04Bの責務を再設定すること、次の作業が代表サンプルでの方式確認であることを引き継ぐ。本Workから他Workを起動・送信しない。
