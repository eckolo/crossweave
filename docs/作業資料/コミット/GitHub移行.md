# GitHub移行記録

## 対象と保持方針

移行先は `eckolo/crossweave` の `dev_design_tmp_assembly`。移行基点は `f4a87bb6ff3b13ccbe2ac164a8a8148b01259409`。この基点までのPush済み履歴を保持し、Dropboxの未コミット文書6件の原本保存と運用変更を分けて記録する。masterの更新、強制Push、既存履歴の書き換えはしない。

## 未コミット文書の保全

取り込み元は2026-09-09に取得したDropboxの現行ファイル。各ファイルをサイズとDropbox content hashで照合した。原本保存ツリーは `b485c159c52de6ea2617b01f31d6c6b8d8135aef`。詳細な元データのSHA-256・Git blob SHAは[照合記録](GitHub移行照合.json)に記録する。原本保存コミットでは6件を取得時のバイト列のまま格納し、その次の運用変更コミットでREADME・案内リンク等を調整する。

ゲーム内容・採用状態・過去の試験結果は再解釈しない。基本設計0.36と統合検討68〜71章の到達点を引き継ぐ。

## 外部化

GitHubで追跡済みの再現ZIP4件を現行ツリーから除き、未追跡の回復構築ZIPと合わせてDropbox正本の5件を[外部成果物一覧](../../検証/外部成果物.md)へ記録する。Dropboxの実体は削除・変更しない。小さい画像と既存bundleは保持する。旧ZIPはGit履歴に残る。

## ローカル作業ツリーの扱い

GitHubへの内容反映と、ユーザーPC上のHEAD・インデックス・未コミット状態の整理は別。この移行では後者を操作していない。未コミット表示が残っていても、内容が移行先へ保全されたこととは矛盾しない。

旧Dropbox同期フォルダで、いきなりpull、reset --hard、cleanを実行しない。GitHubでのZIP追跡解除がローカルでファイル削除として適用されたり、残存差分と競合したりする可能性がある。同期する前にREADMEとdocs一式をリポジトリ外へバックアップし、移行照合記録と比較して移行後に追加した独自差分がないか確認する。

当面はGitHubの作業ブランチを直接利用するか、別ディレクトリに新しくcloneすることで、旧作業ツリーとDropboxの原本をそのまま保全できる。旧作業ツリーの整理は必要になった時点で別途行う。

## 継続運用

正本の入口はルートREADME。大型ZIP以外をDropboxへ二重保存しない。通常の更新・コミット・対象作業ブランチへのPushは継続してよい。ChatGPTのプロジェクト設定欄は[置換文](../プロジェクト設定.md)へ更新する。
