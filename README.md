# crossweave

カードの属性一致と共有の場・回収山を使う探索ゲームの設計・試作プロジェクト。ゲーム名は暫定。最重要の評価軸は「これで面白いかどうか」。

<a id="source-of-truth"></a>
## 正本と作業ブランチ

設計文書・コード・軽量資料の正本保管先は **GitHub `eckolo/crossweave`**。特定ブランチを恒久的な最終正本とは定めない。`dev_design_tmp_assembly` は設計ひな形を詰める現段階の作業・集約先であり、全Workの更新先を固定するものではない。明示された引継ぎ・後継案内を優先する。

実作業前に[プロジェクト設定](docs/作業資料/プロジェクト設定.md#current-settings)と[Work分担・開始登録](docs/作業資料/Work分担.md#work-start)を読み、WorkID・目的に加え、**作業ブランチ／必須同期元／統合先と担当／共通文書の担当**を定める。新規独立作業の命名・登録はAIが行い、同一作業の引継ぎは既存設定を継承する。作業開始時・成果反映前の同期と、読み取り相談の扱いも同設定に従う。

大型成果物は[外部成果物一覧](docs/検証/外部成果物.md)に指定されたものだけDropboxを正本とする。正確なパス・版・対応条件は一覧で確認し、同じファイルを両方で独立更新しない。

## まず読む資料

上記のWork設定を確認した後、基本設計と要検討事項から担当する論点を特定し、関連する案・検証・経緯を読む。全履歴・全ZIPの読み込みや再計算を開始条件にしない。

| 確認したいこと | 参照先 |
|---|---|
| 採用済みのルール・現在の仕様版 | [基本設計](docs/確定仕様/カード探索ゲーム_基本設計.md) |
| 現在の進捗・残る判断・次の作業 | [要検討事項](docs/作業資料/カード探索ゲーム_要検討事項.md) |
| 未採用の候補・未決定の詳細 | [仕様案](docs/仕様案/カード探索ゲーム_仕様案.md) |
| 比較の経緯・判断理由 | [統合検討](docs/作業資料/カード探索ゲーム_統合検討.md) |
| 仮の試験入力・結果の適用範囲 | [試験条件](docs/検証/統合試作/カード探索ゲーム_試験条件.md) |

## 作業別の入口

設計検討・試遊の担当と成果の受け渡し先は[Work分担](docs/作業資料/Work分担.md)。試遊担当は[試遊Work引継ぎ](docs/作業資料/引継ぎ/カード探索ゲーム_試遊Work_引継ぎ.md)から、登録ブランチの試験記録・固定版・開始条件を確認する。全Workを試遊用の引継ぎへ誘導しない。

機械検証の報告・再現コード・ZIPの組合せは[検証資料一覧](docs/検証/検証資料一覧.md)。実行手順は各検証フォルダの案内を使い、再計算する試験のコミット・入力・条件を固定する。原案は [designmemo.tsv](docs/原案/designmemo.tsv) として保全している。

## 情報の確度と置き場

| 保存先 | 扱う情報 |
|---|---|
| `docs/確定仕様/` | 採用済みの仕様・方針。未決定値は確定扱いにしない |
| `docs/仕様案/` | 未採用案・未決定の詳細 |
| `docs/作業資料/` | Work設定・進捗・経緯・引継ぎ。過去記録は現行指示と区別する |
| `docs/検証/` | 試験条件・報告・再現用資料。試行値や数値結果を正式採用・面白さの実証としない |
| `docs/原案/` | 発想の出所。現行仕様と異なる場合は基本設計を優先する |

<a id="更新するとき"></a>
## このREADMEの更新範囲

READMEには概要・作業開始に必要な注意・資料への導線を置く。更新するのは入口、保存区分、参照先が変わるとき。通常の検討・検証・試遊の進捗は、それぞれの担当文書へ記録し、このREADMEへ追記しない。

仕様の採用履歴・検証数値・所感・コミット実績・試験ごとの固定SHA・仕様版の現在値は、担当文書で管理する。詳しい運用規則はプロジェクト設定に集約し、READMEで別の規則を並行管理しない。リポジトリ内は相対リンク、Dropbox専用の実体は外部成果物一覧へのリンクで案内する。
