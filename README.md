## 更新するとき

1. 正式な仕様・目指す遊び方の変更はユーザーへ確認する。試行仮設定は、目的・条件・維持前提・範囲・結果・限界を記録して個別確認なしに進めてよい。
2. 採用した内容は基本設計へ反映し、仕様案・要検討事項の状態と参照先も更新する。検証結果だけを理由に正式採用へ昇格させない。
3. 過去の判断理由・試験結果は記録として残す。変更された古い判断を、現在の判断待ちとして再提示しない。
4. ファイル名は固定する。設計版は文書内で管理し、版番号付きの同種ファイルを増やさない。
5. リンクはこの階層を基準にした相対パスとする。現在のDropboxプロジェクトルートは `/久乃銑泉/gist/crossweave/`。
6. 保存先は情報区分で選ぶ。新しい検証分野や実装資料が増えるまでは、既存区分を優先して使う。
7. 仕様策定に関する差分は元リポジトリへ反映・コミットしてよい。`dev_design_tmp_assembly` の更新と、新規ブランチ作成は許可済み。コミットメッセージは差分が簡潔に分かる日本語にする。Gitへの記録と仕様の正式採用は別に扱い、未採用案・仮条件の区分を維持する。Pushは実施しない。反映時はコミットを別ブランチへ保存するだけで完了とせず、現在の作業ツリーに今回の未コミット差分が残っていないことも確認する。

## 整理の記録

基本設計0.30への整理で、採用事項と未採用案・試験前提を分けた。旧基本設計の章番号は案内として残し、移動先をたどれるようにしている。今回の自分の行動について、公開情報から確定する命中・HP変化・防御終了等を札選択時に事前表示する基本方針を採用した。画面配置や情報密度は引き続き検討する。

検討記録にのみ残っていた確認済みの命中・会心・能動防御の規則も、基本設計4.5・4.6へ集約した。数値や計算式の未決定部分は仕様案へ分けている。

確定仕様と資料整理のコミットを、現在の作業ブランチ `dev_design_tmp_assembly` へ反映した。作業ツリー・インデックス・HEADを一致させ、今回の整理による未コミット差分を解消した。`dev_design_docs_organized` は資料整理時点のブランチとして残している。Pushは実施していない。反映範囲と確認方法は[コミット記録](docs/作業資料/コミット/README.md)を参照。仕様案・仮条件・検証結果は、それぞれの情報区分を維持してコミットしている。
